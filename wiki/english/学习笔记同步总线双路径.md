## 1. 背景与目标

### 1.1 问题

初版跨窗同步纯依赖 `BroadcastChannel`（BC），但桌面端（macOS WKWebView 多 WebView）之间 BC 常不通——Tauri 独立弹窗是第二个 WKWebView 实例，与主窗 WebView 不在同一 BC 命名空间，导致：

1. **弹窗编辑草稿 → 主窗看不到**：`publishDraft` 走 `ch.postMessage`，但弹窗 BC 消息没到主窗。
2. **主窗保存/删除 → 弹窗不刷新**：同理，主窗 `publishSaved` / `publishDeleted` 到不了弹窗。
3. **selection 不回显**：对端点开同一篇笔记时，本窗不会响应 `request-state`。

此外还有两个附属问题：

4. **Host API 缺少 `openPopoutWindow` 入口**：插件侧想从笔记列表卡片调「独立打开」，必须自己 import Tauri 并判断环境——Host 应暴露统一方法。
5. **PopoutShell 布局不统一**：原设计用独立 `div[data-tauri-drag-region]` 做 6pt 顶边距，容易出内容溢出；弹窗内容区无背景圆角。
6. **英语 Agent 介绍卡边框色透明**：`border` 与 `bg-theme/5` 组合时边框使用了默认 `currentColor`（继承文字色），与介绍卡主色调不和谐。

### 1.2 重构目标

1. **同步总线双路径**：Web 端继续用 BC；桌面端追加 Tauri 全局事件（`emit` / `listen`）作为副路径，两条路径同时生效、handler 去重；同一发消息同时走两条通道，接收方由 `windowId` 去重。
2. **Host API 补齐**：`modules.learningNotes.openPopoutWindow()` 懒加载打开弹窗，避免顶层 import 触发 TDZ 导致子窗冷启空白。
3. **PopoutShell 视觉整合**：顶栏拖动区与外壳合并为一层（`p-7 pt-7.5`），内容区加 `bg-theme-secondary rounded-md p-2`。
4. **Agent 介绍卡边框色**：`border` → `border border-theme/5`，边框与背景一致。

## 3. 实现思路与架构方案

### 3.1 同步总线双路径架构

```
 Web 端（标签页/多窗口同进程）         桌面端 Tauri（多 WKWebView，BC 不通）
─────────────────────────────────        ────────────────────────────────────────
 publishLearningNotesSync(msg)             publishLearningNotesSync(msg)
  ├─ ch.postMessage(msg)                    ├─ ch.postMessage(msg)  ← 常无效
  └─ dispatchToHandlers(msg)                ├─ dispatchToHandlers(msg)
    (本地订阅者同步投递)                       └─ onEmit(TAURI_EVENT, msg)  ← 副路径
                                                ↑
                                                │ 全局事件：
                                                │   由 Rust `app.emit()` 转发
                                                │   跨所有 WebView
                                                ↓
 subscribeLearningNotesSync(handler)          subscribeLearningNotesSync(handler)
  ├─ getChannel().onmessage → dispatch        ├─ getChannel()  ← 忽略
  └─ handlers.add(handler)                    ├─ handlers.add(handler)
                                                └─ ensureTauriListen() →
                                                     onListen(TAURI_EVENT, msg =>
                                                       dispatchToHandlers(msg))
```

**关键决策**：

1. **双通道并行而非切换**：不做运行时检测选单一通道；两条同时发、同时收。接收方靠 `msg.windowId === getLearningNotesWindowId()` 过滤自发消息，也自然过滤了同一条消息从两条不同通道到达的重复。
2. **Tauri 通道用 `emit`/`listen` 而非 `invoke`**：`emit` 是 Tauri 原生全局事件广播，跨 WebView 可靠；`invoke` 是单次 Rust 命令调用，不做广播。
3. **`dispatchToHandlers` 抽取**：三处需要遍历 handlers（BC onmessage、publish 本地投递、Tauri listen），抽取成辅助函数避免重复。
4. **`ensureTauriListen` 幂等**：`publish` 与 `subscribe` 都调 `ensureTauriListen()`，首次调就启动一次 Tauri `onListen`，用 `tauriListenStarted` 标记避免重复订阅。

### 3.2 `openPopoutWindow` 懒加载

为什么不顶层 import：

```
 HostApi (federation/capabilities/)
     └─ import openPopoutWindow from '…/notes/openPopoutWindow'
              openPopoutWindow → import { isTauriRuntime, createWebviewWindow } from '@/utils/tauri'
                 utils/tauri → import { routeInjector } from '@/federation'
                    又拉回 federation 层
```

弹窗冷启时，子窗 JS 加载顺序触发 `getStorage / routeInjector` 的**暂时性死区（TDZ）**——导致子窗首帧空白。

**修复**：把 `openPopoutWindow` 放在调用时 dynamic import，等 federation 层完全初始化后再进入，避免 TDZ。

### 3.3 PopoutShell 布局

改动前：外层 `div` 无 padding，里面单独放一个 6pt 空 div 做拖动占位，再一个 `div[pb-7]` 放内容。

改动后：外层 `div` 同时承担背景+拖动+外壳 padding（`p-7 pt-7.5` + `data-tauri-drag-region`），内容区套一层 `bg-theme-secondary rounded-md p-2`。优点：拖动区更大、结构少一层、视觉有层次。

#### 4.1.2 `getChannel` + `ensureTauriListen`

**对比范围**：`getChannel` 全函数 + 新增 `ensureTauriListen` 全函数。

**改动前** · `apps/frontend/src/federation/capabilities/learningNotesSyncBus.ts`（基线，约 L78–L96）

```typescript
// 创建或返回 BroadcastChannel 单例；类型声明返回 BC 或 null
function getChannel(): BroadcastChannel | null {
	// 浏览器不支持 BC（旧 SSR/老浏览器）时返回 null
	if (typeof BroadcastChannel === 'undefined') return null;
	// 单例尚未创建则新建
	if (!channel) {
		// 注释：BroadcastChannel 在同一浏览器中不同页面（标签页/窗口/iframe）之间的通信
		channel = new BroadcastChannel(LEARNING_NOTES_SYNC_CHANNEL);
		// BC 收到对端消息时：类型守卫后分发 handlers
		channel.onmessage = (ev: MessageEvent<LearningNotesSyncMessage>) => {
			// 从事件中取出 data 即消息体
			const msg = ev.data;
			// 基本类型守卫：必须是非 null object 且含 type 字段
			if (!msg || typeof msg !== 'object' || !('type' in msg)) return;
			// inline 遍历 handlers 分发
			for (const h of handlers) {
				try {
					h(msg);
				} catch (e) {
					console.error('[learningNotesSync]', e);
				}
			}
		};
	}
	// 返回 BroadcastChannel 实例
	return channel;
}
```

**改动后** · `apps/frontend/src/federation/capabilities/learningNotesSyncBus.ts`（当前，约 L89–L113）

function getChannel(): BroadcastChannel | null {
	// 浏览器不支持 BC 时返回 null（不变）
	if (typeof BroadcastChannel === 'undefined') return null;
	// 单例尚未创建则新建（不变）
	if (!channel) {

		channel = new BroadcastChannel(LEARNING_NOTES_SYNC_CHANNEL);
		// BC 收到对端消息（不变的类型守卫+分发，改为调抽取的辅助函数）

			// 从事件中取出 data 即消息体
			const msg = ev.data;
			// 基本类型守卫：必须是非 null object 且含 type 字段
			if (!msg || typeof msg !== 'object' || !('type' in msg)) return;
			// 改用抽取的 dispatchToHandlers 代替 inline 遍历
			dispatchToHandlers(msg);
		};
	}
	// 返回 BroadcastChannel 实例
	return channel;
}

// 桌面端订阅 Tauri 全局事件；Web 端不走 CustomEvent（同页已有本地 dispatch）
function ensureTauriListen() {
	// 已启动或非 Tauri 环境直接短路
	if (tauriListenStarted || !isTauriRuntime()) return;
	// 置位：下次进入不再启动
	tauriListenStarted = true;
	// 调 Tauri onListen 订阅全局事件，泛型指定消息体类型
	void onListen<LearningNotesSyncMessage>(
		// 事件名：与 publish 时 emit 的事件名一致
		LEARNING_NOTES_SYNC_TAURI_EVENT,
		// 回调：收到对端 WebView emit 的消息
		(msg) => {
			// 类型守卫：必须是非 null object 且含 type 字段
			if (!msg || typeof msg !== 'object' || !('type' in msg)) return;
			// 分发给本窗订阅者
			dispatchToHandlers(msg);
		},
	);
}
```

**变更摘要**：`getChannel` 内把 inline handlers 遍历改为 `dispatchToHandlers(msg)`；新增 `ensureTauriListen()`，首次调用（publish/subscribe 时）启动 Tauri 全局事件监听。

// 导出：发布同步消息；void 返回
export function publishLearningNotesSync(msg: LearningNotesSyncMessage): void {
	// 先拿 BC 单例
	const ch = getChannel();
	// BC 可用时通过 postMessage 发给其它同源页面
	ch?.postMessage(msg);
	// 本窗订阅者同步投递（BC onmessage 不回环到发端）：inline 遍历
	for (const h of handlers) {
		try {
			h(msg);
		} catch (e) {
			// 本地投递打了 'local' tag 用于区分
			console.error('[learningNotesSync] local', e);
		}
	}
}

// 导出：订阅同步消息；返回取消订阅函数
export function subscribeLearningNotesSync(
	handler: LearningNotesSyncHandler,
): () => void {
	// 触发 BC 单例创建（懒实例化）
	getChannel();
	// 将 handler 加入 Set
	handlers.add(handler);
	// 简化版取消订阅：直接 delete
	return () => handlers.delete(handler);
}
```

```typescript
// 导出：发布同步消息（函数签名不变）
export function publishLearningNotesSync(msg: LearningNotesSyncMessage): void {
	// publish 时顺便启动 Tauri listen（保证发布之前订阅已就绪）
	ensureTauriListen();
	// BC 可用时发（与旧版一致）
	getChannel()?.postMessage(msg);
	// 本窗订阅者同步投递（BC 不回环）；windowId 过滤由消费方处理
	dispatchToHandlers(msg);
	// Tauri 多 WebView：BC 常不通，靠全局 emit 作为副通道
	if (isTauriRuntime()) {
		// 调 Tauri onEmit 广播全局事件；void 忽略 Promise
		void onEmit(LEARNING_NOTES_SYNC_TAURI_EVENT, msg);
	}
}

// 导出：订阅同步消息；函数签名不变
export function subscribeLearningNotesSync(
	handler: LearningNotesSyncHandler,
): () => void {
	// subscribe 时也顺便启动 Tauri listen（保证首次 subscribe 就能收 Tauri 消息）
	ensureTauriListen();
	// 触发 BC 单例创建（与旧版一致）
	getChannel();
	// 将 handler 加入 Set（与旧版一致）
	handlers.add(handler);
	// 取消订阅：delete 保留显式花括号扩展位（未来可加 Tauri 停止监听逻辑）
	return () => {
		handlers.delete(handler);
	};
}
```

**变更摘要**：`publish` 新增 `ensureTauriListen()` + Tauri emit；`subscribe` 新增 `ensureTauriListen()`；两处 handlers 遍历都改为 `dispatchToHandlers`。

## 5. 兼容性与影响

### 5.1 行为变化

| 场景 | 改动前（仅 BC） | 改动后（BC + Tauri emit） |
| --- | --- | --- |
| 桌面端弹窗 ↔ 主窗 | BC 不通，草稿/保存/删除同步失效 | 两条通道并行，Tauri emit 送达可靠；windowId 过滤避免重复 |
| Web 端标签页 ↔ 窗口 | 正常 | 正常（BC 原路径不变；Tauri emit 路径 `isTauriRuntime()` 短路不生效） |
| 双通道重复到达 | 不存在 | 同一消息从 BC 与 Tauri emit 同时到达 → 两次 dispatch 同一 handler → 消息体完全相同、`windowId` 一致、消费方幂等（`applyRemoteDraft` 按 revision 覆盖；`refreshList` 幂等；`applyRemoteDeleted` 幂等），无副作用 |
| Host API `openPopoutWindow` | 不存在，插件必须自己引 Tauri 工具 | 新增，插件调 `api.modules.learningNotes.openPopoutWindow()` 即开；dynamic import 避免 TDZ |
| PopoutShell 视觉 | 独立顶栏 6pt 拖动占位 + 底部 pb-7 | 拖动合并到外容器，内容区带次要背景圆角 |
| Agent 介绍卡边框 | `border`（currentColor）灰调 | `border-theme/5`（主题色 5%）和谐 |

### 5.2 风险与回归

- **Tauri emit 权限 / 版本**：`onEmit / onListen` 依赖仓库内封装的 `event.ts`（再调 Tauri `@tauri-apps/api/event`）。若 Tauri 2.x API 变动则需同步封装层。回归：桌面端发 draft → 主窗是否即时看到。
- **双通道消息序**：BC 与 Tauri 两条通道到达时间差不可预测；消费方必须按 `revision` + `windowId` 幂等处理（`draft` 消息已有 `revision: number`），不依赖到达顺序。
- **`openPopoutWindow` 返回 Promise**：调用方若未 await 直接判断，可能在 promise 未决时拿到 undefined；API 文档要注明。
- **PopoutShell `data-tauri-drag-region` 在外层**：可能导致子元素（如 `<button>`）点击也被视为拖动；实际 Tauri drag 会忽略 `data-tauri-no-drag` 子元素或可点击元素，需回归确认弹窗内按钮可正常点击。
