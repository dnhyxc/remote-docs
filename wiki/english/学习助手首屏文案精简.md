# 学习助手首屏文案精简

英语学习页右侧助手的顶部介绍（`englishLearning.intro`）在本轮被压缩重写：中文从 96 字缩到 57 字，英文从 60 词缩到 30 词，只保留「能问什么、能帮忙做什么、收藏与错题会二次确认、快捷意图随下次发送附带」四个信息点。

> **文档角色**：本模块是英语学习域的**文案级**改动，不涉及组件结构或数据流。因改动同时落在中英两个 locale 文件，故单独立篇，避免与功能专题混写。
> **延伸阅读**：
> - [英语学习.md](./README.md) —— 英语学习域文档索引
> - [../项目更新信息.md](../项目更新信息.md) 第 24 节 —— 面向用户的说明

## 1. 背景与目标

原文案是一段「把所有能力都列一遍」的长句：

- 罗列了查词、翻译、语法、口语、阅读五类问题；
- 又把左侧面板的七类内容（词库/语料、每日阅读、收藏、错题、复习、单词与语句资料、笔记）全部点名；
- 最后再解释快捷意图「点一次设定、再点取消」。

问题在于：这段文字位于**对话输入区上方**，是每屏都能看到的常驻文案。信息越全，用户越读不完，真正关键的两条（「收藏/错题需要确认」「快捷意图随下次发送生效」）反而被淹没。

目标：

| 编号 | 目标 | 验收 |
| --- | --- | --- |
| C1 | 保留核心能力描述（问什么、能帮什么） | 仍能看出可用于查词/翻译/语法/口语/阅读 |
| C2 | 保留风险提示（收藏与加错题会先确认） | 文案含「会先确认」 |
| C3 | 保留快捷意图的作用说明 | 文案说明「随下次发送附带，再点取消」 |
| C4 | 中英长度同步压缩 | 中文 ≤ 60 字，英文 ≤ 32 词 |
| C5 | 中英信息点一一对应 | 四个信息点在两语言中都存在 |

## 3. 实现思路

1. **只改文案值，不改键名。** `englishLearning.intro` 被助手面板直接读取，改键名会牵连组件；改值则零风险。
2. **信息按「做什么 → 能帮什么 → 注意事项 → 快捷操作」排序。** 先给动作（可问查词、翻译…），再给能力（也可让助手查左侧内容），然后是风险提示，最后是快捷意图——与用户的阅读路径一致。
3. **把「七类内容」抽象成「左侧学习内容」。** 具体清单在左侧栏本身可见，文案里再列一遍属于重复信息。
4. **英文不逐字直译。** 英文用破折号把「或让助手使用左侧面板」并进第一句，避免中文式的长并列；同时把「Favorites / mistakes ask for confirm first」压成一句独立短句。
5. **保持现有的引号与标点风格。** 中文继续用「」，英文继续用中文引号包 `/`（与相邻文案一致），不引入新的排版约定。

本改动无跨模块数据流，略图。

## 4. 关键代码

### 4.1 中文文案

来源：`apps/frontend/src/i18n/locales/zh-CN/englishLearning.ts`（**改动前**，约 L288）

```typescript
// 键名不变，仅替换值；此处为改动前的长句版本
'englishLearning.intro':
	// 罗列五类提问能力 + 七类左侧内容 + 收藏/错题确认提示 + 快捷意图说明
	'直接提问即可：查词、翻译、语法、口语与阅读讲解。也可让助手查询或整理左侧学习内容（词库/语料、每日阅读、收藏、错题、复习、单词与语句资料、笔记）；收藏与加错题会先弹出确认。左侧「快捷意图」可设定本轮方向，再点同一项取消，下次发送时自动附带。',
```

来源：`apps/frontend/src/i18n/locales/zh-CN/englishLearning.ts`（**改动后**，约 L288）

```typescript
// 键名保持不变，保证组件读取路径不变
'englishLearning.intro':
	// 四段信息：可问什么 → 可让助手查左侧内容 → 收藏/错题需确认 → 快捷意图随下次发送
	'可问查词、翻译、语法、口语与阅读；也可让助手查左侧学习内容。收藏/加错题会先确认。左侧「快捷意图」点选后随下次发送附带，再点取消。',
```

**变更摘要**：删去七类左侧内容的逐一罗列与「直接提问即可」的铺垫，把「收藏与加错题会先弹出确认」压成「收藏/加错题会先确认」，把快捷意图的三段说明合并为「点选后随下次发送附带，再点取消」。
