# 固定列表统一虚拟滚动与续读

> **路径与命名已收口**：本文「改动后」代码基于合并前的中间态（`useLibraryWordsList` + 计划中的 `hooks/englishLearningListResume.ts`）。实际最终代码已把 Hook 重命名为 `useEnglishLearningList`、把续读 store 与 scope helper 合并为 `store/englishLearningResume.ts`、工具函数从 `library/utils/` 上移到 `utils/`。完整路径与命名变更见 [英语学习列表模块收口.md](./英语学习列表模块收口.md)。阅读本文时，§4.7 的 `englishLearningListResume.ts` 实际已并入 `store/englishLearningResume.ts` 的固定列表段。

## 1. 背景与目标

英语学习模块原先有 5 个**结构高度相似**的列表 Hook：

- `useVocabularyFavoritesList`：单词收藏列表
- `useClassicFavoritesList`：经典句收藏列表
- `useVocabularyMistakesList`：单词错题集
- `useClassicQuoteMistakesList`：经典句错题集
- `useDailyMemorizeRecordsList`：每日记词记录列表

它们都各自维护「分页拉取 + 向下滚动加载更多 + 状态代次控制」这一套逻辑，差异仅在于：

1. 调用的后端列表 API 不同；
2. 列表项类型不同（`EnglishVocabularyFavoriteItem` / `EnglishClassicQuoteFavoriteItem` 等）；
3. 是否需要 totalCount、是否需要续读位置。

这导致每个 Hook 都重复实现了一份 `fetchFirstPage` / `fetchMore` / `onViewportScroll` / 代次互斥逻辑，且都没用上 `useLibraryWordsList` 已经做好的「续读 offset 持久化 + 缓存短路 + 并发预取 + react-virtuoso 行级虚拟化」能力。

本轮改动的目标：

1. 删除上述 5 个 Hook；
2. 让这 5 个固定列表**统一**复用资源库的 `useLibraryWordsList<TItem, TLibrary>` Hook，通过传入 `fetchPage` 回调适配不同后端 API；
3. 为这些固定列表新增 `englishLearningListResume.ts`，复用已有的 `english_library_items_resume` 表（用占位 `library_id` 区分 5 个固定列表），实现跨会话续读；
4. 在 `useLibraryWordsList` 上新增 `resolveInitialResume`（无会话缓存时从服务端拉续读 offset）、`refetchOnEnter`（每次进入列表跳过会话缓存并刷新）、`reloadFromStart`（删除/重置后从开头重载）等能力；
5. 后端为 5 个固定列表补齐 `items-resume` GET/PATCH 端点，并把 `limit` 上限提至 1000，与资源库词条一致。

## 3. 实现思路

### 3.1 用泛型 `fetchPage` 适配不同后端列表

`useLibraryWordsList` 原本只为资源库词条设计，参数里耦合了 `LibraryKind` / `libraryId` 等资源库专属概念。为了让 5 个固定列表复用，本 Hook 早已把「具体如何拉取一页」抽成 `fetchPage: (id, limit, offset) => Promise<LibraryWordsListResult<TItem, TLibrary>>` 回调——调用方自己决定调哪个 API、如何把响应映射成 `{ items, totalCount, library }`。

本轮只需保证 5 个固定列表各自写一个 `fetchPage` 包装函数，把后端返回映射成 Hook 期望的结构即可。后端列表响应统一有 `items` 与 `totalCount`，所以包装函数基本是一行展开。

### 3.2 用占位 `library_id` 复用续读表

`english_library_items_resume` 表的主键原本是 `(userId, libraryKind, libraryId)`，专门存资源库词条的续读 offset。5 个固定列表**没有真实的 libraryId**，但只要给它分配 5 个**固定的占位 ID**（如 `vocab-favorites-resume` / `classic-favorites-resume` / `vocab-mistakes-resume` / `classic-mistakes-resume` / `vocab-daily-memorize-resume`），就能复用同一张表，避免新建表与新建后端模块。

`englishLearningListResume.ts` 暴露 `EnglishLearningFixedListScope` 联合类型，把这 5 个 scope 串起来；并提供：

- `englishLearningFixedListResumeId(scope)`：scope → 占位 libraryId；
- `resolveEnglishLearningFixedListResumeOffset(scope)`：从 MobX store 读对齐后的 offset；
- `setEnglishLearningFixedListResumeOffset(scope, offset)`：写入 MobX store（异步 flush 到后端）；
- `flushEnglishLearningFixedListResume(scope, { keepalive })`：立即 flush，用于 `pagehide` / `visibilitychange`；
- `resolveEnglishLearningFixedListInitialResume(scope)`：会话内无缓存时调用新增的 `items-resume` GET 端点拿服务端值并 hydrate 到 store。

### 3.3 `resolveInitialResume`：服务端续读的延迟 hydrate

资源库词条列表的续读通常已经在会话内存在（用户刚操作过）；而 5 个固定列表**冷启动**时，会话 store 里多半还没有对应 scope 的 offset。`useLibraryWordsList` 新增 `resolveInitialResume?: () => Promise<number`，在 `libraryId` 生效后若 `resolveInitialResumeRef.current` 有值，则先 `await` 它拿到服务端 offset，再用作本列表的初始续读点。

调用方传入的 `resolveInitialResume` 实际是 `() => resolveEnglishLearningFixedListInitialResume(LIST_SCOPE)`：先看 store，再 lazy 调 `items-resume` GET 接口 hydrate。这样冷启动也能正确恢复上次离开时的位置。

### 3.4 `refetchOnEnter`：每次进入刷新列表内容

固定列表的内容会在用户离开后变化（例如错题集会因新练习而新增条目）。`refetchOnEnter` 默认 `false`；固定列表传 `true`，让 Hook 在 `libraryId` 生效时：

1. 调用 `invalidateLibraryWordsListCache(cacheNamespace, libraryId)` 失效会话缓存；
2. 跳过 `restoreFromCache` 短路，强制走 `fetchFirstPage` 重新拉取首页。

`libraryId` 失活（变为 `null`）时，若 `refetchOnEnter` 且之前有过 `prevLibraryId`，也清掉旧缓存，避免下次返回时撞上陈旧缓存。

### 3.5 `reloadFromStart`：删除后从开头重载

收藏/错题集支持「移除条目」。旧 5 个 Hook 删除条目后只能手动改本地 state；统一到 `useLibraryWordsList` 后，调用方可以通过新增的 `reloadFromStart(resetResume?)` 方法：

1. 失效会话缓存；
2. 重置 `bootedLibraryIdRef` / `listReadyRef`；
3. 取代次 `++loadGenRef.current` 使旧请求失效；
4. 若 `resetResume=true`，把续读 offset 清零（用于「全部清空」类操作）；
5. 否则若有 `resolveInitialResumeRef.current`，重新走服务端续读；
6. 最后调 `fetchFirstPageRef.current` 重新拉首页。

### 3.6 `LibraryWordsListResult` 与 `UseLibraryWordsListOptions` 的类型扩展

为了让固定列表也能用，`LibraryWordsListResult.library` 改为 `library?: TLibrary | null`（固定列表没有 library 概念，传 `null` 即可），并新增 `totalCount?: number`（旧版只在 items 里隐含）。`UseLibraryWordsListOptions` 新增 `resolveInitialResume` / `refetchOnEnter` 两个可选参数；老调用方（资源库）不传时行为完全不变，保持向后兼容。

### 3.7 后端

5 个固定列表各加一个 `GET /:scope/items-resume` 与 `PATCH /:scope/items-resume`，复用资源库的 `english_library_items_resume` 表。`limit` 上限统一提至 1000，与资源库一致，避免固定列表分页拉取次数过多。

```typescript
// Hook 签名：active 控制是否激活加载（默认 true），失活时取消旧请求
export function useDailyMemorizeRecordsList(active = true) {
	// 从 i18n 上下文获取翻译函数 t（用于错误 Toast 文案）
	const { t } = useI18n();
	// 已加载的每日记词记录条目数组 state
	const [entries, setEntries] = useState<EnglishDailyMemorizeRecordEntry[]>([]);
	// 总条目数 state（来自后端 totalCount）
	const [totalCount, setTotalCount] = useState(0);
	// 首屏 loading state
	const [loading, setLoading] = useState(false);
	// 加载更多 loading state
	const [loadingMore, setLoadingMore] = useState(false);
	// 当前已加载条目数（用作下次分页的 offset）
	const offsetRef = useRef(0);
	// 是否还有更多数据的标记
	const hasMoreRef = useRef(true);
	// 防止 fetchMore 并发重入的互斥标记
	const fetchingMoreRef = useRef(false);
	// 加载代次：每次重新拉首页递增，用于丢弃过期请求结果
	const loadGenRef = useRef(0);

	// 拉取首页的回调（依赖 t，用于错误文案）
	const fetchFirstPage = useCallback(
		// 入参 gen 为当前代次
		async (gen: number) => {
			// 重置加载更多互斥标记
			fetchingMoreRef.current = false;
			// 进入首屏 loading
			setLoading(true);
			// 退出加载更多 loading
			setLoadingMore(false);
			// 偏移量归零
			offsetRef.current = 0;
			// 默认认为还有更多
			hasMoreRef.current = true;
			// 清空已加载列表
			setEntries([]);
			// 清空总条目数
			setTotalCount(0);
			try {
				// 调用每日记词记录列表 API
				const res = await listEnglishDailyMemorizeRecords({
					// 单页大小常量
					limit: VOCAB_HISTORY_PAGE_SIZE,
					// 从 0 开始
					offset: 0,
					// silent 不弹错误 Toast
					silent: true,
				});
				// 代次过期则丢弃结果
				if (gen !== loadGenRef.current) return;
				// 取响应数据
				const page = res.data;
				// 取 items（兼容空响应）
				const list = Array.isArray(page?.items) ? page.items : [];
				// 写入已加载列表
				setEntries(list);
				// 写入 totalCount（缺失时退化为 list 长度）
				setTotalCount(
					typeof page?.totalCount === 'number' ? page.totalCount : list.length,
				);
				// 推进 offset 为本页长度
				offsetRef.current = list.length;
				// 满页则认为还有更多
				hasMoreRef.current = list.length >= VOCAB_HISTORY_PAGE_SIZE;
			} catch {
				// 代次过期则忽略
				if (gen !== loadGenRef.current) return;
				// 出错时清空列表
				setEntries([]);
				// 出错时清零 totalCount
				setTotalCount(0);
				// 出错时停止继续加载更多
				hasMoreRef.current = false;
				// 弹错误 Toast
				Toast({ type: 'error', title: t('englishLearning.daily.recordsLoadFailed') });
			} finally {
				// 仅当代次未变时退出首屏 loading
				if (gen === loadGenRef.current) setLoading(false);
			}
		},
		// 依赖 t
		[t],
	);

	// 加载更多回调（依赖 loading 用于互斥）
	const fetchMore = useCallback(async () => {
		// 无更多 / 正在加载更多 / 首屏 loading 中则跳过
		if (!hasMoreRef.current || fetchingMoreRef.current || loading) return;
		// 锁定当前代次
		const gen = loadGenRef.current;
		// 占据互斥锁
		fetchingMoreRef.current = true;
		// 进入加载更多 loading
		setLoadingMore(true);
		// 取当前 offset
		const offset = offsetRef.current;
		try {
			// 调用每日记词记录列表 API 拉下一页
			const res = await listEnglishDailyMemorizeRecords({
				// 单页大小常量
				limit: VOCAB_HISTORY_PAGE_SIZE,
				// 当前 offset
				offset,
				// silent 模式
				silent: true,
			});
			// 代次过期则丢弃
			if (gen !== loadGenRef.current) return;
			// 取响应数据
			const page = res.data;
			// 取 chunk（兼容空响应）
			const chunk = Array.isArray(page?.items) ? page.items : [];
			// 同步更新 totalCount
			if (typeof page?.totalCount === 'number') setTotalCount(page.totalCount);
			// 空 chunk 表示没有更多
			if (chunk.length === 0) { hasMoreRef.current = false; return; }
			// 追加到已加载列表后
			setEntries((prev) => [...prev, ...chunk]);
			// 累加 offset
			offsetRef.current += chunk.length;
			// 满页则认为还有更多
			hasMoreRef.current = chunk.length >= VOCAB_HISTORY_PAGE_SIZE;
		} catch {
			// 代次过期则忽略
			if (gen !== loadGenRef.current) return;
			// 出错时停止加载更多
			hasMoreRef.current = false;
		} finally {
			// 仅当代次未变时释放互斥
			if (gen === loadGenRef.current) {
				fetchingMoreRef.current = false;
				setLoadingMore(false);
			}
		}
	}, [loading]);

	// active 变化时触发首页拉取
	useEffect(() => {
		// 失活时递增代次使旧请求失效
		if (!active) { loadGenRef.current += 1; return; }
		// 激活时取下一代次
		const gen = ++loadGenRef.current;
		// 调用首页拉取
		void fetchFirstPage(gen);
	}, [active, fetchFirstPage]);

	// 视口滚动事件回调（依赖 fetchMore）
	const onViewportScroll = useCallback<UIEventHandler<HTMLDivElement>>(
		(e) => {
			// 取滚动容器
			const el = e.currentTarget;
			// 计算距底剩余距离
			const rest = el.scrollHeight - el.scrollTop - el.clientHeight;
			// 小于阈值时触发加载更多
			if (rest < SCROLL_LOAD_THRESHOLD_PX) void fetchMore();
		},
		[fetchMore],
	);

	// 返回列表状态与滚动回调
	return { entries, totalCount, loading, loadingMore, onViewportScroll };
}
```

	// resetResume=true 时把续读 offset 清零（用于「全部清空」类操作）

		// 取当前 libraryId（占位或真实）

		bootedLibraryIdRef.current = null;

		listReadyRef.current = false;
		// 取下一代次，使旧请求结果失效
		const gen = ++loadGenRef.current;
		// 先用 props / store 中的初始续读 offset 作为基础
		let resumeOffset = alignResumeOffset(
			initialResumeOffsetRef.current,
			pageSize,
		);

				resumeOffset = alignResumeOffset(
					await resolveInitialResumeRef.current(),
					pageSize,
				);
			} catch {
				// 异常时用前面的 fallback（props / store）
			}
		}
		// 标记已启动该 library
		bootedLibraryIdRef.current = id;
		// 更新 lastSavedResume 为本次采用的 offset
		lastSavedResumeRef.current = resumeOffset;

- **向后兼容**：`LibraryWordsListResult.library` 由必填改为可选可空、`totalCount` 为新增可选字段；`UseLibraryWordsListOptions` 新增的 `resolveInitialResume` / `refetchOnEnter` 均为可选，老调用方（资源库词条列表）不传时行为完全不变。
- **行为变化**：5 个固定列表首次进入时：
  - 会调 `items-resume` GET 拿服务端 offset 并 hydrate；
  - `refetchOnEnter=true` 会失效会话缓存，每次进入都重新拉首页；
  - 滚动时 offset 通过 `setEnglishLearningFixedListResumeOffset` 写入 store；
  - `pagehide` / `visibilitychange` 触发 `flushEnglishLearningFixedListResume(scope, { keepalive: true })` 强制 flush。
- **后端影响**：新增 5 套 `items-resume` GET/PATCH 端点；`limit` 上限从原值提升至 1000，与资源库词条一致。
- **风险与回归建议**：
  - 5 个固定列表冷启动续读是否恢复到上次离开位置；
  - 离开页面后再返回，`refetchOnEnter` 是否强制刷新；
  - 在低数据量（少于单页）场景下是否有「还有更多」误判；
  - 移除条目后调用 `reloadFromStart` 是否能正确从开头重载；
  - 后端 `limit` 上限提升后大列表的分页拉取次数是否减少；
  - `pagehide` flush 在弱网下是否会丢失最后一次 offset。
