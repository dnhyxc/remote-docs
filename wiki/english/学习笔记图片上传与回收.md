# 学习笔记图片上传与孤儿回收

> **文档角色（主文档）**：本轮把「学习笔记正文图片」从纯前端 base64 内联升级为「服务端 COS 上传 + 附件表引用计数 + pending 会话结算 + 孤儿自动回收」全链路；桌面端粘贴的 `data:image/` 也从「直接塞进 TipTap」改为「转 File → 派发 `rich-editor:desktop-paste-images` → 走 ImageUpload 上传钩子」，与本后端接口协同。
> **延伸阅读**：[学习笔记远程.md](./学习笔记远程.md)（MF Remote 容器与路由挂载）；[学习笔记CRUD.md](./学习笔记CRUD.md)（列表/编辑/删除 HostBridge 全链路）；[Tauri剪贴板图片文件.md](./Tauri剪贴板图片文件.md)（桌面端剪贴板四 flavor 并行读取基线，本文在其上加了「data: 图走上传钩子」分支）；[../cos/COS对象存储.md](../cos/COS对象存储.md)（COS 对象键前缀白名单与 `/ext-cos/` 代理）。

## 1. 背景与目标

### 1.1 问题

学习笔记在引入富文本编辑器（TipTap）后，图片有两种来源：

- **Web 浏览器粘贴 / 拖拽**：TipTap Image 扩展自带 `onUploadImage` 钩子，前端拿到 `File` 后 POST 到后端，后端上传 COS 返回 `notes/...` URL，编辑器回填 `<img src="https://.../notes/...">`。这条路径此前已可用。
- **Tauri 桌面端粘贴**：剪贴板里的位图、文件列表、富文本 HTML 在 `apps/frontend/src/utils/clipboard.ts` 的 `attachTauriPlainFieldClipboardShortcuts` 中被读成 `data:image/...;base64,...`，旧实现**直接以 `<img src="data:...">` 插入 ProseMirror 文档**。后果：
  1. 笔记正文里塞满 base64，几兆的截图贴几张就内存溢出、序列化卡顿；
  2. DOCX 导出（`learning-note-docx.builder.ts`）必须对 base64 做 `atob` + `sharp` 转码，长笔记极易超时；
  3. base64 在 `EnglishLearningNote.content` 列（`text` 类型，5MB 上限）里很快撑爆；
  4. 桌面端粘贴没有走 `onUploadImage`，前后端两套图片处理路径分裂。

另一侧——即便走通了 `onUploadImage` 的图片——也存在「孤儿对象」问题：

- 用户新建笔记时先粘贴若干图（前端调 `POST .../upload-image` 已写入 COS），随后**关闭或刷新**而没保存笔记：COS 上多出几条永远不被任何笔记引用的图（孤儿）。
- 用户编辑已有笔记，先粘贴新图（已上传 COS），随后**把图删掉再保存**：旧正文里有该图，新正文里没有，COS 上残留孤儿。
- 用户**删整篇笔记**：COS 上对应的图若没有引用计数回收，永远残留。

### 1.2 目标

| # | 目标 |
|---|------|
| 1 | 后端 `POST /english-learning/notes/upload-image`：图片走 COS `notes/` 前缀，按 `noteId` 或 `uploadSessionId` 落库登记 |
| 2 | 后端 `DELETE /english-learning/notes/upload-session/:sessionId`：放弃会话，删 pending 行 + 无引用 COS 对象 |
| 3 | 后端 `POST /english-learning/notes/upload-session/:sessionId/settle`：按正文结算会话，正文里没有的 pending 删 COS |
| 4 | `SaveLearningNoteDto` / `UpdateLearningNoteDto` 增加可选 `uploadSessionId`，保存/更新时一并结算 pending |
| 5 | 删除笔记：按附件表 + 正文 HTML 双源收集 key，删行 + 引用计数后回收 COS |
| 6 | 笔记正文变更（save / update content）：以正文为真相源，diff 同步附件表，本篇移除的 key 走引用计数回收 |

## 3. 实现思路

```mermaid
flowchart LR
  subgraph 客户端
    A[Tauri 粘贴] --> B[clipboard.ts 抽 data: 图]
    B --> C[派发 desktop-paste-images]
    C --> D[RichEditor ImageUpload preventDefault]
    D --> E["POST /notes/upload-image"]
  end
  subgraph 后端
    E --> F[uploadService.uploadObjectToCos notes/]
    F --> G{有 sessionId?}
    G --|有| H[pending_repo 写行]
    G --|仅 noteId| I[attachment_repo 写行]
    H --> J[save/update 带 uploadSessionId]
    I --> J
    J --> K[settlePendingSession]
    K --> L{正文里有该 key?}
    L --|有| M[pending 行删 + 写 attachment 行]
    L --|无| N[pending 行删 + deleteCosObject]
    J --> O[syncAttachmentsFromContent]
    O --> P[diff 附件表 与正文]
    P --> Q[本篇移除的 key 走引用计数]
    Q --> R[deleteOrphanCosKeys]
    R --> S{attachment 表 + pending 表任一有?}
    S --|都没有| T[uploadService.deleteCosObject]
    S --|有| U[跳过]
  end
  J --> V[void gcExpiredPending]
  V --> W[1h 前的 pending 行删 + 回收]
```

**关键决策**：

1. **双表分工**：`attachment` 表按 `noteId` 关联已保存笔记的正文图片；`pending_upload` 表按 `sessionId` 关联尚未保存会话的图片。两者都以 `cosKey` 为引用计数键，`deleteOrphanCosKeys` 在删 COS 前先 `count` 两表，只要任一仍引用就跳过。
2. **正文为真相源**：保存/更新笔记时，`syncAttachmentsFromContent` 用 `extractNoteImageRefsFromHtml(html)` 抽出当前正文所有 `notes/` key，与 `attachmentRepo` 现有行 diff：移除的 → 删行后引用计数回收；新增的 → 写行（URL 缺失时调 `uploadService.buildCosPublicUrl(key)` 补全）。这避免了「编辑期删图但忘了主动调接口」残留。
3. **会话结算**：`uploadSessionId` 是前端在新建/编辑会话开始时生成的 UUID；图片上传时一并带上，落 `pending_upload` 行。保存笔记（save/update）时 `settlePendingSession`：正文里仍有的 key → 删 pending 行（已被 `syncAttachmentsFromContent` 写入 attachment 表）；正文里没有的 key → 删 pending 行 + 删 COS（用户「上传又删且保存」的孤儿回收）。`POST .../settle` 端点复用同一私有方法，用于「上传又删但内容回到基线无需保存」时立刻回收。
4. **放弃会话**：`DELETE .../upload-session/:sessionId` → `deletePendingSession`：删该 session 全部 pending 行 + 直接回收这些 key（不查正文，因为是「放弃」语义）。
5. **TTL 兜底**：`PENDING_TTL_MS = 60 * 60 * 1000`。客户端崩溃 / 关闭浏览器没机会调 `DELETE` 时，下次该用户的任意读/写笔记入口（`findOne` / `findAll` / `save` / `update` 等）都会 `void gcExpiredPending(userId)` 兜底回收 1 小时前的 pending 行。`void` + 内部 try-catch + Logger.warn：GC 失败不阻断主请求。
6. **删笔记**：`remove` 收集 `attachmentRepo` + 正文 HTML 双源 key（旧笔记可能只有 HTML 没有附件行），先删附件行、再删笔记行，最后 `deleteOrphanCosKeys` 引用计数回收。
7. **桌面端粘贴分流**：旧实现把 `data:image/` 直接 `insertClipSegments` 塞进 ProseMirror 文档；新实现先用 `extractAndStripDataUrlImages` 把 HTML 里所有 `data:image/` 抽出并从 DOM 移除，再 `dataUrlToFile` 转 `File`，再 `offerDesktopPasteImages` 派发 `rich-editor:desktop-paste-images` 自定义事件。RichEditor ImageUpload 扩展监听该事件、`preventDefault` 后走 `onUploadImage` 钩子（即上述后端接口）；事件未被拦截（如未挂载 RichEditor）时回退老的 `insertClipSegments` base64 路径，避免回归。位图（`imageFiles` / `imageDataUrl`）仅在「HTML 完全没抽出 data: 图」或「HTML 图数 < 位图数且 >1」时补一份，避免同一张图既走上传钩子又塞 base64。
8. **COS 前缀白名单同步**：后端 `COS_OBJECT_KEY_PREFIXES` 增 `'notes'`，让 `isCosObjectKey` / `normalizeCosObjectKey` 接受 `notes/...`；前端 `extractCosObjectKey` 同步正则，让 `notes/...` URL 能被解析为对象键（用于 `/ext-cos/` 代理下载、未来去重等）。
9. **不引入外键 CASCADE**：COS 桶是外部资源，不能由 DB CASCADE 回收；附件表与笔记表无 FK，靠 service 层显式 `delete + deleteOrphanCosKeys` 维持一致。这给了「同 key 多笔记引用」的余地（同一图被多篇笔记引用时，删一篇只删一行，count 仍 >0 不删 COS）。

### 4.3 `note-image-refs.ts` 抽 key 工具（纯新增）

**改动后** · `apps/backend/src/services/learning-notes/note-image-refs.ts`（全文，约 L1–L83）

```typescript
/**
 * 学习笔记 HTML → notes/ COS 附件引用（抽 key，供附件表同步）。
 */
// 该模块仅暴露 extractNoteCosKeyFromSrc 与 extractNoteImageRefsFromHtml 两个函数

// 正则：匹配 <img> 标签的 src，支持双引号 / 单引号 / 裸值三种形式
const IMG_SRC_RE =
	/<img\b[^>]*\bsrc\s*=\s*(?:"([^"]*)"|'([^']*)'|([^\s>]+))/gi;

/** 与 uploadService.buildCosObjectKey 一致：notes/{uuid}_… */
// 正则：notes/{36 位 uuid}_任意非斜杠字符，校验裸 key 合法性
const NOTES_KEY_RE =
	/^notes\/[0-9a-f-]{36}_[^/]+$/i;

// 类型：抽出的引用，含 key 与（若可用）原始 URL
export type NoteImageRef = { key: string; url: string };

// 函数：解码常见 HTML 实体（img src 里可能被转义）
function decodeHtmlEntities(s: string): string {
	return s
		.replace(/&amp;/gi, '&')
		.replace(/&quot;/gi, '"')
		.replace(/&#39;/gi, "'")
		.replace(/&lt;/gi, '<')
		.replace(/&gt;/gi, '>');
}

// 函数：把 URL 路径分段解码（%20 → 空格等），失败分段保留原样
function decodePathKey(raw: string): string {
	return raw
		.replace(/^\//, '')
		.split('/')
		.map((seg) => {
			try {
				return decodeURIComponent(seg);
			} catch {
				return seg;
			}
		})
		.join('/');
}

// 函数：仅当裸 key 形如 notes/{uuid}_... 才视为合法 notes 域 key
function normalizeNotesKey(key: string): string | null {
	const cleaned = decodePathKey(key.replace(/^\//, '').trim());
	return NOTES_KEY_RE.test(cleaned) ? cleaned : null;
}

/** 从 img src（完整 URL / /ext-cos/ 代理 / 裸 key）抽出 notes/… 对象键 */
// 导出函数：单 src 抽 key；非 data: 且不匹配 notes 域返回 null
export function extractNoteCosKeyFromSrc(src: string): string | null {
	// 去前后空白 + 解码 HTML 实体（src 来自 HTML 可能含 &amp; 等）
	const trimmed = decodeHtmlEntities(src?.trim() ?? '');
	// 空字符串或 data: URL 直接放弃（data: 不走 COS）
	if (!trimmed || /^data:/i.test(trimmed)) return null;

	// 路径 1：src 本身就是裸 key（notes/...）
	const bare = normalizeNotesKey(trimmed);
	if (bare) return bare;

	try {
		// 路径 2：src 是 URL（含 /ext-cos/ 代理形式），解析 pathname 后从中截 notes/... 段
		const asUrl = /^https?:\/\//i.test(trimmed)
			? new URL(trimmed)
			: new URL(
					trimmed.startsWith('/') ? trimmed : `/${trimmed}`,
					'http://local.invalid',
				);
		const path = decodePathKey(asUrl.pathname);
		// 在 pathname 里找 notes/ 起始位置（兼容 /ext-cos/notes/... 与 https://.../notes/...）
		const idx = path.indexOf('notes/');
		if (idx < 0) return null;
		return normalizeNotesKey(path.slice(idx));
	} catch {
		// URL 解析失败放弃
		return null;
	}
}

/** 从 TipTap HTML 抽出本笔记域图片附件（按 key 去重） */
// 导出函数：批量抽 refs；空 HTML 返回空数组；同 key 只保留首条
export function extractNoteImageRefsFromHtml(html: string): NoteImageRef[] {
	if (!html?.trim()) return [];
	// 用 Map 按 key 去重
	const byKey = new Map<string, NoteImageRef>();
	// 重置正则 lastIndex（全局正则复用前必须重置）
	IMG_SRC_RE.lastIndex = 0;
	let m: RegExpExecArray | null;
	// 循环所有 <img> 标签
	while ((m = IMG_SRC_RE.exec(html)) !== null) {
		// 三种引号形式任一命中
		const rawSrc = (m[1] ?? m[2] ?? m[3] ?? '').trim();
		const src = decodeHtmlEntities(rawSrc);
		const key = extractNoteCosKeyFromSrc(src);
		// 非 notes 域或已存在则跳过
		if (!key || byKey.has(key)) continue;
		// 仅当 src 是 http(s) URL 时才记 url（供 attachment 表 url 列复用）
		byKey.set(key, {
			key,
			url: /^https?:\/\//i.test(src) ? src : '',
		});
	}
	return [...byKey.values()];
}
```

**变更摘要**：新增抽 key 工具，支持裸 key / 完整 URL / `/ext-cos/` 代理 / HTML 实体转义四种形态；按 key 去重；只识别 `notes/{uuid}_...` 形态以排除头像 `assets/` 与电子书 `ebooks/` 等他域 key。

```typescript
	/**
	 * 保存后结算会话：正文里没有的 pending → 删 COS；已认领的只删 pending 行。
	 */
	private async settlePendingSession(
		userId: number,
		sessionId: string,
		html: string,
	): Promise<void> {
		// 抽出当前正文里所有 notes/ key（引用计数白名单）
		const kept = new Set(
			extractNoteImageRefsFromHtml(html).map((r) => r.key),
		);
		// 查该会话所有 pending 行
		const rows = await this.pendingRepo.find({
			where: { userId, sessionId },
			select: { id: true, cosKey: true },
		});

		// 拆分：正文里没有的 key 视为孤儿

			.filter((r) => !kept.has(r.cosKey))
			.map((r) => r.cosKey);
		// 先删所有 pending 行（无论是否孤儿）
		await this.pendingRepo.delete({
			id: In(rows.map((r) => r.id)),
		});
		// 再回收孤儿 key（pending 表已删，attachment 表若无引用即可删 COS）
		await this.deleteOrphanCosKeys(orphanKeys);
	}

		userId: number,
		sessionId: string,
	): Promise<void> {
		// 查该会话所有 pending 行
		const rows = await this.pendingRepo.find({

		await this.pendingRepo.delete({ id: In(rows.map((r) => r.id)) });

	}
```

### 4.19 私有方法 `gcExpiredPending`

```typescript
	/** 过期 pending（崩溃未放弃的会话） */
	private async gcExpiredPending(userId: number): Promise<void> {
		try {
			// 截断时间点：当前时间往前 1h
			const cutoff = new Date(Date.now() - PENDING_TTL_MS);
			// 查该用户 1h 前的 pending（最多取 100 条，避免单次 GC 拖慢主请求）
			const rows = await this.pendingRepo.find({
				where: { userId, createdAt: LessThan(cutoff) },
				select: { id: true, cosKey: true },
				take: 100,
			});
			// 没数据直接返回
			if (!rows.length) return;
			// 收集所有 key
			const keys = rows.map((r) => r.cosKey);
			// 删过期 pending 行
			await this.pendingRepo.delete({ id: In(rows.map((r) => r.id)) });
			// 引用计数回收
			await this.deleteOrphanCosKeys(keys);
		} catch (e) {
			// GC 失败不阻断主请求，仅 warn
			this.logger.warn(
				`清理过期 pending 失败: ${e instanceof Error ? e.message : e}`,
			);
		}
	}
```

### 4.22 前端 `clipboard.ts` 新增 `dataUrlToFile`

**对比范围**：新增 `dataUrlToFile` 函数（纯新增）。

**改动后** · `apps/frontend/src/utils/clipboard.ts`（当前，约 L265–L289）

```typescript
/** data URL → File，供学习笔记等走 onUploadImage，避免桌面端直接塞 base64 */
function dataUrlToFile(dataUrl: string, index = 0): File | null {
	// 正则：匹配 data:<mime>;base64,<payload>
	const m = /^data:([^;,]+);base64,([\s\S]+)$/i.exec(dataUrl.trim());
	// 非 data URL 返回 null
	if (!m) return null;
	// 取 MIME，默认 image/png
	const mime = (m[1] || 'image/png').toLowerCase();
	// 非 image MIME 放弃（仅处理图片）
	if (!mime.startsWith('image/')) return null;
	try {
		// base64 解码为二进制
		const bin = atob(m[2]);
		// 转 Uint8Array
		const bytes = new Uint8Array(bin.length);
		// 逐字节填充
		for (let i = 0; i < bin.length; i++) bytes[i] = bin.charCodeAt(i);
		// 取扩展名（image/png → png；image/svg+xml → svg）
		const ext = mime.split('/')[1]?.split('+')[0] || 'png';
		// 构造 File 对象（name 形如 paste-0.png）
		return new File([bytes], `paste-${index}.${ext}`, { type: mime });
	} catch {
		// 解码失败返回 null
		return null;
	}
}
```

**变更摘要**：新增 `dataUrlToFile`，把 `data:image/...;base64,...` 转 `File` 对象（供 `onUploadImage` 钩子使用），非 data URL / 非图片 / 解码失败均返回 null。

```typescript
/** 从 HTML 抽出 data:image，并从 DOM 移除对应 img（交给上传钩子） */
function extractAndStripDataUrlImages(html: string): {
	html: string;
	dataUrls: string[];
} {
	// 临时容器解析 HTML
	const tmp = document.createElement('div');
	tmp.innerHTML = html;
	// 收集 data: URL
	const dataUrls: string[] = [];
	// 遍历所有 img
	tmp.querySelectorAll('img').forEach((img) => {
		// 取 src 去空白

		img.remove();
	});
	// 返回清洗后 HTML + data URL 列表
	return { html: tmp.innerHTML, dataUrls };
}
```

```typescript
/**
 * 通知 RichEditor ImageUpload：桌面端粘贴的本地图请走 resolveSrc（上传）。
 * 插件 preventDefault 后 Host 不再插入 base64。

function offerDesktopPasteImages(root: HTMLElement, files: File[]): boolean {
	// 无文件直接返回 false
	if (!files.length) return false;

}
```

## 5. 行为变化与兼容性

- **新建笔记 + 粘贴图片**：前端在会话开始生成 UUID `uploadSessionId`，每张图上传时随表单字段带上；保存笔记时一并 `settlePendingSession` 结算。若用户关页面没保存：1 小时后任意笔记读写入口触发 GC 回收 COS。
- **编辑已有笔记 + 粘贴图片**：前端可传 `noteId` 直接落 attachment 行；也可继续传 `uploadSessionId` 走 pending，保存时 `syncAttachmentsFromContent` + `settlePendingSession` 一并处理。
- **编辑期删图 + 保存**：`syncAttachmentsFromContent` 按 diff 删 attachment 行 + 引用计数回收 COS。
- **删整篇笔记**：双源（附件表 + 正文 HTML）收 key → 删附件行 → 删笔记行 → 引用计数回收。
- **桌面端粘贴 `data:image/`**：转 File → 派发 `rich-editor:desktop-paste-images` → RichEditor ImageUpload 扩展 `preventDefault` 后走 `onUploadImage` 钩子上传 COS；事件未被拦截时回退老的 base64 插入路径（兼容未挂载 RichEditor 的场景，避免回归）。
- **桌面端粘贴 HTML 含远程图**：远程图 `<img src="https://...">` 不受影响，仍按 `insertHtmlViaEditor` 整段插入。
- **桌面端粘贴位图（无 HTML）**：若 HTML 完全无 data 图或位图数 > 远程图数且 >1 时补一份位图走上传钩子；否则只走抽出的 data 图。
- **破坏性**：`update` 返回值由 `EnglishLearningNote` 改为 `{ id }`，调用方（前端 `put` 通过 HostBridge）已同步只取 `id`；前端调用 `PUT /english-learning/notes/:id` 时若只想结算可只传 `uploadSessionId`（无需 `title` / `content`）。
- **数据库迁移**：新增 `english_learning_note_attachment` 与 `english_learning_note_pending_upload` 两张表（含唯一约束与索引），部署时跑迁移。

## 6. 风险与回归建议

1. **新建笔记粘贴若干图后关闭浏览器不保存**：等待 1h 后再次进入任意笔记页应触发 GC；COS 上对应 key 应被删除。可在 COS 控制台核对。
2. **编辑已有笔记先粘图后删图再保存**：保存后 `attachment` 表应只剩正文里仍有的 key，COS 上被删图的 key 应回收。
3. **删除整篇笔记**：`attachment` 表对应行清空，COS 上该笔记所有图按引用计数回收（同图被其它笔记引用则不删）。
4. **同一图被多篇笔记引用**：删一篇只删一行，COS 不删；删最后一篇时才真正删 COS。
5. **桌面端粘贴 HTML 含 `<img src="data:...">`**：应走上传钩子，编辑器内回填的应是 `https://.../notes/...` 而非 base64；DOCX 导出时不再做 base64 转码。
6. **桌面端粘贴纯位图**：应转 File 走上传钩子；若未挂载 RichEditor（如普通 `textarea`），应回退 base64 不阻断。
7. **`update` 只传 `uploadSessionId`**：应不写笔记主表，仅结算 pending；返回 `{ id }`。
8. **迁移幂等性**：两套迁移各跑一次（attachments 与 pending_uploads），含表与索引两份；重复跑应 no-op。
9. **桌面端粘贴非图片文件**：`fileFilter` 返回 `BadRequestException('仅支持图片文件')`，前端应提示。
10. **`uploadImage` 未传 `noteId` 与 `sessionId`**：图片已上传 COS 但未登记任何行——会立即成为孤儿。前端务必传其一；可在后端再加一层校验（当前未加，留给调用方约束）。
