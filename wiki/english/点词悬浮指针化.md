# 点词悬浮指针化

> 文档角色：本篇记录**每日阅读点词（GlossSentence）悬浮高亮从 CSS `:hover` 改为指针事件驱动**的实现（当前生效）。

> - 单词 TTS 与正在读高亮（同组件的 `playing` 态）：[单词TTS复读防抖.md](./单词TTS重复播放修复.md)、[TTS单句播放互斥.md](./TTS单句播放互斥.md)
> - 每日阅读前端总览：[每日阅读前端.md](./每日阅读前端.md)

## 1. 背景与目标

改动前，每个可点词的 `<button>` 用 Tailwind 的 `hover:text-teal-400` 做悬浮高亮。在阅读页这种 **ScrollArea 容器 + 两端对齐长正文** 的场景里，CSS `:hover` 容易「粘住」：弹层开关、正文滚动或鼠标快速划过多个词时，浏览器对 `:hover` 的刷新滞后，会出现某个词一直亮着、或多个词同时亮着的错觉。

本轮把悬浮态收进 React 状态：指针进入某词时记下它的 key，离开该词（或离开整句）时清掉，高亮由 `hoverKey === key` 计算，保证任何时刻至多一个词处于悬浮高亮，且指针一走就灭。

## 3. 实现思路

1. **状态代替伪类**：`useState<string | null>` 存当前悬浮词的 key；`onPointerEnter` 设置、`onPointerLeave` 清除。指针事件由浏览器实时派发，不存在 `:hover` 在滚动容器里的刷新滞后。
2. **双保险清除**：词按钮自身的 `onPointerLeave` 用函数式更新（只清自己的 key，避免与相邻词的事件交错时误清别人）；外层整句 `<span>` 再挂一个 `onPointerLeave` 兜底——指针离开整句时无论落在哪个词上都强制清空，覆盖「从词上直接移出句子」的路径。
3. **优先级不变**：弹层打开态（`open`）仍压过悬浮态——打开弹层的词保持更深的 `text-teal-500`，悬浮只给 `text-teal-400`；与原 `:hover` 版本的视觉层级一致。
4. **不删 `playing` 逻辑**：单词朗读中的 `playingWord` 高亮在 `WordLine` 内部，与本改动正交，未动。

单组件内部状态迁移，无跨模块数据流与分支失败路径，按规范略图。

**改动后** · `apps/frontend/src/views/englishLearning/dailyReading/components/GlossSentence.tsx`（当前，约 L93–L183）

```tsx
// 点词句子组件：签名与旧版一致，props 零变化
export function GlossSentence({
	// ...（未改动：en/words/sentenceIndex/openKey/onOpen/playingWord/onPlay/playLabel/stopLabel 九项 props 及其内联类型，前后一致）
}: {
	// ...（未改动：props 类型声明，前后一致）
}) {
	// 源码 ponytail 注释：说明为何弃用 CSS :hover（ScrollArea/两端对齐正文里易粘住）
	// ponytail: CSS :hover 在 ScrollArea / 两端对齐正文里易粘住；指针态可随 leave 清掉
	// 悬浮词 key 状态：null 表示当前没有词被悬浮
	const [hoverKey, setHoverKey] = useState<string | null>(null);
	// 按空白切词并保留分隔符：捕获分组让空白段也留在数组里，逐段原样渲染
	const tokens = en.split(/(\s+)/);
	// 词表对齐游标：记录当前词应对齐到 words 数组的第几个释义
	let at = 0;

	// 外层 span 兜底：指针离开整句时无条件清空悬浮态
	return (
		// 整句容器：兜底 leave 挂在这里，覆盖「从词上直接移出句子」的路径
		<span onPointerLeave={() => setHoverKey(null)}>
			{/* ...（未改动：tokens.map 内的空白 token、链接 token、bare/gloss 对齐与 Popover 结构，前后一致） */}
						<PopoverTrigger asChild>
							{/* 词按钮：触发器本体，指针事件与状态高亮都挂在它身上 */}
							<button
								// 显式声明 type，防止在表单上下文里被当作提交按钮
								type="button"
								// 进入本词即记 key，高亮立刻生效
								onPointerEnter={() => setHoverKey(key)}
								// 离开本词时只清自己的 key：函数式更新防止与相邻词的 enter 事件交错时误清
								onPointerLeave={() =>
									// 仅当当前悬浮的仍是本词才清空：相邻词的 enter 先到时不会误清别人
									setHoverKey((current) => (current === key ? null : current))
								}
								// 高亮改由状态计算：open 态优先（深 teal），否则本词被悬浮才给浅 teal
								className={cn(
									// 基础样式：清掉按钮默认外观；注意这里已删掉 hover:text-teal-400 伪类
									'cursor-pointer bg-transparent p-0 text-inherit',
									// 三态计算：打开深 teal 优先，否则本词被悬浮才浅 teal，都不中保持继承色
									open ? 'text-teal-500' : hoverKey === key && 'text-teal-400',
								)}
							// 开标签收尾，下面进入按钮子内容
							>
								{/* 按钮文本：原样渲染词 token（含附着标点） */}
								{token}
							{/* 词按钮结束：一个可点词的触发器到此闭合 */}
							</button>
						{/* 触发器结束：Popover 的点击锚点封装完毕 */}
						</PopoverTrigger>
			{/* ...（未改动：PopoverContent 与 WordLine 弹层内容，前后一致） */}
		</span>
	);
}
```

**变更摘要**：新增一行 state + 三处指针事件；className 里 `hover:text-teal-400` 伪类删除，改为 `open ? 'text-teal-500' : hoverKey === key && 'text-teal-400'` 的三态计算（打开 > 悬浮 > 普通）。

## 5. 兼容性与影响

- **用户可感知**：点词悬浮高亮随指针进入/离开即时亮灭，不再出现滚动后某个词一直亮着的「粘住」现象；视觉颜色与层级不变。
- **兼容**：纯前端交互实现替换，组件 props 与弹层行为零变化。
- **注意**：`hoverKey === key && 'text-teal-400'` 在不为真时返回 `false`，`cn` 会自动忽略 falsy 项，与旧版 `open && 'text-teal-500'` 同一写法惯例。

## 6. 风险与回归

建议回归路径：

- 指针在一段多词句子上快速横扫：任何时刻至多一个词亮，划走后全灭。
- 点开某词弹层：该词保持深 teal；指针移开弹层仍开、词仍深色；关弹层后词恢复普通色（指针若已离开）或浅 teal（指针还在词上）。
- 正文区内滚动：不再出现静止词一直亮的情况。
- 触屏设备：无指针悬浮概念，`onPointerEnter/Leave` 不干扰点按开弹层。

## 8. 后继更新（2026-11-04）

`GlossSentence` 后续把 `PopoverTrigger` 换成了 `PopoverAnchor`，并去掉 `role="button"` / `tabIndex={0}`，改为 `onClick` 手动打开释义。原因：`PopoverTrigger` 会把每个词当成可聚焦按钮，右键 `mousedown` 聚焦该词时浏览器会清掉跨词选区，导致拖选时「只剩点击处被选中」。改用 `PopoverAnchor` 后，跨词拖选 / 右键复制畅通，左键点词仍可打开释义；有文本选区时点击不弹释义（`hasTextSelection()` 判断）。
