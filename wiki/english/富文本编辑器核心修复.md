# 富文本编辑器核心优化

## 1. 背景与目标

学习笔记富文本编辑器（`apps/remote-plugins/src/components/design/RichEditor/`）在近期使用中暴露出若干选区、气泡与布局问题，本轮针对其核心链路做了一次集中修复与重构。动机如下：

- **GapCursor 选区修正不精确**：`TitleNode.appendTransaction` 仅用 `isGap` 一刀切判断，遇到「正文已空但光标不在段内」时仍把光标钉到正文首段，导致已有内容的正文末尾光标被错误拉回首段。
- **onCreate 选区被 NodeView 打乱**：编辑器初始化时把选区写进正文首段，但 Title 的 ReactNodeView 挂载会扰动选区，导致首帧选区错位、光标落到 title atom 旁。
- **气泡菜单误显**：`BubbleMenu.shouldShow` 内联判断缺少「空选区/非文本选区/编辑器未聚焦」等条件，空段落或失焦时仍会弹出格式气泡。
- **工具栏溢出计算不准**：固定 `gap = 4`、`MORE_RESERVE = 36` 的经验值，未读 `getComputedStyle`，亚像素与真实 padding/gap 下容易出现「多塞一项被裁切」或「More 与可见区错位」。
- **LinkForm 样式不统一**：原生 `<input>/<button>` + 自定义 CSS class，与项目 UI 组件库（`Button`/`Input`）风格不一致。
- **Title 标签样式微调**：标签条与 Input 占位符颜色偏深，视觉上抢标题输入焦点。
- **正文滚动条与列表不一致**：`rich-editor-body` 自带 `overflow-y`，与左侧笔记列表的 `ScrollArea` 滚动条风格不统一。

## 2. 改动范围

- `apps/remote-plugins/src/components/design/RichEditor/title/TitleNode.ts` — `appendTransaction` GapCursor 修正逻辑重写，新增 `Selection` 导入；**本轮追加**：`needsFix` 新增 `sel.empty` 前置条件，新增 `addKeyboardShortcuts()` 重写全选。
- `apps/remote-plugins/src/components/design/RichEditor/index.tsx` — `onCreate` 改用 `requestAnimationFrame` 两帧 + `focusBodyEnd`；`shouldShowBubble` 提取为 `useCallback` 并补全判断；`EditorContent` 改由 `ScrollArea` 包裹。
- `apps/remote-plugins/src/components/design/RichEditor/toolbar/Toolbar.tsx` — 溢出计算重写：`MORE_RESERVE` → `MORE_W`，新增 `fits(toolsW, withMore)` 闭包；JSX 新增 `rich-editor-toolbar-start` 包裹 `toolbar-main` + `toolbar-more`。
- `apps/remote-plugins/src/components/design/RichEditor/link/LinkForm.tsx` — 迁移到 `Button`/`Input` UI 组件 + Tailwind 原子类。
- `apps/remote-plugins/src/components/design/RichEditor/title/Title.tsx` — 标签条与 Input placeholder 样式微调。
- `apps/remote-plugins/src/components/design/RichEditor/styles.css` — 工具栏/正文/链接相关样式调整；**本轮追加**：新增 `::selection` 选区高亮样式，支持主题色变量。
- `apps/remote-plugins/src/components/design/NotePreview/index.tsx` — 外层与 header 样式微调。

## 3. 实现思路

1. **`appendTransaction` 引入 `bodyEmpty` / `caretInBody` 精细判断**：用 `doc.textBetween(titleSize, end)` 判断正文是否完全为空；用 `sel instanceof TextSelection && sel.empty && $from.parent.isTextblock && $from.pos > titleSize` 判断光标是否已在正文段内。仅当「GapCursor / 非正文块 / 正文已空却不在段内」时才修正，避免把已有内容正文末尾的光标错误拉回首段。
2. **选区策略改为 `bodyEmpty ? TextSelection.create : Selection.atEnd`**：正文为空钉回首段（可输入），正文非空则钉到正文末尾，保留用户已有内容的光标语义。
3. **`onCreate` 用 `requestAnimationFrame` 两帧 + `focusBodyEnd`**：第一帧同步尝试，下一帧再钉一次，再下一帧钉第三次，覆盖 Title NodeView 异步挂载对选区的扰动；每次进入前先 `e.isDestroyed` 防御，避免编辑器已销毁后访问 state 报错。
4. **`shouldShowBubble` 提取为 `useCallback`**：用 `linkDraftRef` 镜像 `link.draft`，避免闭包内联导致 deps 漂移；补回 `isTextSelection`、`selection.empty`、`from === to`、`doc.textBetween(from, to)` 空文本判断，并加 `view.hasFocus()` 与 `e.isEditable` 检查，杜绝失焦/只读时空段落误显气泡。
5. **`fits` 闭包重写溢出计算**：用 `getComputedStyle` 精确读取 `paddingLeft/Right` 与 `columnGap/gap`，`contentW = clientWidth - padX`；`fits(toolsW, withMore)` 统一计算「工具区 + 可选 More + 可选 extra + gap」是否放得进 `contentW`，并以 `contentW - 0.5` 做亚像素保守判定，杜绝裁切。
6. **`MORE_RESERVE(36)` → `MORE_W(30)`**：把「More 按钮预留宽度（含间距）」拆为「More 自身宽度 30」与 `fits` 内独立累加的 `gap`，语义更清晰。
7. **`toolbar-start` 包裹 `main + more`**：`main` 改 `flex: 0 1 auto` 不抢剩余空间，`start` 抢 `flex: 1 1 auto`，More 紧跟最后一个可见按钮，extra 始终右贴。
8. **LinkForm 迁移 `Button`/`Input`**：移除 `rich-editor-link-input`/`rich-editor-link-action` 自定义样式，统一由 UI 组件库承担视觉；容器改用 Tailwind 原子类。
9. **`ScrollArea` 接管正文滚动**：`rich-editor-body` 去掉 `overflow-y`/`overscroll-behavior`，由外层 `ScrollArea` 提供与列表一致的滚动条。
10. **全选只覆盖正文，避开 title NodeView**：重写 `Mod-a` 快捷键，从 title 后面第一个 textblock 选到文档末尾，让浏览器能画出原生选区高亮。
11. **`needsFix` 增加 `sel.empty` 前置条件**：有 range 选区时不干预光标修正，保护 Cmd+A 全选不被 `appendTransaction` 清掉。

```typescript
// appendTransaction：每次文档/选区变更后做去重 title、补正文、纠正 GapCursor
appendTransaction(transactions, _old, state) {
    // 既没有文档变更也没有选区变更，直接返回 null（PM 约定不产生新事务）
    if (!transactions.some((tr) => tr.docChanged || tr.selectionSet))
        return null;

    // 基于当前 state 起一个新事务，逐步累积变更
    let tr = state.tr;
    let changed = false;

    // 去掉多余 title：遍历顶层，第二个及以后的 title 记录位置
    const extras: { pos: number; nodeSize: number }[] = [];
    let seen = 0;
    state.doc.forEach((node, offset) => {
        // 非 title 节点跳过
        if (node.type.name !== 'title') return;
        // 命中 title 计数
        seen += 1;
        // 第二个及以后才入队待删
        if (seen > 1) extras.push({ pos: offset, nodeSize: node.nodeSize });
    });
    // 从后往前删，避免删除后位置偏移
    for (let i = extras.length - 1; i >= 0; i--) {
        const { pos, nodeSize } = extras[i];
        // 用空段落替换多余 title，保持文档结构合法
        tr.replaceWith(
            pos,
            pos + nodeSize,
            state.schema.nodes.paragraph.create(),
        );
        changed = true;
    }

    // 取可能已被修改的 doc
    const doc = changed ? tr.doc : state.doc;
    const title = doc.firstChild;
    // 没有正文块时补一段：atom 旁的 GapCursor 看起来有光标但输不进字
    if (title?.type.name === 'title' && doc.childCount < 2) {
        tr = tr.insert(
            title.nodeSize,
            state.schema.nodes.paragraph.create(),
        );
        changed = true;
    }

    // 取最终 doc 与当前选区
    const nextDoc = changed ? tr.doc : state.doc;
    const sel = changed ? tr.selection : state.selection;
    // 仅纠正 GapCursor：看起来有光标但父节点不是 textblock，无法输入
    const isGap =
        sel instanceof GapCursor ||
        (sel.empty && !sel.$from.parent.isTextblock);
    // 是 GapCursor 且首节点是 title 时，把光标钉到正文首段首位置
    if (isGap && nextDoc.firstChild?.type.name === 'title') {
        // 跳过 title atom，+1 进入正文首段
        const pos = nextDoc.firstChild.nodeSize + 1;
        if (pos <= nextDoc.content.size) {
            tr = tr.setSelection(TextSelection.create(nextDoc, pos));
            changed = true;
        }
    }

    // 有变更才返回事务，否则 null
    return changed ? tr : null;
},
```

```typescript
// appendTransaction：去重 title、补正文后，按 bodyEmpty/caretInBody 精细纠正选区
appendTransaction(transactions, _old, state) {
    // 既没有文档变更也没有选区变更，返回 null
    if (!transactions.some((tr) => tr.docChanged || tr.selectionSet))
        return null;

    // 起新事务累积变更
    let tr = state.tr;
    let changed = false;

    // 去掉多余 title：遍历顶层收集第二个及以后的 title
    const extras: { pos: number; nodeSize: number }[] = [];
    let seen = 0;
    state.doc.forEach((node, offset) => {
        // 非 title 跳过
        if (node.type.name !== 'title') return;
        // 计数
        seen += 1;
        // 多余的入队
        if (seen > 1) extras.push({ pos: offset, nodeSize: node.nodeSize });
    });
    // 从后往前替换为空段落
    for (let i = extras.length - 1; i >= 0; i--) {
        const { pos, nodeSize } = extras[i];
        tr.replaceWith(
            pos,
            pos + nodeSize,
            state.schema.nodes.paragraph.create(),
        );
        changed = true;
    }

    // 取可能已修改的 doc
    const doc = changed ? tr.doc : state.doc;
    const title = doc.firstChild;
    // 没有正文块时补一段，避免 atom 旁 GapCursor 输不进字
    if (title?.type.name === 'title' && doc.childCount < 2) {
        tr = tr.insert(
            title.nodeSize,
            state.schema.nodes.paragraph.create(),
        );
        changed = true;
    }

    // 取最终 doc
    const nextDoc = changed ? tr.doc : state.doc;
    // 取首节点（title）做后续判断
    const titleNode = nextDoc.firstChild;
    if (titleNode?.type.name === 'title') {
        // title 节点占据的尺寸，用于定位正文起点
        const titleSize = titleNode.nodeSize;
        // 取当前选区
        const sel = changed ? tr.selection : state.selection;
        // bodyEmpty：title 之后正文是否完全没有文本
        const bodyEmpty = !nextDoc.textBetween(
            titleSize,
            nextDoc.content.size,
        ).length;
        // 光标起点
        const $from = sel.$from;
        // caretInBody：是文本选区且落在正文段内（pos > titleSize）
        const caretInBody =
            sel instanceof TextSelection &&
            sel.empty &&
            $from.parent.isTextblock &&
            $from.pos > titleSize;
        // needsFix：GapCursor / 非正文块 / 正文已空却不在段内 → 需要纠正
        const needsFix =
            sel instanceof GapCursor ||
            (sel.empty && !$from.parent.isTextblock) ||
            (bodyEmpty && !caretInBody);

        // 命中纠正且正文有空间时钉选区
        if (needsFix && titleSize + 1 <= nextDoc.content.size) {
            // 正文为空钉回首段首位置（可输入）；非空钉到正文末尾
            const nextSel = bodyEmpty
                ? TextSelection.create(nextDoc, titleSize + 1)
                : Selection.atEnd(nextDoc);
            tr = tr.setSelection(nextSel);
            changed = true;
        }
    }

    // 有变更才返回事务
    return changed ? tr : null;
},
```

**变更摘要**：新增 `Selection` 导入；用 `bodyEmpty` / `caretInBody` 取代单 `isGap` 判断；选区策略改为「空正文钉首段、非空钉末尾」，避免已有内容正文末尾光标被错误拉回首段。

```typescript
// onCreate：用 focusBodyEnd + 两帧 rAF 抵抗 Title NodeView 挂载对选区的扰动
onCreate: ({ editor: e }) => {
    // 把光标钉到正文末尾的内部函数
    const focusBodyEnd = () => {
        // 编辑器已销毁则直接返回，避免访问 state 报错
        if (e.isDestroyed) return;
        // 首节点是 title 时才 focus end（聚焦到正文末尾）
        if (e.state.doc.firstChild?.type.name === 'title') {
            e.commands.focus('end');
        }
    };
    // 同步先尝试一次
    focusBodyEnd();
    // Title NodeView 挂载可能打乱选区，下一帧再钉到末尾
    requestAnimationFrame(() => {
        // 第二帧再钉一次
        focusBodyEnd();
        // 第三帧再钉一次，彻底覆盖异步挂载
        requestAnimationFrame(focusBodyEnd);
    });
    // 透传外部 onCreate
    onCreate?.(e);
},
```

**变更摘要**：把「钉选区到首段」改为「`focus('end')` 钉到正文末尾」；用两帧 `requestAnimationFrame` 反复重钉，覆盖 NodeView 异步挂载；每次进入先做 `e.isDestroyed` 防御。

```tsx
// 用 ref 镜像 link.draft，避免 useCallback deps 漂移
const linkDraftRef = useRef(link.draft);
// 每次渲染同步最新 draft 到 ref
linkDraftRef.current = link.draft;

// 仅有真实文本选区时显示；补回 TipTap 默认的空块判断，避免空段落误显
const shouldShowBubble = useCallback(
    // shouldShow 回调签名，显式声明参数类型
    ({
        editor: e,
        view,
        state,
        from,
        to,
    }: {
        // 编辑器实例
        editor: Editor;
        // 视图对象，提供 hasFocus
        view: { hasFocus: () => boolean };
        // 编辑器状态，提供 doc/selection
        state: {
            doc: { textBetween: (a: number, b: number) => string };
            selection: { empty: boolean };
        };
        // 选区起点
        from: number;
        // 选区终点
        to: number;
    }) => {
        // 链接草稿存在或不可编辑时隐藏
        if (linkDraftRef.current || !e.isEditable) return false;
        // 编辑器未聚焦时隐藏，避免失焦仍弹气泡
        if (!view.hasFocus()) return false;
        // 解构 doc 与 selection
        const { doc, selection } = state;
        // 非文本选区 / 空选区 / from===to / 选区无文本 → 隐藏
        if (
            !isTextSelection(selection) ||
            selection.empty ||
            from === to ||
            !doc.textBetween(from, to).length
        ) {
            return false;
        }
        // 图片或代码块激活时隐藏
        if (e.isActive('image') || e.isActive('codeBlock')) return false;
        // 其余情况显示
        return true;
    },
    // 空依赖：通过 ref 读取最新 draft，回调稳定
    [],
);
```

```typescript
// useLayoutEffect：测量并裁剪可见工具项
useLayoutEffect(() => {
    // 工具栏根与隐形测量行
    const root = rootRef.current;
    const measure = measureRef.current;
    if (!root || !measure) return;

    // recalc：重算可见项数量
    const recalc = () => {
        // 右侧 extra 宽度
        const extraW = extraRef.current?.offsetWidth ?? 0;
        // 固定 gap=4（经验值，未读 computed style）
        const gap = 4;
        // 可用宽度 = 根宽 - extra - gap
        const avail = root.clientWidth - extraW - gap;
        // 测量行内所有工具节点
        const nodes = [...measure.children] as HTMLElement[];
        if (nodes.length === 0) {
            // 无工具时清零
            setVisibleCount(0);
            return;
        }

        // 每个工具节点的渲染宽度
        const widths = nodes.map((el) => el.getBoundingClientRect().width);
        // 所有工具总宽
        const total = widths.reduce((a, b) => a + b, 0);

        // 全放下：不显示 More
        if (total <= avail) {
            setVisibleCount(widths.length);
            return;
        }

        // 给 More 预留后剩余预算
        const budget = avail - MORE_RESERVE;
        let used = 0;
        let count = 0;
        // 逐项累加直到超出预算
        for (const w of widths) {
            if (used + w > budget) break;
            used += w;
            count += 1;
        }
        // 至少留 0；避免 More 占满后一个都没有仍显示空主区
        setVisibleCount(Math.max(0, count));
    };

    // 立即算一次
    recalc();
    // 监听根与 extra 尺寸变化
    const ro = new ResizeObserver(recalc);
    ro.observe(root);
    if (extraRef.current) ro.observe(extraRef.current);
    return () => ro.disconnect();
```

```typescript
// useLayoutEffect：用 getComputedStyle + fits 闭包精确裁剪
useLayoutEffect(() => {
    // 工具栏根与隐形测量行
    const root = rootRef.current;
    const measure = measureRef.current;
    if (!root || !measure) return;

    // recalc：重算可见项数量
    const recalc = () => {
        // 读取根容器 computed style，精确拿 padding 与 gap
        const cs = getComputedStyle(root);
        // 左右 padding 之和
        const padX =
            (parseFloat(cs.paddingLeft) || 0) + (parseFloat(cs.paddingRight) || 0);
        // column-gap 或 gap
        const gap = parseFloat(cs.columnGap || cs.gap) || 0;
        // 内容区宽度 = clientWidth - padding
        const contentW = root.clientWidth - padX;
        // 右侧 extra 宽度
        const extraW = extraRef.current?.offsetWidth ?? 0;

        // fits：tools 宽度 + 可选 More + 可选 extra 是否放得进 contentW
        const fits = (toolsW: number, withMore: boolean) => {
            // start 区 = 工具 + 可选 More 自身宽度
            const startW = toolsW + (withMore ? MORE_W : 0);
            // 已用 = start 区
            let used = startW;
            // 有 extra 时再加 extra + 一个 gap
            if (extraW > 0) used += extraW + gap;
            // 偏保守，减 0.5px 避免亚像素导致多塞一项被裁切
            return used <= contentW - 0.5;
        };

        // 测量行内所有工具节点
        const nodes = [...measure.children] as HTMLElement[];
        if (nodes.length === 0) {
            // 无工具时清零
            setVisibleCount(0);
            return;
        }

        // 每个工具节点宽度
        const widths = nodes.map((el) => el.getBoundingClientRect().width);
        // 所有工具总宽
        const total = widths.reduce((a, b) => a + b, 0);

        // 全放下（不含 More）则不显示 More
        if (fits(total, false)) {
            setVisibleCount(widths.length);
            return;
        }

        // 逐项累加，需要为 More 预留位置
        let used = 0;
        let count = 0;
        for (const w of widths) {
            // 放到 used+w 并带 More 后还放得下才计入
            if (!fits(used + w, true)) break;
            used += w;
            count += 1;
        }
        // 设置可见数量
        setVisibleCount(count);
    };

    // 立即算一次
    recalc();
    // 监听根与 extra 尺寸变化
    const ro = new ResizeObserver(recalc);
    ro.observe(root);
    if (extraRef.current) ro.observe(extraRef.current);
    return () => ro.disconnect();
}, [tools]);
```

**变更摘要**：`MORE_RESERVE(36)` 拆为 `MORE_W(30)` + `fits` 内独立累加的 `gap`；用 `getComputedStyle` 精确读取 `padding`/`gap`，`contentW = clientWidth - padX`；引入 `fits(toolsW, withMore)` 闭包统一判定，并以 `contentW - 0.5` 做亚像素保守判定。

**改动后** · `apps/remote-plugins/src/components/design/RichEditor/title/TitleNode.ts`（当前，约 L152–L173）

```typescript
// 注册键盘快捷键：重写全选行为，避开 title NodeView
addKeyboardShortcuts() {
    return {
        // Mod-a = Cmd+A（macOS）/ Ctrl+A（Windows/Linux）
        'Mod-a': ({ editor }) => {
            // 取当前文档
            const { doc } = editor.state;
            // 取首节点
            const title = doc.firstChild;
            // 首节点不是 title 则不接管，交给默认行为
            if (title?.type.name !== 'title') return false;

            // 正文起点：跳过 title atom，+1 进入第一个 textblock 内部
            const start = title.nodeSize + 1;
            // 正文起点已超出文档末尾则不选（理论上不会发生）
            if (start >= doc.content.size) return true;

            // 用 TextSelection.near 找到最接近的有效文本选区起点（向前搜索）
            const from = TextSelection.near(doc.resolve(start), 1).from;
            // 选区终点：文档末尾
            const to = Selection.atEnd(doc).to;
            // 起点 < 终点才设置范围选区，否则退化为塌缩光标
            if (from < to) {
                editor.commands.setTextSelection({ from, to });
            } else {
                editor.commands.setTextSelection(from);
            }
            // 拦截默认全选
            return true;
        },
    };
},
```

**变更摘要**：新增 `addKeyboardShortcuts()` 方法，重写 `Mod-a` 全选；只选 title 之后的正文部分，避开 title NodeView，让浏览器能画出原生选区高亮。

## 5. 兼容性与影响

- **选区行为**：`appendTransaction` 不再把「正文非空但光标在 GapCursor」的场景一刀切钉回首段，改为钉到正文末尾，已有内容正文的光标语义更自然；空正文仍钉首段，输入体验不变。
- **初始化选区**：`onCreate` 由「钉首段」改为「钉正文末尾」，且两帧 rAF 重钉，首次打开编辑器光标稳定落在正文末尾；`e.isDestroyed` 防御避免卸载后报错。
- **气泡菜单**：`shouldShowBubble` 收紧显示条件，失焦/只读/空选区/空文本不再弹气泡，避免误显；`useCallback` 稳定引用减少 `BubbleMenu` 不必要重渲染。
- **工具栏溢出**：`fits` + `getComputedStyle` 让溢出计算随真实 padding/gap 自适应，`MORE_W` 拆分使 More 宽度语义更准；`toolbar-start` 包裹让 More 紧跟可见按钮、extra 始终右贴。
- **链接表单**：`LinkForm` 视觉与项目其它表单统一；移除 `rich-editor-link-input` 自定义样式后，旧的 `.rich-editor-link-input` CSS 已删除，不会影响其它引用（仅本组件使用）。
- **正文滚动**：`rich-editor-body` 不再自带滚动，由 `ScrollArea` 接管，滚动条风格与左侧笔记列表一致；`NotePreview` 同样依赖 `ScrollArea`，行为不变。
- **样式**：`.rich-editor` 的 `color` 注释掉后，正文文字颜色由上层主题继承，需确认各使用场景上层已提供 `--theme-textcolor`/`foreground`。
- **全选行为**：`Mod-a` 重写后只选正文部分（避开 title NodeView），浏览器原生选区高亮能正常显示；`needsFix` 增加 `sel.empty` 前置条件，有 range 选区时 `appendTransaction` 不再干预，保护 Cmd+A 全选不被清掉。
- **选区高亮样式**：新增 `::selection` 规则，默认用主题色 42% 透明作为选区背景；支持 `--theme-selection-bg` / `--theme-selection-fg` CSS 变量覆盖，各主题可自定义选区颜色。
- **回归建议**：重点验证①空笔记新建后光标位置与可直接输入；②已有内容笔记打开后光标在正文末尾；③选中文本才弹气泡、点击空白/失焦不弹；④工具栏在窄宽下 More 正确出现且不裁切；⑤链接表单输入/Enter/Esc/应用/解链；⑥Cmd+A 全选仅覆盖正文、浏览器原生选区高亮正常显示；⑦Tauri 与 Web 两种运行环境。
