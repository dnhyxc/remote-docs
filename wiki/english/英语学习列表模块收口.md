## 1. 背景与目标

「固定列表统一虚拟滚动与续读」初版方案把续读能力拆成两层：

1. 通用 store 层 `apps/frontend/src/store/englishLibraryItemsResume.ts`：按 `(kind, libraryId)` 管理会话缓存与 keepalive flush，**只为资源库词条服务**；
2. 固定列表 helper 层 `apps/frontend/src/views/englishLearning/hooks/englishLearningListResume.ts`：把 5 个固定列表 scope 映射到占位 `libraryId`，再委托通用 store。

同时统一 Hook `useLibraryWordsList` 仍放在 `apps/frontend/src/views/englishLearning/library/hooks/` 下，工具函数放在 `library/utils/` 下——命名与路径都带「library」，但实际已被收藏 / 错题 / 每日记词等非资源库列表复用。

本轮改动把上述分散的模块**收口**为一套路径与命名都脱离「library」前缀的通用英语学习列表基础设施：

1. **Hook 重命名并上移**：`useLibraryWordsList` → `useEnglishLearningList`，从 `library/hooks/` 移到 `hooks/`；类型 `LibraryWordsListResult` → `ElListPageResult`、`UseLibraryWordsListOptions` → `UseEnglishLearningListOptions`。
2. **工具函数上移**：`libraryWordsListCache.ts` / `libraryWordsListPrefetch.ts` / `libraryWordsListResume.ts` 从 `library/utils/` 移到 `utils/`。
3. **续读 store 合并**：删除 `store/englishLibraryItemsResume.ts`，把通用 store 与固定列表 scope helper 合并为 `store/englishLearningResume.ts`（函数前缀 `EnglishLibraryItemsResume` → `El`，scope helper 前缀 `englishLearningFixedList` → `elFixedList`）。
4. **服务层统一路由**：在 `service/index.ts` 新增 `resolveElListResumePatch` + `patchElListResume`，按 `(kind, libraryId)` 路由到对应 PATCH API，store 层不再按 kind 分支。
5. **后端常量落盘**：占位 `libraryId` 常量从只在 service 内使用，改为 `apps/backend/.../english-learning-list-resume.constants.ts` 独立文件，前端 `constants/index.ts` 同步镜像。

## 3. 实现思路

### 3.1 Hook 与类型重命名

`useLibraryWordsList` 原本只为资源库词条设计，但「固定列表统一虚拟滚动」一轮已让它同时服务收藏 / 错题 / 记词记录。命名仍带 `Library` 会误导读者以为只用于资源库。本轮把：

- Hook：`useLibraryWordsList` → `useEnglishLearningList`（语义：英语学习分页列表）；
- 结果类型：`LibraryWordsListResult<TItem, TLibrary>` → `ElListPageResult<TItem, TLibrary>`（`El` = English Learning）；
- 选项类型：`UseLibraryWordsListOptions<TItem, TLibrary>` → `UseEnglishLearningListOptions<TItem, TLibrary>`；
- 文件注释：`资源库右侧词条列表` → `英语学习分页列表`。

文件从 `library/hooks/` 移到 `hooks/`，使导入路径 `from '../hooks/useEnglishLearningList'` 对 library / favorites / mistakes / daily 各域都自然。

### 3.2 工具函数上移

`libraryWordsListCache.ts` / `libraryWordsListPrefetch.ts` / `libraryWordsListResume.ts` 三个工具从 `library/utils/` 移到 `utils/`，与 Hook 同级。文件名保持不变（`library` 前缀仍指「列表」语义，不再特指资源库），避免大范围改导入语句。

### 3.3 续读 store 合并

旧设计把续读拆成两层：

- `store/englishLibraryItemsResume.ts`：通用 `set/get/resolve/hydrate/flush/clear`，按 `(kind, libraryId)` 操作 `english_library_items_resume` 表；`flush` 内按 `kind` 分支调 `patchEnglishVocabularyLibraryItemsResume` / `patchEnglishClassicQuotesLibraryItemsResume`。
- 计划中的 `hooks/englishLearningListResume.ts`：固定列表 scope → `(kind, 占位 libraryId)` 映射 + 调通用 store。

合并后的 `store/englishLearningResume.ts` 在同一文件内分两段：

1. **通用段**（`El` 前缀）：`setElResumeOffset` / `getElResumeOffset` / `resolveElResumeOffset` / `hydrateElResumeOffset` / `flushElResume` / `clearElResumeOffset` / `clearElResumeCache`。`flushElResume` 不再按 kind 分支，而是调服务层统一路由 `patchElListResume(kind, id, offset, opts)`。
2. **固定列表段**（`ElFixedList` 前缀）：`ElFixedListScope` 类型 + `elFixedListResumeId` / `elFixedListKind` / `resolveElFixedListResume` / `setElFixedListResume` / `flushElFixedListResume` / `resolveElFixedListInitialResume`。这些 helper 内部调通用段，把 scope 映射成 `(kind, 占位 libraryId)`。

合并的好处：两层不再跨文件互相 import；scope helper 与通用 store 的命名一致收口；`resetUserState` 只需 import 一个文件。

### 3.4 服务层统一路由

旧 `flush` 内按 `kind` 分支：

```typescript
const patch = kind === 'vocab'
  ? patchEnglishVocabularyLibraryItemsResume
  : patchEnglishClassicQuotesLibraryItemsResume;
```

但固定列表有 5 个 scope，对应 5 个不同的 PATCH 端点（单词收藏 / 经典句收藏 / 单词错题 / 经典句错题 / 每日记词记录），不能用 `kind` 二分。服务层新增 `resolveElListResumePatch(kind, libraryId)`：按 `kind` + 占位 `libraryId` 路由到对应的 `patch*` / `keep*` 函数对。store 层 `flushElResume` 调 `patchElListResume(kind, id, offset, opts)` 即可，不再感知具体端点。

### 3.5 后端常量独立

占位 `libraryId`（如 `__el-vocab-favorites__`）原散落在 service 各处。本轮把它们抽到 `apps/backend/src/services/english-learning/english-learning-list-resume.constants.ts`，前端 `apps/frontend/src/constants/index.ts` 镜像同一对象，注释标注「与后端一致」，确保前后端占位 ID 不漂移。

### 4.3 续读 store 合并：通用段（改动前 → 改动后）

**改动前** · `apps/frontend/src/store/englishLibraryItemsResume.ts`（基线，约 L84–L133）

```typescript
// 将本地 dirty 续读刷到服务端
export function flushEnglishLibraryItemsResume(
	// kind：vocab 或 classic
	kind: LibraryKind,
	// libraryId：资源库真实 id
	libraryId: string,
	// 可选：keepalive 标志（页面卸载时为 true）
	opts?: { keepalive?: boolean },
): void {
	// trim libraryId
	const id = libraryId.trim();
	// 空 id 直接返回
	if (!id) return;
	// 取 entry key
	const key = entryKey(kind, id);
	// 非 dirty 直接返回
	if (!dirty.has(key)) return;
	// 取本地 offset
	const offset = offsets.get(key) ?? 0;

	// keepalive 分支：同步发请求，不等返回
	if (opts?.keepalive) {
		// 按 kind 分支调对应 keepalive API
		if (kind === 'vocab') {
			// 单词库 keepalive patch
			patchEnglishVocabularyLibraryItemsResumeKeepalive(id, offset);
		} else {
			// 经典句库 keepalive patch
			patchEnglishClassicQuotesLibraryItemsResumeKeepalive(id, offset);
		}
		// 标记已同步
		synced.set(key, offset);
		// 移出 dirty
		dirty.delete(key);
		// 返回
		return;
	}

	// 非 keepalive：按 kind 分支选 patch 函数
	const patch =
		kind === 'vocab'
			? patchEnglishVocabularyLibraryItemsResume
			: patchEnglishClassicQuotesLibraryItemsResume;
	// 异步调 patch
	void patch(id, offset)
		.then(() => {
			// 成功后标记已同步
			synced.set(key, offset);
			// 移出 dirty
			dirty.delete(key);
		})
		.catch(() => {
			// 失败保持 dirty，下次离开再试
		});
}
```

```typescript
export function flushElResume(
	// kind：vocab 或 classic
	kind: LibraryKind,
	// libraryId：资源库真实 id 或固定列表占位 id
	libraryId: string,
	// 可选：keepalive 标志（页面卸载时为 true）
	opts?: { keepalive?: boolean },
): void {
	// trim libraryId
	const id = libraryId.trim();
	// 空 id 直接返回
	if (!id) return;
	// 取 entry key
	const key = entryKey(kind, id);
	// 非 dirty 直接返回
	if (!dirty.has(key)) return;
	// 取本地 offset
	const offset = offsets.get(key) ?? 0;

	// keepalive 分支：委托服务层 patchElListResume（内部按 kind+id 路由）
	if (opts?.keepalive) {
		// 调统一路由函数，keepalive=true
		void patchElListResume(kind, id, offset, { keepalive: true });
		// 标记已同步
		synced.set(key, offset);
		// 移出 dirty
		dirty.delete(key);
		// 返回
		return;
	}

	// 非 keepalive：委托服务层统一路由，不再在 store 内按 kind 分支
	void patchElListResume(kind, id, offset)
		.then(() => {
			// 成功后标记已同步
			synced.set(key, offset);
			// 移出 dirty
			dirty.delete(key);
		})
		.catch(() => {
			// 失败保持 dirty，下次离开再试
		});
}
```

**变更摘要**：`flush` 内删除 `kind === 'vocab'` 分支与两个直接 patch 调用，改为统一委托 `patchElListResume(kind, id, offset, opts)`；函数名 `flushEnglishLibraryItemsResume` → `flushElResume`。

```typescript
		// 按 scope 分支

			// 经典句收藏

			case 'vocab-mistakes':

				return getVocabMissResume;
			// 经典句错题
			case 'classic-mistakes':

				return getClassicMissResume;
			// 每日记词记录
			case 'vocab-daily-memorize':
				// 返回对应 API
				return getDailyMemoResume;
```

```typescript
// 续读 PATCH 的 kind 联合类型（与 LibraryKind 一致）
export type ElListResumeKind = 'vocab' | 'classic';

// 一对 patch 函数：非 keepalive（返回 Promise）与 keepalive（同步发请求不等返回）
type ElListResumePatchPair = {
	// 非 keepalive patch：返回 Promise<unknown>
	patch: (offset: number) => Promise<unknown>;
	// keepalive patch：同步调用，无返回
	keepalive: (offset: number) => void;
};

// 按 (kind, libraryId) 路由到对应的 patch / keepalive 函数对
function resolveElListResumePatch(
	// kind：vocab 或 classic
	kind: ElListResumeKind,
	// libraryId：资源库真实 id 或固定列表占位 id
	libraryId: string,
): ElListResumePatchPair {
	// trim libraryId
	const id = libraryId.trim();
	// vocab 分支
	if (kind === 'vocab') {
		// 单词收藏占位 id
		if (id === ENGLISH_LEARNING_LIST_RESUME_LIBRARY_ID.vocabFavorites) {
			// 返回单词收藏的 patch / keepalive 对
			return { patch: patchVocabFavResume, keepalive: keepVocabFavResume };
		}
		// 单词错题占位 id
		if (id === ENGLISH_LEARNING_LIST_RESUME_LIBRARY_ID.vocabMistakes) {
			// 返回单词错题的 patch / keepalive 对
			return { patch: patchVocabMissResume, keepalive: keepVocabMissResume };
		}
		// 每日记词记录占位 id
		if (id === ENGLISH_LEARNING_LIST_RESUME_LIBRARY_ID.vocabDailyMemorize) {
			// 返回记词记录的 patch / keepalive 对
			return { patch: patchDailyMemoResume, keepalive: keepDailyMemoResume };
		}
		// 其余 vocab id 视为资源库词条
		return {
			// 资源库词条 patch（需传 id）
			patch: (offset) => patchVocabLibResume(id, offset),
			// 资源库词条 keepalive（需传 id）
			keepalive: (offset) => keepVocabLibResume(id, offset),
		};
	}

	// classic 分支：经典句收藏占位 id
	if (id === ENGLISH_LEARNING_LIST_RESUME_LIBRARY_ID.classicFavorites) {
		// 返回经典句收藏的 patch / keepalive 对
		return { patch: patchClassicFavResume, keepalive: keepClassicFavResume };
	}
	// 经典句错题占位 id
	if (id === ENGLISH_LEARNING_LIST_RESUME_LIBRARY_ID.classicMistakes) {
		// 返回经典句错题的 patch / keepalive 对
		return { patch: patchClassicMissResume, keepalive: keepClassicMissResume };
	}
	// 其余 classic id 视为经典句资源库词条
	return {
		// 经典句资源库词条 patch（需传 id）
		patch: (offset) => patchClassicLibResume(id, offset),
		// 经典句资源库词条 keepalive（需传 id）
		keepalive: (offset) => keepClassicLibResume(id, offset),
	};
}

// 按列表类型 + libraryId 路由续读 PATCH（含 keepalive）
export function patchElListResume(
	// kind：vocab 或 classic
	kind: ElListResumeKind,
	// libraryId：资源库真实 id 或固定列表占位 id
	libraryId: string,
	// 续读 offset
	offset: number,
	// 可选：keepalive 标志
	opts?: { keepalive?: boolean },
): Promise<void> {
	// 解析出对应的 patch / keepalive 函数对
	const { patch, keepalive } = resolveElListResumePatch(kind, libraryId);
	// keepalive 分支
	if (opts?.keepalive) {
		// 同步调用 keepalive（不等返回）
		keepalive(offset);
		// 返回已 resolved 的 Promise
		return Promise.resolve();
	}
	// 非 keepalive：调 patch 并映射为 void
	return patch(offset).then(() => undefined);
}
```

**变更摘要**：新增 `resolveElListResumePatch` 按 `(kind, libraryId)` 路由到 5 个固定列表 + 2 个资源库共 7 对 patch/keepalive 函数；新增 `patchElListResume` 作为统一入口，store 层 `flushElResume` 调此函数即可，不再感知具体端点。

## 5. 兼容性与影响

- **向后兼容**：Hook 重命名 + 文件移动属于纯路径变更，所有调用方已在同轮更新 import；类型新增字段（`resolveInitialResume` / `refetchOnEnter` / `totalCount` / `patchItems` / `setItems` / `reloadFromStart`）均为可选或新增返回值，老调用方不使用时不受影响。
- **行为变化**：
  - `flushElResume` 不再在 store 内按 kind 分支，改为委托 `patchElListResume` 统一路由；5 个固定列表的 keepalive flush 现在能正确路由到各自端点（旧版只支持资源库词条）。
  - 切换账号时 `clearElResumeCache` 清空所有英语学习列表续读缓存（资源库 + 5 个固定列表），覆盖范围与旧版一致。
- **风险与回归建议**：
  - 5 个固定列表 + 资源库词条列表的续读 offset 是否正确持久化与恢复；
  - `pagehide` / `visibilitychange` 时 `flushElResume(scope, { keepalive: true })` 是否路由到正确端点；
  - 切换账号后所有列表续读缓存是否清空；
  - `useEnglishLearningList` 的 `reloadFromStart` 在删除条目后是否正确重载；
  - `LibraryVirtuosoGrid` 的 FAB 拦截与程序化滚动是否正常（滚动注册表路径变更后）。
