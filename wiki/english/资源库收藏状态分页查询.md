# 资源库收藏状态分页查询：按库 offset 批量取 + Hook 会话缓存

> 解决资源库（单词库 / 经典句库）接入虚拟滚动 + 一次性预取续读窗口后，**收藏星状态查询从按词 POST 变为按库 offset GET**，减少 N 次去重循环与大 body，同时做**会话级缓存**避免列表重挂载 / 缓存恢复时重复打 status。  
> 延伸阅读：[资源库词条续读.md](./资源库词条续读.md)（跨会话进度）、[资源库词条预取并发.md](./资源库词条预取并发.md)（续读窗口并发取词条 / 收藏状态）。

若与仓库最新源码不一致，**以源码为准**。

---

## 1. 背景与目标

### 1.1 问题：原「按词批量 POST」在资源库场景的 3 个缺点

旧版 `useIncrementalVocabFavoriteStatus` 对所有场景都走同一套逻辑：把当前 items 中**还没查过**的词提取出来，用 POST `/vocabulary-favorites/status`（body 内含词数组，上限 500）。

资源库场景下有 3 个问题：

| 问题 | 说明 |
| --- | --- |
| 大 body | 续读窗口一次预取 3000 词条，要遍历 3000 个 item 去重、拼 word 数组，再转 JSON body |
| 与分页不对齐 | items 分页是按 (libraryId, offset, limit) 拉，但收藏状态按随机 word 集合查，后端需要 `IN (words)`，词数多时索引利用率不如按 offset 扫库内排序表 |
| 列表重挂载重复查 | 缓存恢复（`libraryWordsListCache`）或切回该库时，items 整体替换被视为「非增量」，清空 state 后重新查一遍；同一会话内几千个词又 POST 一次 |

### 1.2 目标

1. **资源库专用接口**：对「单词库 / 经典句库」新增 `GET .../:libraryId/favorites-status?limit&offset`，与 items API 的分页完全对齐。
2. **Hook 双模式**：传 `libraryId` 时用新 GET 接口（并按 offset 并发分块）；未传时回退旧 POST 接口（保持其他场景兼容）。
3. **会话级缓存**：
   - 模块级 `sessionQueriedWordKeys` / `sessionFavoriteIdByWordKey` 记录整会话内已查过的词，整体替换时优先从会话缓存「播种（seed）」state。
   - 模块级 `sessionLibraryStatusEnd` 记录某库已按 offset 查到哪个位置，列表重挂载不重复查同一段。
4. **后端 limit 上限**：单词库与经典句库的 items / favorites-status 分页 limit 上限从 200 提到 1000，减少续读窗口的 HTTP 次数。

## 3. 实现思路

### 3.1 后端：与 items 分页同源查收藏

以单词库为例：

1. **鉴权 + 可读断言**：先 `assertVocabularyLibraryReadable(userId, libraryId)`（自有或公开都可以读自己的收藏状态）。
2. **按 (libraryId, sortOrder) 扫 items 表**：`take: limit / skip: offset / select: ['word']`，只取 word 一列（够做去重 key）。
3. **用 word 集合查用户收藏表**：调用已有 `listVocabularyFavoriteRefsForWords(userId, words)`，返回 `{ wordKey, id }`。

这样好处：分页逻辑与 listVocabularyLibraryItems **完全同序**（都是 `sortOrder ASC`），前端用同样的 (offset, limit) 查 items 与 favorites-status 时，结果一一对应。

### 3.2 前端 Hook：双模式分支

```
useIncrementalVocabFavoriteStatus(items, { libraryId })
  ├── 有 libraryId（资源库场景）
  │    ├── 用 sessionLibraryStatusEnd 查到当前查过哪个位置
  │    ├── 对 [statusEnd, items.length) 用 buildLibraryRangeChunks 按 1000 切片
  │    ├── mapWithConcurrency(3) 并发 GET favorites-status
  │    ├── 合并结果 → state + sessionFavoriteIdByWordKey
  │    └── 更新 sessionLibraryStatusEnd = items.length
  └── 无 libraryId（其他场景：错题集 / 单词卡详情等）
       ├── 旧版逻辑：遍历 items → 归一化 wordKey → 去重 → POST /status
       └── 失败回滚 queriedKeys，下次重试
```

整体替换（非 append / 非 prepend）时：
- 先尝试 `seedFavoriteStateFromSession(items)`：把会话内已查过的词直接播种回 state，避免浪费一次请求。
- 再按分支查剩余部分。

### 4.4 `useIncrementalVocabFavoriteStatus`：新增 libraryId 模式 + 会话缓存（改动前 / 改动后）

**对比范围**：整个 Hook（从 import 到 return），因为新增了模块级缓存、options 参数、双模式分支。

**改动前** · `apps/frontend/src/hooks/useIncrementalVocabFavoriteStatus.ts`（基线，全文）

```typescript
/**
 * 按列表增量查询单词收藏状态：仅对尚未查询过的词请求 /status，结果合并进 Map（wordKey → 收藏 id）。
 * 末尾追加 / 头部 prepend 均视为增量；仅整体替换时才清空本地状态并重新查询。
 */
// React Hook 基础：副作用 / 缓存 / ref / state
import { useEffect, useMemo, useRef, useState } from 'react';
// service 引入：收藏引用类型、旧版按词批量 POST、归一化工具
import {
	type EnglishVocabFavoriteRef,
	fetchEnglishVocabularyFavoriteStatus,
	normalizeEnglishVocabWordKey,
} from '@/service';

// 生成签名时使用的词分隔符（控制字符 U+0001，不应该出现在真实词中）
const WORD_SIG_SEP = '\u0001';
// 去抖 150ms：快速 append / prepend 合并成一次请求
const STATUS_QUERY_DEBOUNCE_MS = 150;

// 旧版签名：只有 items，没有 libraryId
export function useIncrementalVocabFavoriteStatus(
	items: ReadonlyArray<{ word: string }>,
) {
	// state：wordKey → 收藏 id 的 Map（驱动 favoritedWordKeys 重算）
	const [favoriteIdByWordKey, setFavoriteIdByWordKey] = useState<
		Map<string, string>
	>(() => new Map());
	// ref：本 Hook 生命周期内已查过的 key（避免重复请求）
	const queriedKeysRef = useRef<Set<string>>(new Set());
	// ref：上次 items 的「全量词签名」（用于判断 append / prepend / 整体替换）
	const prevItemsWordSigRef = useRef('');

	// 已收藏的 wordKey 集合（Set 版，便于 `has` O(1)）
	const favoritedWordKeys = useMemo(
		() => new Set(favoriteIdByWordKey.keys()),
		[favoriteIdByWordKey],
	);

	// 全量词签名：把所有词用 U+0001 拼起来；append 时新签名以旧签名开头，prepend 时新签名以旧签名结尾
	const itemsWordSig = useMemo(
		() => items.map((it) => it.word).join(WORD_SIG_SEP),
		[items],
	);

	// 副作用：items 或签名变化时触发去抖查询
	useEffect(() => {
		// 空列表：清空所有状态，直接返回
		if (items.length === 0) {
			setFavoriteIdByWordKey(new Map());
			queriedKeysRef.current = new Set();
			prevItemsWordSigRef.current = '';
			return;
		}

		// 判断 append：新签名开头 = 旧签名（或完全相等=不变）
		const prevSig = prevItemsWordSigRef.current;
		const appended =
			prevSig.length > 0 &&
			(itemsWordSig === prevSig ||
				itemsWordSig.startsWith(`${prevSig}${WORD_SIG_SEP}`));
		// 判断 prepend：新签名结尾 = 旧签名（或完全相等）
		const prepended =
			prevSig.length > 0 &&
			(itemsWordSig === prevSig ||
				itemsWordSig.endsWith(`${WORD_SIG_SEP}${prevSig}`));
		// 既非 append 又非 prepend → 整体替换 → 清空 state 与已查集合（从头开始查）
		if (!appended && !prepended) {
			setFavoriteIdByWordKey(new Map());
			queriedKeysRef.current = new Set();
		}
		// 写入本次签名，供下次比较
		prevItemsWordSigRef.current = itemsWordSig;

		// 去抖：150ms 内 items 再变则重置，避免瞬态触发多次
		let cancelled = false;
		const timer = window.setTimeout(() => {
			// 本轮需要查询的词：遍历 items，挑出未查过的
			const wordsToQuery: string[] = [];
			for (const item of items) {
				// 归一化（trim + 小写）→ wordKey
				const wk = normalizeEnglishVocabWordKey(item.word);
				// 非法 key 或已查过 → 跳过
				if (!wk || queriedKeysRef.current.has(wk)) continue;
				// 先写入已查（乐观：失败时回滚删除）
				queriedKeysRef.current.add(wk);
				wordsToQuery.push(item.word);
			}
			// 没有新词 → 直接返回（不发请求）
			if (wordsToQuery.length === 0) return;

			// 合并收藏引用：把 refs 合并进 state Map
			const mergeFavoritedRefs = (refs: EnglishVocabFavoriteRef[]) => {
				// 已取消（effect 提前 cleanup）或空 → 不做
				if (cancelled || refs.length === 0) return;
				setFavoriteIdByWordKey((prev) => {
					// 拷贝旧 Map
					const next = new Map(prev);
					// 逐个合并
					for (const r of refs) next.set(r.wordKey, r.id);
					return next;
				});
			};

			// 走旧版按词批量 POST
			void (async () => {
				try {
					await fetchEnglishVocabularyFavoriteStatus(wordsToQuery, {
						// 分块返回时逐块合并
						onPartial: mergeFavoritedRefs,
					});
					if (cancelled) return;
				} catch {
					// 失败：回滚本次乐观写入的 queriedKeys（下次可重试）
					if (!cancelled) {
						for (const word of wordsToQuery) {
							const wk = normalizeEnglishVocabWordKey(word);
							if (wk) queriedKeysRef.current.delete(wk);
						}
					}
				}
			})();
		}, STATUS_QUERY_DEBOUNCE_MS);

		// cleanup：标记取消 + 清定时器

		Map<string, string>

		() => new Set(favoriteIdByWordKey.keys()),

		() => items.map((it) => it.word).join(WORD_SIG_SEP),

		// libraryId 切换 → 重置组件级 statusEnd（从 session 读上次查到哪）

			libraryStatusEndRef.current = libraryId
				? (sessionLibraryStatusEnd.get(libraryId) ?? 0)

		if (items.length === 0) {
			setFavoriteIdByWordKey(new Map());
			queriedKeysRef.current = new Set();
			prevItemsWordSigRef.current = '';
			if (libraryId) {
				libraryStatusEndRef.current =
					sessionLibraryStatusEnd.get(libraryId) ?? 0;
			}
			return;
		}

		// append / prepend 判断（同旧版）
		const prevSig = prevItemsWordSigRef.current;
		const appended =
			prevSig.length > 0 &&
			(itemsWordSig === prevSig ||
				itemsWordSig.startsWith(`${prevSig}${WORD_SIG_SEP}`));

			prevSig.length > 0 &&
			(itemsWordSig === prevSig ||

			setFavoriteIdByWordKey(seeded.map);
			queriedKeysRef.current = seeded.queried;

			if (libraryId) {
				libraryStatusEndRef.current = Math.min(
					sessionLibraryStatusEnd.get(libraryId) ?? 0,
					items.length,
				);
			}

			// 合并收藏引用（新版比旧版多了 session 写入）
			const mergeFavoritedRefs = (refs: EnglishVocabFavoriteRef[]) => {
				if (cancelled || refs.length === 0) return;
				setFavoriteIdByWordKey((prev) => {
					const next = new Map(prev);

						next.set(r.wordKey, r.id);

					return;

								return refs;
							},
						);
						// 中途被取消（切库 / 切页）：不写 session
						if (cancelled) return;
						// 成功：推进 statusEnd = 本次目标
						libraryStatusEndRef.current = fetchTo;
						sessionLibraryStatusEnd.set(libraryId, fetchTo);
						// 并把这段 items 的词标为会话已查
						markWordsFromItemsQueried(items.slice(fetchFrom, fetchTo));
					} catch {
						// 失败：回滚 statusEnd 到 fetchFrom（下次重试）
						if (!cancelled) {
							libraryStatusEndRef.current = fetchFrom;
						}
					}
				})();
				// 资源库分支直接返回，不走下面的 POST 分支
				return;
			}

			// ========= 分支 2：非资源库模式（旧版按词 POST） =========

			}

			void (async () => {

								sessionQueriedWordKeys.delete(wk);

						}
					}
				}
			})();
		}, STATUS_QUERY_DEBOUNCE_MS);

		return () => {
			cancelled = true;
			clearTimeout(timer);
		};

	}, [itemsWordSig, items, libraryId]);

		favoriteIdByWordKey.get(wordKey);

	// set：旧版只写 state，新版同步写入会话级缓存

		});
	};

			const next = new Map(prev);
			next.delete(wordKey);
			return next;
		});
	};

	return {
		favoritedWordKeys,
		getVocabularyFavoriteId,
		setVocabularyFavoriteId,
		clearVocabularyFavorite,
	};

- **双模式分支**：`if (libraryId)` 走 GET offset 分页并发请求；否则走旧版按词 POST。
- **会话级缓存**：整体替换不再从头重查，先 seed；set/clear 也同步维护 sessionFavoriteIdByWordKey。
- **按库进度追踪**：`sessionLibraryStatusEnd` 记录某库已查到哪个 offset，Hook 实例重挂载不重复查。
- **成功/失败回滚**：GET 分支推进或回滚 `libraryStatusEndRef`；POST 分支同步回滚会话级 queried。

				if (!ck || queriedKeysRef.current.has(ck)) continue;
				// 乐观写入实例级（经典句库没有写会话 queried 缓存）
				queriedKeysRef.current.add(ck);
				englishesToQuery.push(item.english);
			}
			if (englishesToQuery.length === 0) return;

			// 旧版 POST（同旧版）
			void (async () => {
				try {
					await fetchEnglishClassicQuoteFavoriteStatus(englishesToQuery, {
						onPartial: mergeFavoritedRefs,
					});
					if (cancelled) return;
				} catch {
					// 失败回滚：仅实例级 queriedKeys（经典句库无会话级 queried）
					if (!cancelled) {
						for (const english of englishesToQuery) {
							const ck = classicQuoteFavoriteContentKey(english);
							if (ck) queriedKeysRef.current.delete(ck);
						}
					}
				}
			})();
		}, STATUS_QUERY_DEBOUNCE_MS);

		// cleanup（同旧版）
		return () => {
			cancelled = true;
			clearTimeout(timer);
		};
		// effect 依赖新增 libraryId
	}, [itemsEnglishSig, items, libraryId]);

	// get（同旧版）
	const getClassicQuoteFavoriteId = (contentKey: string) =>
		favoriteIdByContentKey.get(contentKey);

	// set（同旧版：只写 state，无会话缓存）
	const setClassicQuoteFavoriteId = (contentKey: string, id: string) => {
		setFavoriteIdByContentKey((prev) => {
			const next = new Map(prev);
			next.set(contentKey, id);
			return next;
		});
	};

	// clear（同旧版：只清 state）
	const clearClassicQuoteFavorite = (contentKey: string) => {
		setFavoriteIdByContentKey((prev) => {
			if (!prev.has(contentKey)) return prev;
			const next = new Map(prev);
			next.delete(contentKey);
			return next;
		});
	};

	// 返回同构（无破坏性）
	return {
		favoritedContentKeys,
		getClassicQuoteFavoriteId,
		setClassicQuoteFavoriteId,
		clearClassicQuoteFavorite,
	};
}
```

**变更摘要**：
- 整体结构与单词库完全对称（双模式分支、并发 GET、sessionLibraryClassicStatusEnd）。
- 故意不做经典句级会话 key 缓存（contentKey 由整句归一化，体积大、命中低）；仅保留「按库 offset 末尾」的会话级去重。
- set / clear 仅写 state（不写 session）：经典句收藏交互频次低于单词，收益有限。

## 5. 兼容性与影响

| 项 | 说明 |
| --- | --- |
| 破坏性 | 无。Hook 返回对象完全同构；**未传 `options.libraryId` 的调用方**仍走旧版 POST 分支，行为不变 |
| 新增依赖 | `libraryWordsListPrefetch.ts` 的 `buildLibraryRangeChunks` / `mapWithConcurrency`；只有传了 libraryId 才会执行到这些函数 |
| 后端接口兼容 | 新路由是独立的 GET，不影响原有 POST `/vocabulary-favorites/status` |
| limit 上限 1000 | 前端常量 `VOCAB_LIBRARY_ITEMS_PAGE_SIZE` 仍为 100（`constants/index.ts`），默认分页 100 条；1000 是上限，仅大续读窗口的预取并发才会接近 |
| 会话缓存泄漏 | 会话缓存在模块级 Map/Set，**不跨页面刷新**（刷新即清空）。同一页面长时间浏览、切多个库时，Map 会累计，但 key 体积可控（单词数通常 ≤10 万）；切账号时会清 `resetUserState`（此处未加清库级缓存，如有需要后续可扩展） |
| 失败回滚 | 资源库模式 GET 失败时回滚组件级 `libraryStatusEndRef` 到 fetchFrom，下次重试；POST 模式回滚实例级 + 会话级 queried |
