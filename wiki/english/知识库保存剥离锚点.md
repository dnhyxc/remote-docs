# 知识库保存剥离锚点

> 延伸阅读：
> - [Agent大结果旁路展示.md](./Agent大结果旁路展示.md)：`[[el:…]]` 清单卡锚点的产生与前端挂载机制。
> - [英语Agent侧栏融合.md](./英语Agent侧栏融合.md)：Agent 面板「保存到知识库」入口的上下文。

## 1. 背景与目标

Agent 消息正文里的 `[[el:…]]` 是**清单卡锚点**：只给前端 `cardEdges` 交错渲染时挂 `ResourceListBlock` 用，本身不是给用户看的文本。点「保存到知识库」时旧版直接把 `message.content` 原样塞进知识库编辑器——锚点记号原封不动进了笔记正文，既不可读也删不干净。

目标：保存到知识库前**剥离全部 `[[el:…]]` 锚点**，并把剥离后留下的连续空行压成标准段落间距。

## 2. 改动范围

| 路径 | 改动 |
|------|------|
| `apps/frontend/src/views/englishLearning/agent/index.tsx` | `onSaveToKnowledge` 取正文时先剥锚点、再压空行、后 trim |

## 3. 实现思路

单文件、单函数改动，无跨模块数据流，略图。

1. **锚点正则一把剥**：`/\[\[el:[^\]]+\]\]/g` 精确匹配 `[[el:` 前缀到 `]]` 后缀的整段记号，全局替换为空串——锚点没有嵌套结构，`[^\]]+` 不会越界。
2. **空行压缩兜底**：锚点独占一行时，剥掉后会留下连续空行；`\n{3,} → \n\n` 把 3 个及以上换行压成两个（一个空行），保持知识库段落间距一致。
3. **先剥再 trim**：顺序不可反——先 trim 会把锚点行首尾空白吃掉，影响后续空行压缩的判定。

来源：`apps/frontend/src/views/englishLearning/agent/index.tsx`（**改动后**，约 L611–L618）

```ts
			// 保存到知识库的回调：入参是要保存的那条消息
			const onSaveToKnowledge = useCallback(
				// 消息本体
				(message: Message) => {
					// 清单卡锚点只给前端挂 ResourceListBlock，进知识库编辑器无意义
					const body = (message.content ?? '')
						// 剥掉全部 [[el:…]] 锚点：g 全局、[^\]]+ 不越过 ]]
						.replace(/\[\[el:[^\]]+\]\]/g, '')
						// 锚点独占行留下的 3+ 连续换行压成一个空行
						.replace(/\n{3,}/g, '\n\n')
						// 最后收尾去首尾空白：顺序在剥离之后，保证空行压缩判定准确
						.trim();
```

变更摘要：取正文从一步 `trim()` 变为「剥锚点 → 压空行 → trim」三步；空内容仍走原有 `Toast` 警告分支（未改动）。

## 5. 行为变化与兼容性

- **行为修正**（预期变化）：保存到知识库的 Agent 回答不再含 `[[el:…]]` 记号；清单卡位置变成一个空行间隔。
- **不变**：对话面板内的锚点渲染机制（`cardEdges` / `ResourceListBlock`）不受影响——剥离只发生在保存动作，消息本体 `message.content` 未被改写。

## 6. 测试与回归建议

1. 含清单卡的 Agent 回答点「保存到知识库」→ 编辑器正文无 `[[el:…]]`，卡片位置无大段空白。
2. 纯文本回答保存 → 与旧版完全一致。
3. 多条锚点的长回答保存 → 全部剥净，段落间距正常。
