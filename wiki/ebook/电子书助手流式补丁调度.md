# 电子书助手流式 MobX Patch 调度

> **文档角色**：本轮 diff 的**主实现文档**（写路径 + 改动前后对比 + 逐行注释）。
> **延伸阅读**：[知识预览助手性能.md](../knowledge/知识预览助手性能.md)（知识库助手同模式落地，含 rAF 调度器设计背景）、[英语Agent流式性能隔离.md](../english/英语Agent流式性能隔离.md)（英语助手同模式应用）。

---

## 1. 背景与目标

### 1.1 用户可见问题

电子书助手（MOKE）在**流式输出**时，SSE 每个 token 触发一次同步 `runInAction`，以**数组元素替换**（`st.messages[idx] = { ...prev, content: accumulated }`）的方式写入 MobX state。这导致：

1. **频繁 MobX observer 通知**：每个 token（约 20–50 tokens/秒）触发一次通知，远超屏幕刷新率
2. **数组级 observer 触发**：`messages` 数组元素替换会触发订阅了整个数组的 observer，而非仅订阅 `content` 属性
3. **不必要的重渲染**：对象展开（`{ ...prev, content }`）产生新引用，所有 observer 都会重渲染
4. **UI 卡顿**：消息列表及周围 UI（如章节导航、批注面板）出现可感知的延迟

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 写路径降频 | SSE 增量合并为**每帧最多一次** MobX 写入（rAF 合并） |
| 写入粒度缩小 | 就地变更 `content` 属性，不替换数组元素，仅触发属性级 observer |
| 空写入防护 | `prev.content === accumulated` 时跳过，避免无意义通知 |
| 尾数据保障 | 所有终止路径（onComplete / onError / catch）调用 `flush()` 刷入最终内容 |
| 行为不变 | 发送/停止、会话隔离、错误处理、UI 状态流转等与改前一致 |

## 2. 根因分析

旧版 `patchAssistant` 在每个 SSE token 到达时立即执行：

```typescript
runInAction(() => {
    const idx = st.messages.findIndex((m) => m.chatId === assistantRowId);
    if (idx < 0) return;
    const prev = st.messages[idx] as Message;
    st.messages[idx] = { ...prev, content: accumulated };
});
```

存在三个核心问题：

| # | 问题 | 影响 |
|---|------|------|
| 1 | **频率过高**：每 token 一次 `runInAction`，SSE 约 20–50 tokens/秒 → 20–50 次 MobX 通知/秒 | 主线程被频繁占用，observer 重渲染排队 |
| 2 | **粒度过粗**：`st.messages[idx] = newObj` 替换数组元素 → 触发 `messages` 数组级 observer（订阅整个数组的组件都会重渲染） | 所有依赖 `messages` 的组件（不仅是消息列表）都被通知 |
| 3 | **引用变更**：`{ ...prev, content: accumulated }` 创建新对象引用 → 即使内容未变，React observer 也判定为数据变更 | 产生无意义的 diff 和重渲染 |

---

## 3. 方案总览

### 3.1 核心决策

采用**两阶段优化**方案：

| # | 阶段 | 机制 | 效果 |
|---|------|------|------|
| 1 | **rAF 合并调度** | `createStreamingMobxPatchScheduler` 将同一帧内多次 `schedule()` 合并为一次 `flush()` | 20–50 tokens/秒 → ~1 flush/帧（60fps ≈ 16ms） |
| 2 | **就地属性变更** | `prev.content = accumulated` 替代数组元素替换 | 仅触发 `content` 属性级 observer，不触发 `messages` 数组级 observer |

**设计要点**：

- `schedule()`：同一帧内多次调用合并为一次 flush（`dirty` 标记防重入）
- `flush()`：立即刷入并取消待执行 rAF，保证终止时数据完整
- `cancel()`：丢弃待 flush，用于主动取消场景
- **终止点保障**：在 `onComplete`、`onError`、`catch` 三个路径均调用 `flush()`，确保最后一批 accumulated 内容写入后再更新 `isStreaming` 等状态

## 4. 关键代码对比与注释

### 4.1 `createStreamingMobxPatchScheduler`（scheduleStreamingMobxPatch.ts）

**对比范围**：完整模块（工具库，电子书助手直接复用，无改动）。

**源码** · `apps/frontend/src/utils/scheduleStreamingMobxPatch.ts`（当前，约 L1–L39）

```typescript
// 模块级注释：说明本工具用于将流式 SSE 增量写入合并为每帧最多一次 MobX 写入
// 避免每个 token 触发整页 observer 重渲染
/** 流式 SSE 增量合并为每帧最多一次 MobX 写入，避免每 token 触发整页 observer */
// 导出调度器实例的类型形状，供 store 侧显式声明
export type StreamingMobxPatchScheduler = {
    // schedule：登记一次待 flush，同一帧内多次调用合并为一次
    schedule: () => void;
    // flush：立即执行 flush 并取消待执行的 rAF，用于流结束时保证数据完整
    /** 立即刷入并取消待执行的 rAF */
    flush: () => void;
    // cancel：丢弃待 flush 的内容，不写入 MobX
    cancel: () => void;
};

// 工厂函数：接收 flush 回调（实际写入 MobX 的逻辑），返回调度器实例
export function createStreamingMobxPatchScheduler(
    // flush: 外部传入的实际写入函数，通常是 runInAction 包裹的状态更新
    flush: () => void,
): StreamingMobxPatchScheduler {
    // 当前挂起的 requestAnimationFrame id，0 表示无待执行帧
    let rafId = 0;
    // 本帧是否已有待执行的 flush，用于合并同帧多次 schedule
    let dirty = false;

    // rAF 回调：在浏览器下一个渲染帧执行
    const runFlush = () => {
        // 清 dirty 标记，表示本次 flush 已消费
        dirty = false;
        // 清 rafId，表示当前无挂起的 rAF
        rafId = 0;
        // 调用外部传入的实际写入函数
        flush();
    };

    // 返回调度器的对外 API 对象
    return {
        // schedule：登记一次待 flush
        schedule: () => {
            // 若本帧已有待执行的 flush，直接返回（合并同帧多次调用）
            if (dirty) return;
            // 标记本帧有 dirty 数据
            dirty = true;
            // 注册 rAF，在下一个渲染帧执行 runFlush
            rafId = requestAnimationFrame(runFlush);
        },
        // flush：立即刷入（用于流终止场景，保证最终数据写入）
        flush: () => {
            // 若有挂起的 rAF，先取消，避免 flush 后 rAF 又执行一次
            if (rafId) cancelAnimationFrame(rafId);
            // 清 dirty 标记
            dirty = false;
            // 清 rafId
            rafId = 0;
            // 立即执行外部 flush 回调
            flush();
        },
        // cancel：丢弃待 flush 的内容，不写入（用于主动取消场景）
        cancel: () => {
            // 若有挂起的 rAF，取消它
            if (rafId) cancelAnimationFrame(rafId);
            // 清 dirty 标记
            dirty = false;
            // 清 rafId
            rafId = 0;
        },
    };
}
```

**变更摘要**：本模块为知识库助手先行落地的通用工具（参见 `知识预览助手性能.md`），电子书助手直接引入复用，无修改。

### 4.2 `flushAssistantPatch` 与 `patchAssistant`（ebookAssistant.ts）

**对比范围**：`sendMessage` 方法内 SSE patch 写入路径的改造。

**改动前** · `apps/frontend/src/store/ebookAssistant.ts`（基线 `sendMessage` 内，约 L549–L564）

```typescript
// 旧版：每个 SSE delta 直接 runInAction 写 messages[idx]
// 数组元素替换 + 对象展开，触发数组级 observer + 新引用
const patchAssistant = (delta: string) => {
    // 累加 delta 到闭包变量 accumulated
    if (delta) accumulated += delta;
    // 每个 token 立即触发同步 MobX 写入
    runInAction(() => {
        // 查找助手消息在 messages 数组中的索引
        const idx = st.messages.findIndex((m) => m.chatId === assistantRowId);
        // 若未找到（如被外部删除），直接返回
        if (idx < 0) return;
        // 取出旧消息对象
        const prev = st.messages[idx] as Message;
        // 用对象展开创建新对象替换数组元素
        // 触发数组级 observer + 新引用导致所有 observer 重渲染
        st.messages[idx] = { ...prev, content: accumulated };
    });
};
```

**改动后** · `apps/frontend/src/store/ebookAssistant.ts`（当前，约 L549–L564）

```typescript
// 新版：将写入逻辑抽取为独立函数，供 scheduler 每帧调用一次
const flushAssistantPatch = () => {
    // runInAction 包裹，保证 MobX 事务性
    runInAction(() => {
        // 查找助手消息在 messages 数组中的索引
        const idx = st.messages.findIndex((m) => m.chatId === assistantRowId);
        // 若未找到（如被外部删除），直接返回
        if (idx < 0) return;
        // 取出旧消息对象（就地变更，不替换数组元素）
        const prev = st.messages[idx] as Message;
        // 空写入防护：若内容未变化，跳过写入
        if (prev.content === accumulated) return;
        // 就地修改 content 属性，仅触发属性级 observer
        // 不替换数组元素，不触发数组级 observer
        prev.content = accumulated;
    });
};
// 创建 rAF 调度器，合并多次 patch 为每帧一次写入
const assistantPatchScheduler =
    createStreamingMobxPatchScheduler(flushAssistantPatch);

// SSE 回调：只累加内存，schedule 合并写入
const patchAssistant = (delta: string) => {
    // 累加 delta 到闭包变量 accumulated
    if (delta) accumulated += delta;
    // 调度写入：同一帧内多次调用合并为一次 flush
    assistantPatchScheduler.schedule();
};
```

**变更摘要**：

| # | 改前 | 改后 | 收益 |
|---|------|------|------|
| 1 | 每 token 一次 `runInAction` | 每帧最多一次 `runInAction` | 写入频率从 20–50/秒降至 ~1/帧 |
| 2 | 数组元素替换 `st.messages[idx] = { ...prev, content }` | 就地属性变更 `prev.content = accumulated` | 仅触发属性级 observer |
| 3 | 无空写入防护 | `if (prev.content === accumulated) return` | 避免无意义通知 |

### 4.3 流式终止点 flush 调用（ebookAssistant.ts）

**对比范围**：`onComplete`、`onError`、`catch` 三个终止路径。

#### onComplete 路径

**改动前** · `apps/frontend/src/store/ebookAssistant.ts`（基线，约 L604–L630）

```typescript
// 旧版 onComplete：直接更新 isStreaming 等状态
onComplete: (err) => {
    // 未调用 flush，可能丢失最后一批 accumulated 内容
    runInAction(() => {
        // 设置 isSending 为 false
        st.isSending = false;
        // 查找助手消息索引
        const idx = st.messages.findIndex(
            (m) => m.chatId === assistantRowId,
        );
        // 若找到且仍在流式中
        if (idx >= 0) {
            const prev = st.messages[idx] as Message;
            if (prev.isStreaming) {
                // 替换数组元素，设置 isStreaming: false
                st.messages[idx] = {
                    ...prev,
                    isStreaming: false,
                };
            }
        }
        // 清 abort 句柄
        st.abortStream = null;
        // 清 streamingSessionId
        if (this.streamingSessionId === sid) {
            this.streamingSessionId = null;
        }
    });
    // 刷新会话列表
    void this.refreshSessionListForCurrentBook();
},
```

**改动后** · `apps/frontend/src/store/ebookAssistant.ts`（当前，约 L604–L631）

```typescript
// 新版 onComplete：先 flush 调度器，再更新状态
onComplete: (err) => {
    // 关键：先刷入调度器中积压的最终 delta，确保内容完整
    assistantPatchScheduler.flush();
    // 再更新流式状态
    runInAction(() => {
        // 设置 isSending 为 false
        st.isSending = false;
        // 查找助手消息索引
        const idx = st.messages.findIndex(
            (m) => m.chatId === assistantRowId,
        );
        // 若找到且仍在流式中
        if (idx >= 0) {
            const prev = st.messages[idx] as Message;
            if (prev.isStreaming) {
                // 替换数组元素，设置 isStreaming: false
                // （此处仍用展开，因需修改多个属性：isStreaming + 可选 content）
                st.messages[idx] = {
                    ...prev,
                    isStreaming: false,
                    ...(err &&
                    err !== AGENT_SSE_USER_ABORT_MARKER &&
                    !prev.content
                        ? { content: `生成失败：${err}` }
                        : {}),
                };
            }
        }
        // 清 abort 句柄
        st.abortStream = null;
        // 清 streamingSessionId
        if (this.streamingSessionId === sid) {
            this.streamingSessionId = null;
        }
    });
    // 刷新会话列表
    void this.refreshSessionListForCurrentBook();
},
```

**变更摘要**：新增 `assistantPatchScheduler.flush()`，确保最后一批 accumulated 内容在 `isStreaming: false` 之前写入。

| # | 影响面 | 说明 |
|---|--------|------|
| 1 | **功能行为** | 流式输出效果与改前完全一致；用户看到的打字机体验不变 |
