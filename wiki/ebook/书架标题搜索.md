# 书架按书名搜索

> 延伸阅读：本轮同步还调整了书架排序与分页——排序逻辑与 [电子书书架排序最近阅读.md](./电子书书架排序最近阅读.md) 同源（最近阅读优先），本篇在排序平局打破上做了微调（公开书降级为次序键）。

## 1. 背景与目标

电子书书架原先只支持按分类浏览，**无法按书名快速定位**：当书籍数量变多后，用户想找一本特定书只能在卡片网格里肉眼扫，体验较差。本次新增**按书名关键字搜索**能力：

- 点击书架顶栏的「搜索书籍」按钮，**展开**一个搜索输入框；输入书名关键字后按 Enter 提交，书架列表过滤为匹配结果。
- 点击「关闭搜索」时，**自动清除关键字并恢复完整列表**。
- 搜索**不区分大小写**（`LOWER LIKE`），与知识库搜索保持一致；搜索期间**公开书架也会同步过滤**。

同一轮还顺带做了两项体验微调：

- **排序**：从「公开书优先、组内最近阅读倒序」改回「**最近阅读优先**，同阅读时间时公开书靠前」。后端 `getShelf` 排序键从 `isPublic DESC → shelf_sort DESC` 调整为 `shelf_sort DESC → isPublic DESC`。
- **分页量**：`EBOOK_SHELF_PAGE_SIZE` 从 `50` 改为 `20`，减少首屏加载压力。

用户可感知：书架新增搜索入口；卡片默认顺序更贴近「最近在看的书」；首屏加载更轻。

## 3. 实现思路

1. **后端用 `LOWER(b.title) LIKE %q%` 做不区分大小写的模糊匹配**，与知识库搜索一致；抽出私有方法 `applyTitleFilter(qb, title?)`，`getShelf`（我的书架）与 `getPublicShelf`（公开书架）共用，避免两处重复 SQL 片段。空关键字直接 return，不影响无搜索时的原查询。
2. **搜索与分类/分页正交**：`title` 只追加一个 `andWhere`，与既有的 `categoryId` / `uncategorizedOnly` / `scope` / `skip-take` 互不干扰；`total` 由 `getManyAndCount` 一并返回，前端分页与「加载更多」照常工作。
3. **前端搜索状态收敛在 `EbookStore.titleKeyword`**：组件不自己持有关键字，而是读写 store。这样切分类、加载更多、关闭搜索时都由 store 统一调度 `fetchPage`，关键字作为查询参数下发给两次 `loadEbookShelf`（我的 + 公开）。
4. **`refreshList(keyword?)` 作为搜索入口**：写入 `titleKeyword` 后回到第 1 页重新拉取。关闭搜索时传 `''` 清空关键字并刷新，恢复完整列表。
5. **`hasMore` 在搜索期间走 `safeTotal()` 兜底**：搜索时 `total` 反映的是过滤后的命中数（而非分类计数），用 `books.length < safeTotal()` 判断是否还有下一页，避免「全部」Tab 用 `totalBookCount + publicBookTotal` 这套未过滤计数导致误判。
6. **排序调整**：前端 `sortBooksByLastRead` 改为先比最近阅读时间，**仅当阅读时间相同时**才用「是否公开」做平局打破；后端 `getShelf` 排序同步改为 `shelf_sort DESC → isPublic DESC`，前后端语义一致。
7. **分页量 50 → 20**：搜索后命中数通常不多，更小的页量能让首屏更快返回；同时降低普通浏览时的首屏负担。
8. **UI 形态**：搜索按钮与输入框做成一个可收展的复合控件——收起时只显示按钮，展开时用 CSS grid `0fr → 1fr` 过渡把输入框宽度从 0 拉到 `w-52`，避免布局跳动。

**为何不在前端做本地过滤**：书架是分页加载的，本地只持有当前页数据，本地过滤会漏掉后续页的匹配项；交给后端按 `title` 过滤分页才能保证结果完整与 `total` 准确。

### 4.3 `EbookService.applyTitleFilter` — 标题过滤私有方法（纯新增）

**对比范围**：新增的私有方法完整定义。属于纯新增，无改动前版本。

**改动后** · `apps/backend/src/services/ebook/ebook.service.ts`（当前，约 L543–L552）

```typescript
// 私有方法：给书架查询追加按书名模糊过滤条件
private applyTitleFilter(
	// 已构造好的书籍 QueryBuilder（别名 b）
	qb: SelectQueryBuilder<EbookBook>,
	// 可选的标题关键字（来自 DTO title）
	title?: string,
// 无返回值，原地给 qb 追加 andWhere
): void {
	// 去除首尾空白，得到实际用于匹配的查询串
	const q = title?.trim();
	// 空关键字直接返回，不追加任何条件（保持无搜索时的原查询）
	if (!q) return;
	// 追加不区分大小写的 LIKE：LOWER(b.title) LIKE '%q%'
	qb.andWhere('LOWER(b.title) LIKE :title', {
		// 参数化绑定：% 包裹小写后的关键字，防 SQL 注入
		title: `%${q.toLowerCase()}%`,
	// 结束 andWhere 的参数对象并闭合调用
	});
// 结束 applyTitleFilter 方法
}
```

**变更摘要**：纯新增。集中标题过滤 SQL，供 `getShelf` / `getPublicShelf` 复用。`SelectQueryBuilder` 已在文件顶部从 `typeorm` 导入，无需新增 import。

### 4.8 `sortBooksByLastRead` — 排序逻辑调整

**对比范围**：模块级工具函数 `sortBooksByLastRead` 完整定义。

**改动前** · `apps/frontend/src/store/ebook.ts`（基线，约 L112–L124）

```typescript
// 旧版注释：公开书（含他人公开）优先，组内再按最近阅读倒序
function sortBooksByLastRead(
	// 待排序的书数组
	books: Book[],
	// 阅读进度映射
	progMap: Record<string, Prog>,
// 返回排序后的新数组
): Book[] {
	// 展开新数组再 sort，避免直接 mutate MobX observable
	return [...books].sort((a, b) => {
		// 计算 a 是否为公开书（本人公开或他人公开）
		const aPublic = a.isPublic || a.owner ? 1 : 0;
		// 计算 b 是否为公开书
		const bPublic = b.isPublic || b.owner ? 1 : 0;
		// 公开优先：公开书排前
		if (aPublic !== bPublic) return bPublic - aPublic;
		// 组内再按最近阅读时间倒序

	});
```

```typescript
function sortBooksByLastRead(
	// 待排序的书数组
	books: Book[],
	// 阅读进度映射
	progMap: Record<string, Prog>,
// 返回排序后的新数组
): Book[] {
	// 展开新数组再 sort，避免直接 mutate MobX observable
	return [...books].sort((a, b) => {
		// 主序：最近阅读时间倒序（b - a）
		const byRead = bookLastReadMs(b, progMap) - bookLastReadMs(a, progMap);
		// 阅读时间不同则直接定序
		if (byRead !== 0) return byRead;
		// 同阅读时间时计算 a 是否公开
		const aPublic = a.isPublic || a.owner ? 1 : 0;
		// 同阅读时间时计算 b 是否公开
		const bPublic = b.isPublic || b.owner ? 1 : 0;
		// 公开作为平局打破者：公开书靠前
		return bPublic - aPublic;
	// 结束 sort 比较函数
	});

}
```

## 5. 兼容性与影响

- **兼容**：无数据库迁移、无新接口端点。`title` 为可选 query 参数，旧客户端不传时 `applyTitleFilter` 直接 return，行为与改动前完全一致。
- **搜索大小写**：`LOWER(b.title) LIKE LOWER(q)`，与知识库搜索一致；不影响已有索引利用率（`title` 列原本就无专门大小写索引，书架规模下可接受）。
- **搜索范围**：搜索时公开书架（`scope=public`）也会同步过滤；「全部」Tab 的 `publicData` 拉取同样携带 `title`。
- **分页边界**：搜索期间 `hasMore` 改用 `safeTotal()` 判断（`total` 已是过滤后命中数），不再用未过滤的 `totalBookCount + publicBookTotal`，避免「加载更多」误判。
- **关闭搜索**：`closeSearch` 传 `''` 清空 `titleKeyword` 并 `refreshList`，自动恢复完整列表。
- **排序变化**：从「公开优先」改回「最近阅读优先」（公开仅作同阅读时间平局打破者）；后端 `getShelf` 排序同步从 `isPublic DESC → shelf_sort DESC` 改为 `shelf_sort DESC → isPublic DESC`，前后端语义一致。
- **分页量变化**：`EBOOK_SHELF_PAGE_SIZE` 50 → 20，首屏加载更轻；已加载用户不受影响（store 实例随帐号重置）。
- **`SelectQueryBuilder` import**：`ebook.service.ts` 顶部已从 `typeorm` 导入 `SelectQueryBuilder`（`getShelf` 等既有方法本就在用），本次无需新增 import。
- **切换用户**：`resetOnUserSwitch` 已重置 `titleKeyword`，搜索态不会跨帐号泄漏。

建议回归测试：搜索命中/无命中空状态；搜索下「加载更多」是否仍正确；关闭搜索恢复完整列表；搜索 + 切分类；最近阅读排序（读过 A→A 置顶）；公开书与我的书混合排序。
