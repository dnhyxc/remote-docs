# 书架「全部」标签统一分页

## 1. 背景与目标

电子书书架的「全部」标签原先由前端发起两次请求：一次拉自己的源书（`scope=mine`），一次拉他人公开源书（`scope=public`，固定 `pageSize=100`），随后在内存中按最近阅读时间合并、去重、排序。该方案存在三个问题：

1. **分页总数不准**：`total` 是 `mineTotal + publicBookTotal` 的拼凑值，与真实混排后的分页条数不一致，导致「加载更多」可能提前结束或重复拉取。
2. **网络开销翻倍**：首屏「全部」需要并发两个分页请求，且公开书固定拉 100 条，超出首屏所需。
3. **前端逻辑臃肿**：Store 需要维护 `publicBookTotal`、双轨 `progMap` 合并、`mineIds` 去重、`sortBooksByLastRead` 重排，分支繁杂、难以维护。

本次改动将「全部」标签改为后端 `scope=all` 统一混排分页：后端用一条 SQL JOIN 查询将自有源书与他人公开源书按最近阅读时间混排，直接返回单页结果与准确 `total`；前端 Store 大幅简化——不再单独请求公开书、不再前端合并、不再用 `publicBookTotal` 参与 `hasMore` 判断，直接消费后端返回的单页数据。

## 2. 改动范围（路径清单）

- `apps/backend/src/services/ebook/ebook.service.ts`
  - `getShelf`：新增 `scope === 'all'` 路由分支。
  - 新增私有方法 `getAllShelf`：自有源书 + 他人公开源书按最近阅读混排分页。
- `apps/frontend/src/store/ebook.ts`
  - `shelfQueryFromKey`：返回类型新增 `'all'`，默认返回 `{ scope: 'all' }`。
  - `hasMore` getter：简化为统一 `safeTotal()` 判断。
  - `hydrate`：始终并行 `fetchPublicCount`，不再区分 `kind === 'all'` 跳过。
  - `fetchPage`：移除公开书二次请求与前端合并/重排，直接使用后端单页数据。

## 3. 实现思路

### 后端：单 SQL 混排分页

1. **校验**：`scope=all` 不支持 `categoryId` / `uncategorizedOnly`（「全部」本身就是跨分类混排）。
2. **总数计算**：单独用 `countQb` 查 `source_book_id IS NULL` 且（属于我 或 公开且不属于我）的源书数量，保证 `total` 与混排结果一致。
3. **排序表达式**：优先用进度表 `p.updated_at`（最近阅读时间）；自有书回退 `b.created_at`；他人公开书回退 `COALESCE(b.public_at, b.created_at)`（公开时间优先，使刚公开的书靠前）。
4. **JOIN 构造**：
   - `LEFT JOIN EbookBook 'reading'`：我对他人公开书的「读书记录副本」，用于取该副本的进度。
   - `LEFT JOIN EbookProgress 'p'`：进度表，自有书关联 `p.book_id = b.id`，他人公开书关联 `p.book_id = reading.id`（我的副本进度）。
5. **两步查询**：
   - 先用 `idQb`（`groupBy b.id` + `orderBy shelf_sort DESC`）查出分页后的有序 id 列表，避免 `getManyAndCount` 在 JOIN + MAX 下返回不完整实体。
   - 再用 `find` + `Map` 恢复完整 book 实体，按 id 顺序重排，保持分页顺序。
6. **DTO 组装**：自有书走 `toBookDto` + 进度；他人公开书走 `toBookDtoWithOwner` + 查找我的阅读副本 `readingBySource` + 进度。

### 前端：Store 极简化

1. `shelfQueryFromKey` 默认返回 `scope: 'all'`，使「全部」标签直接命中后端新接口。
2. `hasMore` 统一用 `safeTotal()`，因为后端 `total` 已是准确的混排总数。
3. `hydrate` 始终并行 `fetchPublicCount`（仅维护角标 `publicBookTotal`，不再参与分页判断）。
4. `fetchPage` 删除公开书二次请求、双轨 `progMap` 合并、`mineIds` 去重、`sortBooksByLastRead` 重排；追加加载时直接 `merged`（服务端已分页排序，整表重排会打乱分页）；首页加载完成后异步 `fetchPublicCount()` 刷新角标。

**改动后** · `apps/backend/src/services/ebook/ebook.service.ts`（当前，约 L546–L698）

```typescript
// 方法文档注释：说明「全部」= 自有源书 + 他人公开源书，按最近阅读混排分页
/**
 * 「全部」：自有源书 + 他人公开源书，按最近阅读混排分页。
 * 自有：进度表 / created_at；他人公开：我对该源书的读书记录进度 / public_at / created_at。
 */
// 私有异步方法，接收当前用户 id 与书架查询参数，返回分页 DTO
private async getAllShelf(
	// 当前登录用户 id，用于区分自有书与他人公开书
	userId: number,
	// 书架查询参数（pageNo / pageSize / scope / title 等）
	query: QueryEbookShelfDto,
	// 返回类型：包含 books、progMap、total、pageNo、pageSize 的分页结果
): Promise<EbookShelfPageDto> {
	// 校验：scope=all 不允许带分类或未分类过滤（「全部」本身就是跨分类）
	if (query.categoryId || query.uncategorizedOnly) {
		// 抛出 400 错误，提示 scope=all 不支持这两个参数
		throw new BadRequestException(
			'scope=all 不支持 categoryId / uncategorizedOnly',
		);
	}

	// 解析页码，缺省从第 1 页开始
	const pageNo = query.pageNo ?? 1;
	// 解析每页条数，缺省 20
	const pageSize = query.pageSize ?? 20;
	// TypeORM 取条数等于 pageSize
	const take = pageSize;
	// 计算跳过的条数（偏移量）
	const skip = (pageNo - 1) * take;

	// 构造总数查询构造器，别名 b 代表 ebook_book 表
	const countQb = this.bookRepo
		.createQueryBuilder('b')
		// 只统计源书（source_book_id 为空），排除他人的读书记录副本
		.where('b.source_book_id IS NULL')
		// 用括号分组 OR 条件，保证 AND/OR 优先级正确
		.andWhere(
			new Brackets((w) => {
				// 条件一：源书属于当前用户（我的源书）
				w.where('b.user_id = :userId', { userId }).orWhere(
					// 条件二：源书是公开的且不属于当前用户（他人公开源书）
					'(b.is_public = true AND b.user_id <> :userId)',
					{ userId },
				);
			}),
		);
	// 复用标题过滤：若 query.title 存在则追加 LIKE 模糊查询
	this.applyTitleFilter(countQb, query.title);
	// 执行 count 查询，得到混排后的准确总数
	const total = await countQb.getCount();

	// 定义排序表达式（SQL CASE）：决定每本书的「最近阅读/创建时间」排序键
	// 由于下方是多行模板字符串，无法在字符串内部插入 // 注释，故将各分支含义在此说明：
	// 第一分支 WHEN p.updated_at IS NOT NULL：进度表有 updated_at（我读过这本书），优先用它作为最近阅读时间
	// 第二分支 WHEN b.user_id = :userId：否则若源书是我的，回退到源书创建时间
	// 第三分支 ELSE COALESCE(b.public_at, b.created_at)：否则是他人公开书，回退到公开时间（没有则用创建时间）
	const sortExpr = `CASE
		WHEN p.updated_at IS NOT NULL THEN p.updated_at
		WHEN b.user_id = :userId THEN b.created_at
		ELSE COALESCE(b.public_at, b.created_at)
	END`;

	// 构造分页 id 查询构造器，别名 b 代表源书表
	const idQb = this.bookRepo
		.createQueryBuilder('b')
		// LEFT JOIN EbookBook 别名 reading：我对他人公开书的读书记录副本
		// 关联条件：reading.source_book_id = b.id 且 reading 属于当前用户
		.leftJoin(
			EbookBook,
			'reading',
			'reading.source_book_id = b.id AND reading.user_id = :userId',
			{ userId },
		)
		// LEFT JOIN EbookProgress 别名 p：进度表
		// 关联条件：p 属于当前用户；自有书关联 p.book_id = b.id；他人公开书关联 p.book_id = reading.id（我的副本进度）
		.leftJoin(
			EbookProgress,
			'p',
			`p.user_id = :userId AND (
				(b.user_id = :userId AND p.book_id = b.id) OR
				(b.user_id <> :userId AND p.book_id = reading.id)
			)`,
			{ userId },
		)
		// 只选出源书 id 作为结果列
		.select('b.id', 'id')
		// 额外选出排序键的最大值（同一源书可能 JOIN 出多行进度，取 MAX）
		.addSelect(`MAX(${sortExpr})`, 'shelf_sort')
		// 过滤：只取源书
		.where('b.source_book_id IS NULL')
		// 与 countQb 相同的归属过滤：我的源书 或 他人公开源书
		.andWhere(
			new Brackets((w) => {
				// 条件一：源书属于当前用户
				w.where('b.user_id = :userId', { userId }).orWhere(
					// 条件二：源书公开且不属于当前用户
					'(b.is_public = true AND b.user_id <> :userId)',
					{ userId },
				);
			}),
		);
	// 复用标题过滤，保证 id 分页与 count 口径一致
	this.applyTitleFilter(idQb, query.title);
	// 执行 id 查询：按源书 id 分组，避免 JOIN 多行导致重复
	const idRows = await idQb
		.groupBy('b.id')
		// 主排序：按最近阅读/创建时间倒序
		.orderBy('shelf_sort', 'DESC')
		// 次排序：自有书（is_public=false）排在公开书前面
		.addOrderBy('MAX(b.is_public)', 'DESC')
		// 末排序：同分时按创建时间倒序，保证稳定
		.addOrderBy('MAX(b.created_at)', 'DESC')
		// 设置偏移量（分页跳过）
		.offset(skip)
		// 设置每页条数
		.limit(take)
		// 以原始行形式获取结果（仅含 id 字段）
		.getRawMany<{ id: string }>();

	// 从原始行中提取 id 列表，过滤掉可能的空值
	const orderedIds = idRows.map((r) => r.id).filter(Boolean);
	// 空结果直接返回空分页，避免后续无意义查询
	if (orderedIds.length === 0) {
		return {
			// 空书籍列表
			books: [],
			// 空进度映射
			progMap: {},
			// 总数仍返回真实值（可能为 0）
			total,
			// 当前页码
			pageNo,
			// 每页条数
			pageSize,
		};
	}

	// 用拿到的有序 id 列表一次性查出完整 book 实体（避免 JOIN 导致实体不完整）
	const bookRows = await this.bookRepo.find({
		// 使用 In 操作符匹配 id 列表
		where: { id: In(orderedIds) },
	});
	// 构造 id -> book 的映射，便于按 id 顺序重排
	const bookById = new Map(bookRows.map((b) => [b.id, b]));
	// 按 orderedIds 的顺序从映射中取出 book，过滤掉可能的 null，保持分页顺序
	const books = orderedIds
		.map((id) => bookById.get(id))
		.filter((b): b is EbookBook => b != null);

	// 收集当前页中「我的源书」id 列表（直接用 b.id 查进度）
	const mineIds = books
		.filter((b) => b.userId === userId)
		.map((b) => b.id);
	// 收集当前页中「他人公开源书」id 列表（需先查我的阅读副本再查进度）
	const publicIds = books
		.filter((b) => b.userId !== userId)
		.map((b) => b.id);

	// 批量查询他人公开书的拥有者信息（用于 toBookDtoWithOwner 展示作者）
	const ownerMap = await this.buildUserInfoMap(
		books.filter((b) => b.userId !== userId).map((b) => b.userId),
	);

	// 查询我对当前页他人公开书的「阅读副本」记录（sourceBookId 命中公开源书 id）
	const readingRecords =
		publicIds.length === 0
			? []
			: await this.bookRepo.find({
					// 条件：属于当前用户，且 sourceBookId 在公开源书 id 列表中
					where: { userId, sourceBookId: In(publicIds) },
				});
	// 构造 sourceBookId -> reading 记录的映射，便于按公开源书 id 查我的副本
	const readingBySource = new Map(
		readingRecords.map((r) => [r.sourceBookId!, r]),
	);
	// 收集阅读副本的 id（用于查这些副本的进度）
	const readingIds = readingRecords.map((r) => r.id);
	// 合并需要查进度的 bookId：我的源书 id + 我的阅读副本 id
	const progBookIds = [...mineIds, ...readingIds];
	// 一次性查出当前页涉及的所有进度记录
	const progresses =
		progBookIds.length === 0
			? []
			: await this.progRepo.find({
					// 条件：属于当前用户，且 bookId 在合并列表中
					where: { userId, bookId: In(progBookIds) },
				});
	// 构造 bookId -> progress 的映射，便于按 bookId 取进度
	const progByBookId = new Map(progresses.map((p) => [p.bookId, p]));

	// 准备返回的进度映射（key 为源书 id）
	const progMap: Record<string, EbookProgDto> = {};
	// 准备返回的书籍 DTO 列表
	const shelfBooks: EbookBookDto[] = [];
	// 遍历当前页的源书，按归属分别组装 DTO 与进度
	for (const book of books) {
		// 分支一：源书属于当前用户（自有书）
		if (book.userId === userId) {
			// 直接转成普通 DTO（不含拥有者信息）
			shelfBooks.push(this.toBookDto(book));
			// 查我的源书进度
			const prog = progByBookId.get(book.id);
			// 有进度则写入 progMap（key 为源书 id）
			if (prog) progMap[book.id] = this.toProgDto(prog);
			// 处理完自有书，继续下一本
			continue;
		}
		// 分支二：他人公开源书，转成带拥有者信息的 DTO
		const dto = await this.toBookDtoWithOwner(book, ownerMap);
		// 查我对该公开源书的阅读副本记录
		const reading = readingBySource.get(book.id);
		// 若存在阅读副本
		if (reading) {
			// 在 DTO 上标记我的阅读副本 id（前端可用它跳转到我的副本）
			dto.readingBookId = reading.id;
			// 查该阅读副本的进度
			const prog = progByBookId.get(reading.id);
			// 有进度则写入 progMap（key 仍为公开源书 id，前端按源书 id 取进度）
			if (prog) progMap[book.id] = this.toProgDto(prog);
		}
		// 将他人公开书 DTO 加入返回列表
		shelfBooks.push(dto);
	}

	// 返回完整的分页结果
	return {
		// 当前页的书籍 DTO 列表（已按最近阅读混排）
		books: shelfBooks,
		// 进度映射（key 为源书 id）
		progMap,
		// 混排总数（准确，与分页结果一致）
		total,
		// 当前页码
		pageNo,
		// 每页条数
		pageSize,
	};
}
```

**变更摘要**：纯新增 `getAllShelf`，通过双 LEFT JOIN（阅读副本 + 进度表）与两步查询（先分页 id、再恢复实体），实现自有源书与他人公开源书的统一混排分页，并准确返回 `total`。

// 工具函数：把书架分类 key 转成后端查询参数对象
function shelfQueryFromKey(key: EbookShelfCategoryKey): {
	// scope 仅支持 mine / public 两种取值（「全部」靠空对象走默认 mine 分支）
	scope?: 'mine' | 'public';
	// 分类 id（按分类筛选时使用）
	categoryId?: string;
	// 是否仅看未分类
	uncategorizedOnly?: boolean;
} {
	// 显式公开 Tab：返回 scope=public
	if (key.kind === 'public') {
		return { scope: 'public' };
	}
	// 分类 Tab：返回对应的 categoryId
	if (key.kind === 'category') {
		return { categoryId: key.categoryId };
	}
	// 未分类 Tab：返回 uncategorizedOnly 标记
	if (key.kind === 'uncategorized') {
		return { uncategorizedOnly: true };
	}
	// 默认「全部」Tab：返回空对象，后端 scope 缺省走 mine 分支（旧逻辑：前端再补拉公开书）
	return {};
}

## 5. 兼容性与影响

- **网络开销**：「全部」标签从两个请求合并为一个后端请求，首屏请求数减半，且不再固定拉 100 条公开书。
- **分页正确性**：后端混排保证 `total` 与分页结果一致，修复了之前前端拼凑 `mineTotal + publicBookTotal` 导致的「加载更多」提前结束或重复拉取问题。
- **公开书进度**：现通过后端 JOIN 直接查询，不再需要前端单独请求公开书并合并进度。
- **追加加载排序**：不再前端重排（`sortBooksByLastRead`），避免整表重排打乱服务端已排序的分页顺序；去重时新增 `existingIds.add(book.id)` 标记。
- **`hydrate` 行为**：`fetchPublicCount` 始终并行执行，不再因 `kind === 'all'` 跳过；`publicBookTotal` 现仅用于「全部」Tab 角标显示（`shelfAllCount`），不再参与 `hasMore` 判断。
- **`scope=public` 与 `scope=mine` 保留**：原有 `getPublicShelf` 与「我的源书」分页逻辑未改动，`fetchPublicCount` 仍用 `scope=public` 拉数量。
- **`sortBooksByLastRead` 保留**：`fetchPage` 不再调用它，但 `setBookPublic` 等场景仍使用该函数做局部重排，未删除。
- **回归建议**：验证「全部」Tab 首屏与翻页顺序、搜索关键字下的「全部」分页、切换 Tab 后 `hasMore` 是否正确、公开书进度是否随阅读更新、`setBookPublic` 后列表重排与角标刷新。
