# 书架按最近阅读时间排序

> 延伸阅读：本轮同步还有一篇姊妹专题 [电子书书架卡片未分类.md](./电子书书架卡片未分类.md)（书架卡片未分类兜底文案），与本篇无强耦合。

## 1. 背景与目标

书架原先按 **书籍加入时间（`createdAt`）倒序** 展示：最近导入的书排在最前，**长期不变**。问题在于：

- 用户反复阅读的书，**不会因为「刚读过」而排到前面**，与直觉不符。
- 新导入但没读的书长期占顶，**真正在看的书**反而被挤到后面。

本次改动把书架排序键改为「**最近阅读时间**，没有阅读记录时回退到加入时间」：

- **后端**：`getShelf` 用 `QueryBuilder` 左联阅读进度表，按 `progress.updatedAt ?? book.createdAt` 倒序分页。
- **前端**：`EbookStore` 新增 `bookLastReadMs` / `sortBooksByLastRead` 工具，在分页加载、合并书架、新增书、保存进度四个时机对 `books` 重新排序，保证客户端状态与后端顺序一致。

用户可感知：书架卡片顺序会随阅读行为实时变化。

## 2. 改动范围

- `apps/backend/src/services/ebook/ebook.service.ts` — `getShelf` 方法改写排序逻辑
- `apps/frontend/src/store/ebook.ts` — 新增排序工具函数；`loadShelf` / `mergeBookIntoShelf` / `saveProg` 三处接入排序

## 3. 实现思路

1. **后端用 `CASE WHEN` 表达式作为排序键**：`EbookProgress` 是按 `(userId, bookId)` 维度的进度记录，`updatedAt` 即「最近一次阅读时间」。但**未读过的书没有进度记录**（`LEFT JOIN` 后 `p.updated_at IS NULL`），需要回退到 `b.created_at`。用 SQL `CASE WHEN p.updated_at IS NOT NULL THEN p.updated_at ELSE b.created_at END` 一次表达，避免应用层二次排序。
2. **前端为何再排一遍**：后端只保证**单页**顺序正确，但前端 `EbookStore` 在以下场景会让 `books` 脱离后端返回顺序，必须客户端兜底：
   - `mergeBookIntoShelf`（新增/更新书）：本地直接 `unshift`，不重新拉接口。
   - `saveProg`（保存进度）：进度变化后顺序应立即更新，否则用户看书后顺序不变。
   - `loadShelf` 的 `append` 与 `public` 合并分支：本地拼接后顺序会乱。
3. **排序键 `bookLastReadMs`**：前端 `Book` 模型里 `book.id` 是源书 id，但**实际阅读的是 `readingBookId`**（公开书的源书副本）。所以查进度时优先 `progMap[book.id]`，没有再查 `progMap[book.readingBookId]`，与后端 `b.id` 的 join 等价。
4. **稳定排序**：`[...books].sort(...)` 不要求稳定（同 key 顺序无所谓），因为后端分页已经保证了主序。
5. **不引入新字段**：复用现有 `prog.updatedAt` / `book.addedAt`，无数据库迁移、无新接口。

**为何不用「按阅读进度百分比排序」**：用户可能一本读到 90% 后搁置、一本刚开 5% 但天天读，按百分比会把 90% 那本顶在最前，与「最近在看的」直觉不符。

```typescript
// 分类校验仍保留：指定分类时先确认分类存在且属于该用户

// 新版：改用 QueryBuilder，便于 leftJoin 进度表并加自定义排序表达式
const qb = this.bookRepo

    // 左联 EbookProgress（别名为 p），关联条件：进度表的 book_id = 书 id 且进度属于当前用户
    .leftJoin(
        EbookProgress,
        'p',
        'p.book_id = b.id AND p.user_id = :userId',
        { userId },

    // select('b')：返回完整书籍实体
    .select('b')
    // addSelect：额外计算一个 shelf_sort 排序键，不返回给前端（仅用于 orderBy）
    .addSelect(
        // CASE WHEN：有进度记录用进度更新时间，否则回退到书加入时间
        'CASE WHEN p.updated_at IS NOT NULL THEN p.updated_at ELSE b.created_at END',
        'shelf_sort',
    )
    // 限定当前用户的书
    .where('b.user_id = :userId', { userId })
    // 只取源书（非公开书副本）
    .andWhere('b.source_book_id IS NULL');
if (query.categoryId) {
    // 指定分类：用参数化绑定，避免 SQL 注入
    qb.andWhere('b.category_id = :categoryId', {
        categoryId: query.categoryId,
    });
} else if (query.uncategorizedOnly) {
    // 只看未分类
    qb.andWhere('b.category_id IS NULL');
}
// 按计算出的 shelf_sort 倒序，再分页
qb.orderBy('shelf_sort', 'DESC').skip(skip).take(take);

// 新版：getManyAndCount 返回 [实体数组, 总数]
const [books, total] = await qb.getManyAndCount();
```

**变更摘要**：`findAndCount + order: createdAt DESC` → `QueryBuilder + leftJoin EbookProgress + CASE WHEN shelf_sort DESC`。排序键从「加入时间」改为「最近阅读时间（无记录回退加入时间）」。

### 4.2 `bookLastReadMs` / `sortBooksByLastRead` — 前端排序工具（纯新增）

**对比范围**：两个新增的模块级工具函数完整定义。属于纯新增，无改动前版本。

**改动后** · `apps/frontend/src/store/ebook.ts`（当前，约 L100–L119）

```typescript
// 计算单本书的「最近阅读时间」毫秒数，作为排序键
function bookLastReadMs(book: Book, progMap: Record<string, Prog>): number {
    // 优先取 book.id 对应的进度；公开书的副本用 readingBookId 再查一次
    const prog =
        progMap[book.id] ??
        (book.readingBookId ? progMap[book.readingBookId] : undefined);
    if (prog?.updatedAt) {
        // 有进度更新时间：解析 ISO 字符串为毫秒
        const readAt = Date.parse(prog.updatedAt);
        if (Number.isFinite(readAt)) return readAt;
    }
    // 无进度或解析失败：回退到书加入时间
    const addedAt = Date.parse(book.addedAt);
    // addedAt 也无效时返回 0，保证排序时不抛错
    return Number.isFinite(addedAt) ? addedAt : 0;
}

// 按「最近阅读时间」倒序排序的副本（不改原数组）
function sortBooksByLastRead(
    books: Book[],
    progMap: Record<string, Prog>,
): Book[] {
    // 展开新数组再 sort，避免直接 mutate MobX observable
    return [...books].sort(
        // b 在前表示倒序：最近阅读时间大的排前面
        (a, b) => bookLastReadMs(b, progMap) - bookLastReadMs(a, progMap),
    );
}
```

**变更摘要**：纯新增两个工具函数。`bookLastReadMs` 与后端 `CASE WHEN` 等价；`sortBooksByLastRead` 提供不可变排序。

```typescript
// - all + 第 1 页 + 非追加：公开书进度 + 我的进度合并

// - 其它：用后端返回的 progMap

    key.kind === 'all' && publicData && !append
        ? {
                // 公开书进度在前

            : (data.progMap ?? {});

        (b) => !mineIds.has(b.id),

    this.seedSyncedProgMap(this.progMap);
    // 新版：合并后按最近阅读时间排序
    this.books = sortBooksByLastRead(
```

```typescript
// 合并书到书架（新增或更新后调用）
mergeBookIntoShelf(book: Book, isNew: boolean): void {
    // 写入缓存
    this.bookCache[book.id] = book;
    // 不在当前分类下则不动 books
    if (!this.bookMatchesActiveCategory(book.categoryId)) {
        return;
    }
    // 判断 books 中是否已存在该书
    const existed = this.books.some((b) => b.id === book.id);
    // 旧版：直接把 book 放到最前，过滤掉旧的同 id 项
    this.books = [book, ...this.books.filter((b) => b.id !== book.id)];
    // 新书且 books 中原本没有：总数 +1
    if (!existed && isNew) {
        this.total = this.safeTotal() + 1;
    }
}
```

```typescript
// 保存阅读进度（本地立即更新 + 远端防抖同步）
saveProg(patch: Omit<Prog, 'updatedAt'>): void {
    // 取旧进度作为兜底
    const prev = this.progMap[patch.bookId];
    // 组装新进度对象，updatedAt 用当前时间
    const next: Prog = {
        bookId: patch.bookId,
        updatedAt: new Date().toISOString(),
        epubCfi: patch.epubCfi ?? prev?.epubCfi,
        pdfPage: patch.pdfPage ?? prev?.pdfPage,
        percent: patch.percent !== undefined ? patch.percent : prev?.percent,
    };
    // 在 action 内更新 progMap
    runInAction(() => {
        this.progMap[patch.bookId] = next;
    });
    // 调度远端同步
    this.scheduleProgRemoteSync(patch.bookId);
}
```

```typescript
// 保存阅读进度（本地立即更新 + 远端防抖同步）
saveProg(patch: Omit<Prog, 'updatedAt'>): void {
    // 取旧进度作为兜底
    const prev = this.progMap[patch.bookId];
    // 组装新进度对象，updatedAt 用当前时间
    const next: Prog = {
        bookId: patch.bookId,
        updatedAt: new Date().toISOString(),
        epubCfi: patch.epubCfi ?? prev?.epubCfi,
        pdfPage: patch.pdfPage ?? prev?.pdfPage,
        percent: patch.percent !== undefined ? patch.percent : prev?.percent,
    };
    // 在 action 内更新 progMap 并重排 books
    runInAction(() => {
        this.progMap[patch.bookId] = next;
        // 新增：仅当 books 中存在该书（或其公开书副本）时才重排，避免无谓排序
        if (
            this.books.some(
                (b) => b.id === patch.bookId || b.readingBookId === patch.bookId,
            )
        ) {
            // 刚保存进度 → updatedAt 最新 → 该书应排到最前
            this.books = sortBooksByLastRead(this.books, this.progMap);
        }
    });
    // 调度远端同步
    this.scheduleProgRemoteSync(patch.bookId);
}
```

**变更摘要**：`runInAction` 内新增「books 含该书时按最近阅读时间重排」。读完一本书后该书立即浮到书架顶部。

## 5. 兼容性与影响

- **兼容**：无数据库迁移、无新接口、无字段变更。`EbookProgress` 表结构未动。
- **行为变化**：书架卡片顺序从「加入时间倒序」改为「最近阅读时间倒序」。用户**未读过的书**仍按加入时间排，相对顺序不变。
- **公开书副本**：`bookLastReadMs` 用 `readingBookId` 查进度，与后端 `b.id` join 等价，公开书排序正确。
- **性能**：后端 `LEFT JOIN` + `ORDER BY 表达式` 在 `user_id` + `source_book_id` 有索引时无显著开销；前端排序 `O(n log n)`，书架规模下可忽略。

## 6. 风险与回归

建议测试：

- **书架首页顺序**：读过 A 书 → A 应排最前；再读 B 书 → B 排最前、A 第二。
- **加载更多**：滚动加载第 2 页后顺序应与第 1 页连续，不出现旧书浮到顶。
- **公开书**：在「全部」Tab 读一本公开书 → 该公开书应排到最前。
- **新增书**：导入新书后，因无进度、`addedAt` 最新，应排到「无进度的旧书」之前。
- **未读分类**：切到「未分类」Tab，未读过书按加入时间倒序。
- **进度保存**：阅读过程中进度自动保存 → 书架顺序实时更新（无需刷新）。
- **分页稳定性**：第 2 页不应出现第 1 页已有的书。
