# 书架已读进度百分比取整展示

## 文档角色

**增量专题**：书架卡片「已读约 X%」去掉冗长小数位，展示层对 `prog.percent` 夹紧并 `Math.round`。

**姊妹文档**：[ideas/电子书阅读进度保存.md](../ideas/ebook/电子书阅读进度保存.md)（进度写入）、[电子书进度远程防抖影响.md](./电子书进度远程防抖影响.md)（远端防抖）、[书架阅读打磨.md](./书架阅读打磨.md)（卡片 UI）。

**延伸阅读**：[EPUB听书播放修复2026-07.md](./EPUB听书播放修复2026-07.md)。

---

## 1. 背景与目标

### 1.1 问题

卡片文案出现「已读约 0.0932504%」：存库/同步的 `percent` 偶为多位浮点，展示层原样插进 i18n `{pct}`。

### 1.2 目标

- 展示与四边进度环共用同一取整后的 `pct`（0–100 整数）。
- 不改写入算法与 API；旧脏数据打开书架即可读正常。

---

## 2. 改动范围

| 路径 | 变更要点 |
| ---- | -------- |
| `apps/frontend/src/views/ebook/components/shelf/EbookShelfBookCard.tsx` | `pct` 派生：`Math.min(100, Math.max(0, Math.round(prog.percent)))` |

---

## 3. 实现思路

1. EPUB 写入侧 `resolveEpubPercent` 已有 `Math.round`，历史或边界路径仍可能留下浮点。
2. 展示层取整是最小面、立刻修好存量数据的做法；不必迁移库。
3. 不足 0.5% 会显示 `0%`，可接受；后续若要「至少显示 1%」再单开需求。

	// 书籍实体
	book,
	// 阅读进度
	prog,
	// 分类列表
	categories = [],
	// 书架模式
	shelfMode = 'mine',
	// 打开
	onOpen,
	// 删除
	onRemove,
	// 封面
	onSetCover,
	// 书名

	const { t } = useI18n();
	// 公开书架
	const isPublicShelf = shelfMode === 'public';
	// 可管理
	const canManage = !isPublicShelf;
	// 封面 input
	const coverInputRef = useRef<HTMLInputElement>(null);
	// 书名提交锁
	const titleCommittingRef = useRef(false);
	// 封面 busy

**变更摘要**：仅展示层取整；`0.0932504` → `0`，不再出现长小数尾巴。

## 5. 行为变化与兼容性

- **用户可见**：进度文案为整数百分比。
- **兼容**：不改 `PUT /ebook/progress`；本地 `progMap` 仍可存浮点，下次展示即圆整。
- **边界**：`null/undefined` 仍不显示进度 chip。

---

## 6. 测试与回归建议

1. 书架上曾显示长小数的书 → 刷新后为整数。
2. 新读 EPUB/PDF 保存进度后卡片百分比正常。
3. 无进度书籍仍不显示「已读约」。
