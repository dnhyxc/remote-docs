## 1. 背景与目标

后端多个 Service 原使用 NestJS 内置 `Logger`（`new Logger(XxxService.name)`）实例化日志器。这种方式：

- **脱离 DI 容器**：`new Logger()` 创建的实例不走 nest-winston 的 Winston 模块，无法享受 Winston 的传输、格式化、日志级别统一管理；
- **上下文丢失**：NestJS `Logger` 默认输出到 console，与项目 Winston 日志链路（文件 / 远程）割裂；
- **测试不友好**：硬编码 `new Logger()` 难以注入 mock。

本次将 7 个 Service + 1 个 Processor 的日志器统一改为 **通过 `WINSTON_MODULE_NEST_PROVIDER` 注入 nest-winston 的 `LoggerService`**，让所有日志走统一的 Winston 管线。

涉及文件：

- `ebook.service.ts`、`epub-parse.processor.ts`
- `logs.service.ts`
- `membership.service.ts`、`pay.service.ts`
- `share.service.ts`
- `edge-tts.service.ts`、`minimax-tts.service.ts`、`xfyun-tts.service.ts`、`siliconflow-transcription.service.ts`（TTS 服务同步迁移，配合 L2 缓存接入）

## 3. 实现思路

### 3.1 关键决策

1. **统一注入 `LoggerService`**：通过 `@Inject(WINSTON_MODULE_NEST_PROVIDER) private readonly logger: LoggerService` 注入，所有日志走 nest-winston 配置的 Winston 实例。
2. **`type LoggerService` 导入**：从 `@nestjs/common` 导入 `type LoggerService`（类型导入，无运行时开销）。
3. **保留原有 `logger.log/warn/error` 调用**：`LoggerService` 接口与 `Logger` 的 `log`/`warn`/`error` 签名兼容，调用点无需修改。
4. **TTS 服务新增 logger**：`edge-tts` / `xfyun-tts` 原本没有 logger，本次随 L2 缓存接入新增注入，用于记录 L1/L2 命中与跳过落盘日志。
5. **`share.service.ts` 特殊**：原 `private logger: Logger` 是非 readonly 且未加 `@Inject`，本次改为 `private readonly logger: LoggerService` 并加 `@Inject(WINSTON_MODULE_NEST_PROVIDER)`。

### 3.2 迁移模式图

```mermaid
flowchart LR
  A[旧：new Logger<br/>脱离 DI 容器] --> B[新：@Inject<br/>WINSTON_MODULE_NEST_PROVIDER]
  B --> C[Winston 实例<br/>统一传输/格式化/级别]
  C --> D[文件日志 / 远程日志<br/>与其它服务一致]
```

### 4.4 TTS 服务迁移（含新增 logger）

**改动前** · `apps/backend/src/services/speech-transcription/minimax-tts.service.ts`（基线）

## 5. 兼容性与影响

- **无破坏性**：`LoggerService` 接口的 `log`/`warn`/`error` 签名与 `Logger` 兼容，所有 `this.logger.xxx(...)` 调用点无需修改。
- **日志行为变化**：日志现在走 Winston 管线（文件 / 远程传输），不再直接输出到 console；日志级别由 Winston 配置统一控制。
- **DI 合规**：日志器可被 mock，便于单元测试。
- **`share.service.ts` 小改**：原 `private logger: Logger`（非 readonly、无 `@Inject`）改为 `private readonly logger: LoggerService` + `@Inject`，行为不变。

## 6. 建议回归

1. **日志输出**：启动后端，触发各服务的日志调用（如 EPUB 解析、支付回调、分享生成），确认日志走 Winston 管线（文件 / 远程）。
2. **日志级别**：调整 Winston 日志级别，确认各服务日志级别跟随。
3. **TTS L1/L2 命中日志**：开启 TTS 文件缓存，确认 `TTS 命中进程缓存(L1)` / `TTS file hit` 日志正常输出。
4. **异常路径**：模拟服务异常，确认 `logger.error` / `logger.warn` 正常输出且带上下文。
5. **启动无报错**：确认所有服务构造器注入正常，NestJS 启动无依赖解析错误。
