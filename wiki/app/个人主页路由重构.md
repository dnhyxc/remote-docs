# 个人主页路由重构

> 延伸阅读：[测试账号预填与保护.md](./测试账号预填与保护.md)

## 1. 背景与目标

个人主页相关的三个页面——个人资料（Profile）、账号设置（Account）、会员充值（Pay）——原本散落在 `/profile`、`/account`、`/pay` 三条互相独立的扁平路由下，彼此没有共享的外壳组件，也无法在后续统一添加侧边栏、页头或公共布局。

本次重构的目标：

1. **统一收口**：把资料 / 账号设置 / 会员充值三条路由统一收拢到 `/profile` 之下，形成嵌套路由，便于后续在父级 `ProfileLayout` 中放置共享布局。
2. **共享外壳**：新增 `ProfileLayout` 作为父级路由组件，通过 `Outlet` 渲染子路由，为后续公共导航、统一容器留出扩展点。
3. **向后兼容**：旧的 `/account`、`/pay` 直链不能直接删除（外链、书签、历史跳转可能仍指向它们），改用 `Navigate` 重定向到新的 `/profile/account`、`/profile/pay`，做到无感知迁移。
4. **保持懒加载**：子页面继续使用 `lazy` 动态导入，不因路由嵌套而退化为同步打包。

## 2. 改动范围

- `apps/frontend/src/router/routes.ts`：路由表结构由扁平改为嵌套，新增 `ProfileLayout` 与 `Navigate` 引入，旧 `/account`、`/pay` 改为重定向。
- `apps/frontend/src/views/profile/Layout.tsx`：新增文件，个人主页路由外壳组件。
- `apps/frontend/src/views/profile/index.tsx`：资料页内部跳转路径由 `/account`、`/pay` 更新为 `/profile/account`、`/profile/pay`。
- `apps/frontend/src/views/download/index.tsx`：下载页跳转路径由 `/account` 更新为 `/profile/account`。

## 3. 实现思路

1. **父级用 `ProfileLayout` + `Outlet`**：父级路由只负责提供一个外壳容器（当前是一个占满可用空间的 `div`），子路由通过 `react-router` 的 `Outlet` 渲染。这样后续若要加公共侧栏/页头，只需改 `ProfileLayout` 一处。
2. **子路由用相对路径 `index` / `account` / `pay`**：在 `/profile` 父级下，分别配置 `index`（资料页）、`account`（账号设置）、`pay`（会员充值），最终对外 URL 仍为 `/profile`、`/profile/account`、`/profile/pay`。
3. **旧路径用 `Navigate` 重定向**：`/account`、`/pay` 不再直接渲染业务组件，而是 `createElement(Navigate, { to: '/profile/account', replace: true })`，`replace: true` 避免在历史栈里留下一条无意义的中间记录。
4. **保留 `lazy` 懒加载**：`ProfileLayout` 与各子页面均通过 `lazy(() => import(...))` 引入，路由嵌套不改变代码分割策略。
5. **跳转代码同步更新**：资料页、下载页内部调用 `navigate('/account')`、`navigate('/pay')` 的地方，全部改为新路径，避免触发不必要的重定向往返。

## 4. 关键代码对比与注释

### 4.1 路由表：扁平三路由 → 嵌套 + 重定向（`apps/frontend/src/router/routes.ts`）

**对比范围**：`/profile`、`/account`、`/pay` 三条路由配置块（摘录）。

**改动前** · `apps/frontend/src/router/routes.ts`（基线，约 L1–L40）

```typescript
// 顶层路由数组，扁平结构，三个页面互不嵌套
const routes: RouteObject[] = [
  // 个人资料页：直接渲染 Profile 组件
  {
    path: '/profile',
    // 懒加载 Profile 组件
    element: createElement(Profile),
  },
  // 账号设置页：直接渲染 Account 组件
  {
    path: '/account',
    // 懒加载 Account 组件
    element: createElement(Account),
  },
  // 会员充值页：直接渲染 Pay 组件
  {
    path: '/pay',
    // 懒加载 Pay 组件
    element: createElement(Pay),
  },
];
```

**改动后** · `apps/frontend/src/router/routes.ts`（当前，约 L1–L55）

```typescript
// 引入 react-router 的 Navigate 组件，用于旧路径重定向
import { Navigate } from 'react-router';
// 懒加载新增的 ProfileLayout 外壳组件
const ProfileLayout = lazy(() => import('@views/profile/Layout'));
// 顶层路由数组，profile 相关页面收口为嵌套结构
const routes: RouteObject[] = [
  // 个人主页父级路由：渲染外壳，子路由经 Outlet 渲染
  {
    path: '/profile',
    // 父级渲染 ProfileLayout，提供共享布局容器
    element: createElement(ProfileLayout),
    // 子路由列表：资料 / 账号 / 充值
    children: [
      // index 路由对应 /profile，渲染资料页
      {
        index: true,
        // 懒加载 Profile 组件
        element: createElement(Profile),
      },
      // /profile/account：账号设置页
      {
        path: 'account',
        // 懒加载 Account 组件
        element: createElement(Account),
      },
      // /profile/pay：会员充值页
      {
        path: 'pay',
        // 懒加载 Pay 组件
        element: createElement(Pay),
      },
    ],
  },
  // 旧 /account 重定向到新路径，replace 避免历史栈冗余
  {
    path: '/account',
    // 重定向目标：账号设置新路径
    element: createElement(Navigate, { to: '/profile/account', replace: true }),
  },
  // 旧 /pay 重定向到新路径，replace 避免历史栈冗余
  {
    path: '/pay',
    // 重定向目标：会员充值新路径
    element: createElement(Navigate, { to: '/profile/pay', replace: true }),
  },
];
```

**变更摘要**：`/profile` 由直接渲染 `Profile` 改为渲染 `ProfileLayout` 并新增三个子路由；`/account`、`/pay` 由直接渲染业务组件改为 `Navigate` 重定向到 `/profile/account`、`/profile/pay`；新增 `Navigate` 与 `ProfileLayout` 两个引入。

### 4.2 新增 `ProfileLayout` 外壳组件（`apps/frontend/src/views/profile/Layout.tsx`）

**对比范围**：`ProfileLayout` 组件全函数（纯新增，仅展示改动后）。

**改动后** · `apps/frontend/src/views/profile/Layout.tsx`（当前，约 L1–L12）

```tsx
// 引入 react-router 的 Outlet，用于渲染匹配到的子路由
import { Outlet } from 'react-router';
// 个人主页路由壳：资料 / 账号设置 / 会员充值
export default function ProfileLayout() {
  // 返回一个占满父级可用空间的外壳容器
  return (
    // 外层 div：撑满高度与宽度，作为后续公共布局的挂载点
    <div className="h-full min-h-0 w-full min-w-0">
      {/* Outlet 占位：子路由（Profile / Account / Pay）在此渲染 */}
      <Outlet />
    </div>
  );
}
```

**变更摘要**：新增纯文件，仅提供一个带 `Outlet` 的容器组件，作为 `/profile` 父级路由的渲染外壳，便于后续扩展公共布局。

## 5. 兼容性与影响

- **旧外链/书签可用**：`/account`、`/pay` 仍然有效，会被 `Navigate` 以 `replace` 方式重定向到 `/profile/account`、`/profile/pay`，用户无感知。
- **无破坏性变更**：三个页面的业务组件（`Profile`、`Account`、`Pay`）本身未改动，仅外层路由结构与跳转路径调整。
- **懒加载不变**：`ProfileLayout` 与各子页面均保持 `lazy` 动态导入，首屏与各路由 chunk 体积无明显变化。
- **历史栈更干净**：旧路径用 `replace: true` 重定向，不会在浏览器历史中留下中间项，用户后退体验更自然。
- **内部跳转已同步**：资料页、下载页的 `navigate` 已改为新路径，不会触发「先到旧路径再重定向」的往返。

## 6. 风险与回归

- **回归重点**：直接访问 `/profile`、`/profile/account`、`/profile/pay` 三个新 URL，确认页面正常渲染。
- **重定向验证**：直接访问旧 `/account`、`/pay`，确认地址栏被替换为新路径且页面内容正确。
- **历史栈**：从资料页点击「账号设置」后，浏览器后退应回到资料页而非旧 `/account` 中间态。
- **懒加载**：首次进入 `/profile` 各子路由时，确认对应 chunk 正常加载、无白屏或报错。
- **外链入口**：若有第三方或邮件链接指向 `/account`、`/pay`，需回归确认重定向后目标页面无鉴权/状态丢失。
- **样式继承**：`ProfileLayout` 的外层 `div` 使用 `h-full min-h-0 w-full min-w-0`，需确认子页面在嵌套容器内的滚动与布局表现与重构前一致。
