# 队列事件错误信息防御性取值 — 实现说明

## 延伸阅读

- [后端日志统一注入.md](./后端日志统一注入.md) — 后端日志统一走 Winston 管线（同类横切改动）

## 1. 背景与目标

`QueueEventsListener` 的两处错误日志此前直接读取 `error?.message` / `error.message`。在 TS 开启 `strict`（`useUnknownInCatchVariables` 默认生效）后，`catch` 变量类型为 `unknown`（`.catch` 回调若不标注亦按 `unknown` 处理），直接在 `unknown` 上取 `.message` 类型不安全，且当抛出的不是 `Error`（例如字符串、对象）时，`message` 可能为 `undefined`。

目标：**先做类型收窄再取值**，让错误日志既类型安全、又能稳定输出可读信息，行为不变。

## 2. 改动范围

| 路径 | 说明 |
|------|------|
| `apps/backend/src/utils/queue-events-listener.ts` | `completed` 事件 `try/catch` 与 `onModuleDestroy` 的 `.catch` 各一处 |

## 3. 实现思路

统一模式：`const msg = error instanceof Error ? error.message : String(error);`，再用 `${msg}` 记日志。

- `Error` 实例：取 `error.message`，保持原有可读信息；
- 其它任意抛出值（字符串 / 对象）：`String(error)` 兜底，避免 `message` 为 `undefined` 或运行时取属性报错。

`completed` 事件与 `onModuleDestroy` 两处独立，无跨模块数据流，略图。

## 4. 关键代码对比与注释

### 4.1 `completed` 事件回调的 `catch`

**改动前** · `apps/backend/src/utils/queue-events-listener.ts`（基线，约 L70–L74）

```typescript
// 进入 catch：改动前直接把 error 当 any 用，未做类型收窄
} catch (error) {
	// 日志：直接读 error?.message；可选链在 null/undefined 时输出 undefined
	this.logger.error?.(
		// 错误详情用可选链兜底，非 Error 抛出时信息可能缺失
		`[QueueEventsListener] Failed to parse completed event for job ${jobId}, error: ${error?.message}`,
	);
}
```

**改动后** · `apps/backend/src/utils/queue-events-listener.ts`（当前源码，约 L70–L76）

```typescript
// 进入 catch：改动后先收窄类型，再拼日志
} catch (error) {
	// 类型收窄：Error 实例取 message，否则把任意值转成字符串
	const msg =
		// 三元：instanceof Error 走 message，其它情况 String(...) 兜底
		error instanceof Error ? error.message : String(error);
	// 日志：改用收窄后的 msg，严格模式下不再对 unknown 取属性
	this.logger.error?.(
		// 错误详情统一用 msg 输出，保证可读且类型安全
		`[QueueEventsListener] Failed to parse completed event for job ${jobId}, error: ${msg}`,
	);
}
```

### 4.2 `onModuleDestroy` 的 `.catch` 回调

**改动前** · `apps/backend/src/utils/queue-events-listener.ts`（基线，约 L154–L158）

```typescript
// .close() 链末端 .catch：改动前参数未标注类型，直接读 error.message
.catch((error) => {
	// 日志：直接读 error.message；error 为隐式 any，非 Error 时 message 可能为 undefined
	this.logger.error?.(
		// 错误详情直接拼接 error.message
		`[QueueEventsListener] Failed to close: ${error.message}`,
	);
});
```

**改动后** · `apps/backend/src/utils/queue-events-listener.ts`（当前源码，约 L156–L162）

```typescript
// .close() 链末端 .catch：改动后显式标注参数为 unknown，并先收窄
.catch((error: unknown) => {
	// 类型收窄：Error 实例取 message，否则把任意值转成字符串
	const msg =
		// 三元：instanceof Error 走 message，其它情况 String(...) 兜底
		error instanceof Error ? error.message : String(error);
	// 日志：改用收窄后的 msg，类型安全
	this.logger.error?.(
		// 错误详情统一用 msg 输出
		`[QueueEventsListener] Failed to close: ${msg}`,
	);
});
```

**变更摘要**：两处均新增 `const msg = error instanceof Error ? error.message : String(error);` 并改用 `${msg}`；第二处 additionally 给 `.catch` 参数标注 `(error: unknown)`。日志文案与等级不变。

## 5. 兼容性与影响

| 项 | 说明 |
|----|------|
| 运行时行为 | `Error` 抛出时输出与原先一致；非 `Error` 抛出时由 `undefined` 变为 `String(error)`，信息更完整 |
| 类型安全 | 满足 `useUnknownInCatchVariables`，无需 `any` 断言 |
| 外部接口 | 无变化（仅内部日志） |
