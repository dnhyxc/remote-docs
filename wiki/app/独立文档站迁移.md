# 独立文档站迁移

> 延伸阅读：[强调色外链同步.md](../ui/强调色外链同步.md)（`?accent=` / `?theme=` 传递机制）

## 1. 背景与目标

项目中的「更新信息」「产品指南」「插件开发手册」三个独立页原本是主站前端（`apps/frontend`）内置的 SPA 路由——`/update-info`、`/project-guide`、`/plugin-dev-guide`，由本地 React 组件渲染，正文数据写在前端 `updateInfoSections.ts` / `projectGuideSections.ts` 等 TypeScript 文件中。

这种方案有几个问题：

1. **文档维护耦合在主应用**：每次改更新说明或产品指南都要改前端源码、重新构建发布，正文内容和应用代码强绑定。
2. **主包体积膨胀**：`updateInfoSections.ts` 单文件 2600+ 行、`projectGuideSections.ts` 700+ 行、`pluginDevGuideSections.ts` 1600+ 行，这些纯文档数据被打包进主应用 chunk，拖慢首屏。
3. **无法独立更新**：文档更新需要和应用功能迭代一起发版，不能做到「只更新说明文案，不动应用」。

本次迁移把这三个页面从主站抽离到一个独立的 **remote-docs 微应用**，主站只保留入口跳转能力：

1. **正文外置**：三个页面的正文数据与渲染逻辑迁移到独立仓 `micro-apps/remote-docs`，可独立构建、独立部署到专属 origin（dev `http://127.0.0.1:9013`，prod `https://dnhyxc.cn:9017`）。
2. **主站瘦身**：删除 `views/updateInfo/`、`views/projectGuide/`、`views/pluginDevGuide/` 三个目录及其路由，主应用不再承载文档正文。
3. **跳转统一**：所有打开这三个页面的入口统一改为调用 `openExternalUrl(getXxxAbsoluteUrl(locale))`，在系统浏览器 / 新标签页打开独立站，不再走 SPA 路由。
4. **体验对齐**：跳转时自动追加 `lang`、`theme`、`accent` 查询参数，确保独立站打开后语言、深浅主题、强调色与主站一致（机制同 [强调色外链同步.md](../ui/强调色外链同步.md)）。

## 3. 实现思路

1. **独立站 origin 抽象为 `getRemoteDocsOrigin()`**：origin 可被 `VITE_REMOTE_DOCS_ORIGIN` 覆盖，dev / prod 各有缺省值。这样本地开发连 `127.0.0.1:9013`，线上连 `dnhyxc.cn:9017`，调用方无需关心环境。
2. **URL 拼装复用既有主题/语言机制**：`getRemoteDocsAbsoluteUrl` 内部依次追加 `lang`（`withAppLangInSearch`）、`theme`（`appendShareThemeQuery`）、`accent`（`appendShareAccentQuery`），与分享页、下载页等独立页的参数对齐，避免重复造轮子。
3. **路由直接移除，不保留重定向**：因为目标 origin 已变（跨域），无法用 `<Navigate>` 在 SPA 内重定向到独立站。所以三条路由从 `routes.ts` 中直接删除，调用方统一走 `openExternalUrl`。
4. **barrel 统一出口**：`remote-docs-url.ts` 的常量和函数通过 `@/utils`（`index.ts`）再导出，调用方不必记住具体子路径，也便于后续替换实现。
5. **正文数据留在独立仓**：`updateInfoSections.ts` 等四个数据文件随页面一起迁到 `micro-apps/remote-docs`，主仓不再维护文档正文。

### 4.1 新增 `remote-docs-url.ts`：独立站 URL 拼装

**改动前** · `apps/frontend/src/views/updateInfo/paths.ts`（基线，已删除）

```typescript
// 与路由表一致的页面路径常量

```

**改动后** · `apps/frontend/src/utils/remote-docs-url.ts`（当前源码，L1–L61）

```typescript
// 引入主题/强调色相关工具：追加 query、读取本地 bootstrap
import {
	type AccentId,
	appendShareAccentQuery,
	appendShareThemeQuery,
	readAccentBootstrapSync,
	readThemeBootstrapSync,
	type ThemeName,
} from '@/hooks/theme';
// 引入 Locale 类型，用于判断语言参数
import type { Locale } from '@/i18n';
// 复用 withAppLangInSearch 为 URL 追加 lang 参数
import { withAppLangInSearch } from '@/utils/public-doc-url';

// 与 remote-docs / registry routePath 一致的路径常量
export const UPDATE_INFO_PATH = '/update-info';
export const PROJECT_GUIDE_PATH = '/project-guide';
export const PLUGIN_DEV_GUIDE_PATH = '/plugin-dev-guide';

/**
 * remote-docs 独立站 origin。
 * - 可用 VITE_REMOTE_DOCS_ORIGIN 覆盖
 * - DEV 缺省：http://127.0.0.1:9013
 * - PROD 缺省：https://dnhyxc.cn:9017
 */
export function getRemoteDocsOrigin(): string {
	// 读环境变量并去掉末尾斜杠，避免拼出双斜杠
	const fromEnv = String(import.meta.env.VITE_REMOTE_DOCS_ORIGIN ?? '')
		.trim()
		.replace(/\/$/, '');
	// 环境变量非空则直接使用
	if (fromEnv) return fromEnv;
	// dev 环境回退到本地 9013
	if (import.meta.env.DEV) return 'http://127.0.0.1:9013';
	// prod 环境回退到线上 9017
	return 'https://dnhyxc.cn:9017';
}

/**
 * 拼 remote-docs 绝对 URL（lang / theme / accent）。
 * themeName / accentId 传 undefined 时取本地 bootstrap，传 null 时不追加。
 */
export function getRemoteDocsAbsoluteUrl(
	path: string,
	locale?: Locale,
	themeName?: ThemeName | null,
	accentId?: AccentId | null,
): string {
	// 取独立站 origin
	const origin = getRemoteDocsOrigin();
	// 保证 path 以 / 开头
	const normalized = path.startsWith('/') ? path : `/${path}`;
	// origin + path 拼出基础 URL
	let url = origin ? `${origin}${normalized}` : normalized;
	// 有 locale 时追加 ?lang=
	if (locale) url = withAppLangInSearch(url, locale);
	// themeName 为 undefined 时读本地 bootstrap；为 null 时跳过
	const theme = themeName === undefined ? readThemeBootstrapSync() : themeName;
	if (theme) url = appendShareThemeQuery(url, theme);
	// accentId 同理
	const accent = accentId === undefined ? readAccentBootstrapSync() : accentId;
	if (accent) url = appendShareAccentQuery(url, accent);
	// 返回最终 URL
	return url;
}

// 更新信息独立页绝对 URL
export function getUpdateInfoAbsoluteUrl(locale?: Locale): string {
	return getRemoteDocsAbsoluteUrl(UPDATE_INFO_PATH, locale);
}

// 产品指南独立页绝对 URL
export function getProjectGuideAbsoluteUrl(locale?: Locale): string {
	return getRemoteDocsAbsoluteUrl(PROJECT_GUIDE_PATH, locale);
}

// 插件开发手册独立页绝对 URL
export function getPluginDevGuideAbsoluteUrl(locale?: Locale): string {
	return getRemoteDocsAbsoluteUrl(PLUGIN_DEV_GUIDE_PATH, locale);
}
```

**变更摘要**：origin 从「主站域名」（`getSitePageAbsoluteUrl`）切换为「remote-docs 独立站域名」（`getRemoteDocsOrigin`），路径常量集中到一个文件，三个页面共用同一套拼装逻辑。

## 5. 运行时行为

1. 用户点击「更新说明」/「产品指南」/「插件开发手册」入口 → 调用 `openExternalUrl(getXxxAbsoluteUrl(locale))`。
2. `getXxxAbsoluteUrl` 拼出 `https://dnhyxc.cn:9017/path?lang=zh-CN&theme=dark&accent=xxx`。
3. Tauri 端经 `plugin:opener|open_url` 在系统浏览器打开；Web 端 `window.open` 新标签页打开。
4. 独立站 `remote-docs` 读取 URL 上的 `lang` / `theme` / `accent` 参数，渲染对应语言与主题的页面。
