# 搜索组件提取：知识库 KnowledgeSearchInput 升级为通用 @design/SearchInput

> **文档角色**：把原先仅服务知识库列表/回收站的 `KnowledgeSearchInput` 提取为 `components/design/` 下的通用共享组件 `SearchInput`，并新增 `autoFocus` / `inputRef` / `onEscape` 三个可选 props，为电子书书架搜索等其它业务复用铺路。
> **延伸阅读**：[统一文件选择.md](./统一文件选择.md)（同为「业务专用 → 通用 `@design/`」抽取思路）

## 1. 背景与目标

旧 `KnowledgeSearchInput` 组件位于 `apps/frontend/src/views/knowledge/KnowledgeSearchInput.tsx`，仅服务知识库列表与回收站两处，封装了三段交互：

- **回车提交**：按 Enter 才把本地 draft 同步给父级（避免每次按键触发父级及其列表重渲）；
- **清除即重置**：点浏览器原生清除图标把输入框清空时，立即向父级提交空字符串（无需再按 Enter）；
- **草稿内化**：draft 由组件内部 `useState` 维护，父级只看 `committedQuery`。

电子书书架搜索也想复用完全相同的交互，并额外需要：

1. 挂载即聚焦（`autoFocus`）；
2. 父级命令式操作 input（`inputRef`）；
3. 按 Esc 时回调父级（`onEscape`，如关闭搜索态）。

但旧组件放在 `views/knowledge/` 业务目录下，且未暴露这三个 props——若电子书直接跨业务目录 import 既不雅观也耦合了知识库路径。

**目标**：

- 将 `KnowledgeSearchInput` 上移到 `apps/frontend/src/components/design/SearchInput/index.tsx`，重命名为 `SearchInput`，归入 `@design/` 别名；
- 在不动旧交互的前提下，**新增** `autoFocus` / `inputRef` / `onEscape` 三个**可选** props；
- 知识库列表与回收站两处旧引用切到 `@design/SearchInput`，原 `KnowledgeSearchInput.tsx` 文件删除。

## 3. 实现思路

| # | 要点 | 说明 |
|---|------|------|
| 1 | 落位 `components/design/` | 该目录承载 `@design/` 别名下的横切 UI 组件（如 `Drawer` / `Loading` / `Tooltip` / `CategoryManageDialog` 等），抽取后路径稳定、跨业务复用不再耦合 `views/knowledge/` |
| 2 | 类型重命名 | `Props` → `SearchInputProps` 并 `export`，方便电子书等复用方按需引用类型；旧 `Props` 不导出仅内部使用，删除即整体迁移 |
| 3 | 三个可选 props | `autoFocus?` / `inputRef?` / `onEscape?` 均为可选，知识库两处调用方不传，行为与旧版一致 |
| 4 | ref 透传 | 通过 `<Input ref={inputRef} …>` 把外部 ref 直接转发到底层 Input；不传则为 `undefined`，Input 行为不变 |
| 5 | Escape 优先于 Enter | `onKeyDown` 内先判 `Escape`：阻止默认行为后回调 `onEscape?.()` 并 `return`；只有非 Escape 时才走 Enter 提交逻辑，避免误触 |
| 6 | 草稿态与提交语义不变 | `useState(committedQuery)` + `useEffect` 同步、原生清除图标清空即 `onCommit('')`、Enter 提交 `draft`——三段交互一字不改，知识库搜索外观与行为完全保持 |
| 7 | 双调用方最小替换 | 仅改 import 路径、JSX 标签名（KnowledgeList 另加一行注释文字替换）；不调 props、不改 className、不动调用方逻辑 |
| 8 | 旧文件直接删除 | 抽取后 `KnowledgeSearchInput.tsx` 不再被任何文件引用（已确认仅两处），删除以避免双份维护 |

## 4. 关键代码对比与注释

### 4.1 通用 `SearchInput` 组件（纯新增）

**对比范围**：`SearchInputProps` 类型 + `SearchInput` 函数全文（含 `memo` 默认导出）。纯新增，无「改动前」版本。

**改动后** · `apps/frontend/src/components/design/SearchInput/index.tsx`（约 L1–L65）

```typescript
// 从 @ui/input 别名引入统一的 Input 基础组件（封装自 Radix 等基础库）
import { Input } from '@ui/input';
// 引入 memo 做渲染优化、useEffect 与 useState 用于草稿态管理、Ref 类型用于转发外部 ref
import { memo, useEffect, useState, type Ref } from 'react';

// 对外暴露的 props 类型定义，描述通用搜索输入框的全部可控入参
export type SearchInputProps = {
	/** 已提交的搜索词（回车 / 清除后由父级更新） */
	// 父级维护的「已提交」搜索词；作为 draft 的初始值与同步源
	committedQuery: string;
	// 提交搜索词的回调，参数为当前 draft（按回车或清空时触发）
	onCommit: (query: string) => void;
	// 占位符文本，同时用作 aria-label 以满足无障碍
	placeholder: string;
	// 可选的外部 className，便于父级覆盖样式
	className?: string;
	// 可选的自动聚焦开关，挂载时即聚焦，便于电子书书架等需要立即输入的场景
	autoFocus?: boolean;
	// 可选的外部 ref 转发，便于父级命令式操作 input（如程序化 focus / blur）
	inputRef?: Ref<HTMLInputElement>;
	// 可选的 Escape 键回调（如父级希望按 Esc 关闭搜索态）
	onEscape?: () => void;
};

// 组件顶层文档注释：回车提交搜索；草稿态留在组件内，避免按键拖垮父级列表
/**
 * 回车提交搜索；草稿态留在组件内，避免按键拖垮父级列表。
 */
function SearchInput({
	// 解构入参：已提交的搜索词
	committedQuery,
	// 解构入参：提交搜索词的回调
	onCommit,
	// 解构入参：占位符文本
	placeholder,
	// 解构入参：可选的外部 className
	className,
	// 解构入参：可选的自动聚焦开关
	autoFocus,
	// 解构入参：可选的外部 ref
	inputRef,
	// 解构入参：可选的 Escape 键回调
	onEscape,
	// 类型注解：SearchInputProps
}: SearchInputProps) {
	// 草稿态：初始值取自父级传入的 committedQuery，仅在本组件内更新
	const [draft, setDraft] = useState(committedQuery);

	// 父级 committedQuery 变化时（如外部清空搜索）同步更新本地草稿
	useEffect(() => {
		// 用最新的 committedQuery 重置 draft
		setDraft(committedQuery);
	// 仅在 committedQuery 变化时触发
	}, [committedQuery]);

	// 渲染：返回 Input 元素，转发 ref 与新增的可控 props
	return (
		// Input 基础组件，承载 search 类型输入与全部交互逻辑
		<Input
			// 转发外部 ref，便于父级命令式操作 input；不传则为 undefined
			ref={inputRef}
			// 类型为 search，浏览器会渲染原生清除图标
			type="search"
			// 字号 18px，与知识库列表/回收站历史外观保持一致
			size={18}
			// 透传 autoFocus；为可选值，知识库历史调用方不传则保持原行为
			autoFocus={autoFocus}
			// 受控值：本地 draft，避免每次按键触发父级重渲
			value={draft}
			// 输入事件：维护 draft；在原生清除图标清空时立即提交空字符串
			onChange={(e) => {
				// 取出当前输入框最新值
				const next = e.target.value;
				// 先同步到本地 draft
				setDraft(next);
				// 原生清除图标：清空后立即重置，无需回车
				if (next === '' && committedQuery.trim() !== '') {
					// 通知父级清空已提交搜索
					onCommit('');
				}
			}}
			// 键盘事件：Escape 优先回调父级；Enter 提交 draft
			onKeyDown={(e) => {
				// 优先处理 Escape：阻止默认行为并触发 onEscape（如有）
				if (e.key === 'Escape') {
					// 阻止浏览器默认的 Escape 行为（如部分浏览器会清空 input）
					e.preventDefault();
					// 触发外部可选的 onEscape 回调
					onEscape?.();
					// 提前返回，避免后续 Enter 逻辑误触发
					return;
				}
				// 非 Enter 直接放行，不做处理
				if (e.key !== 'Enter') return;
				// 阻止默认的 Enter 提交表单行为
				e.preventDefault();
				// 提交当前 draft 给父级
				onCommit(draft);
			}}
			// 占位符文本
			placeholder={placeholder}
			// 无障碍标签：复用占位符，便于读屏
			aria-label={placeholder}
			// 外部 className，便于父级覆盖样式
			className={className}
		/>
	);
}

// 默认导出 memo 包装后的组件，避免父级无关重渲时本组件跟着重渲
export default memo(SearchInput);
```

**变更摘要**：纯新增文件。复用旧 `KnowledgeSearchInput` 的草稿态 + 回车提交 + 清除即重置三段交互；新增 `autoFocus` / `inputRef` / `onEscape` 三个可选 props，并把 ref 透传与 Escape 处理织入。

**变更摘要**：仅替换 JSX 标签名；新 props 在本调用方同样不传，回收站搜索行为与外观完全保持。

## 5. 兼容性与影响

| 维度 | 结论 | 说明 |
|------|------|------|
| 知识库列表搜索行为 | **完全不变** | `committedQuery` / `onCommit` / `placeholder` / `className` 子集未改；草稿态、回车提交、清除即重置三段交互一字未改 |
| 知识库回收站搜索行为 | **完全不变** | 同上；placeholder 仍走 `knowledge.trash.searchPlaceholder` |
| 知识库搜索框外观 | **完全不变** | `size={18}`、`type="search"`、外部 className 全部保留 |
| 新增 `autoFocus` / `inputRef` / `onEscape` | **对旧调用方零影响** | 三者均为可选 props；不传时 `autoFocus` 为 `undefined`，`inputRef` 为 `undefined`，`onEscape?.()` 不触发，等价于旧版没有该分支 |
| `Escape` 行为差异 | **细微但兼容** | 旧版按 Esc 仅触发浏览器默认行为（可能清空 input）；新版会 `e.preventDefault()` 并调用 `onEscape?.()`。知识库两处调用方未传 `onEscape`，`onEscape?.()` 不执行，但默认行为被阻止后 Esc 不再清空 input——若需依赖浏览器原生 Esc 清空，可改由父级在 `onEscape` 中显式 `setAppliedQuery('')` |
| 删除旧文件 | **编译期可检出** | `KnowledgeSearchInput.tsx` 删除后，若有其它文件仍 `import './KnowledgeSearchInput'` 或 `import './KnowledgeSearchInput'` 路径别名解析失败，将编译报错；已确认仅 `KnowledgeList.tsx` 与 `KnowledgeTrashList.tsx` 两处引用，均已切换 |
| 后续电子书书架复用 | **可期** | 新 props 齐备后，电子书书架可直接 `import SearchInput from '@design/SearchInput'` 并按需传 `autoFocus` / `inputRef` / `onEscape`，无需再修改本组件 |

**建议回归路径**：

1. 知识库列表：输入关键词 → 按 Enter → 列表过滤命中；点 input 原生清除图标 → 列表恢复全量；
2. 知识库回收站：同上，placeholder 为回收站专属文案；
3. 知识库列表/回收站：外部清空 `appliedQuery`（如切分类）→ input 文本同步清空；
4. 全局编译：确认无残留 `./KnowledgeSearchInput` 导入，TS 无类型错误。
