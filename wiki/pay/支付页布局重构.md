# 支付页布局重构

> 延伸阅读：[Stripe会员计费.md](./Stripe会员计费.md)（主文档，Stripe 三档会员充值与支付页整体逻辑）、[测试账号预填与保护.md](../auth/测试账号预填与保护.md)（`isProtectedAccountUsername` 测试账号判定与禁用场景）。

## 1. 背景与目标

支付页原先以 `min-h-full` 直接铺满父容器，顶部带 `motion.header`（盾牌徽章 + 标题），在嵌入 ProfileLayout（个人资料页布局壳）后会出现：

- **高度溢出**：父壳已是 flex 列布局并限制高度，子页再用 `min-h-full` 会导致内容超长时无法滚动，底部套餐卡被截断。
- **头部冗余**：ProfileLayout 自身已有页面标题与返回栏，支付页再放一层 `ShieldCheck` 徽章 + `pay.title` 显得叠床架屋。
- **文案啰嗦**：嵌入式开关按钮文案「在页面内打开收银台 / 关闭收银台」偏长，与简化的「开启支付 / 关闭支付」目标不符。
- **测试账号可下单**：测试账号能直接唤起 Stripe 收银台，存在误扣风险，需要在打开收银台前拦截。

本次重构目标：

1. 用 `ScrollArea` 包裹整页，让溢出内容在 ProfileLayout 壳内可纵向滚动。
2. 删除 `motion.header`，让套餐选择区直接成为视觉主角。
3. 内容区垂直居中，适配不同视口高度。
4. 打开收银台前校验测试账号并 Toast 拦截。
5. 精简嵌入式开关文案为中英文「开启支付 / 关闭支付」。

## 2. 改动范围

- `apps/frontend/src/views/pay/index.tsx`（支付页主体，约 318 行改动）
- 国际化文案文件（中 / 英）：
  - 移除 `pay.badge.stripeEmbedded`、`pay.footer.stripeProvided` 两个键。
  - 修改 `pay.actions.openEmbedded`、`pay.actions.closeEmbedded` 文案。

## 3. 实现思路

1. **ScrollArea 接管滚动**：最外层改为 `flex h-full w-full min-h-0 flex-col overflow-hidden`，内部套一层 `ScrollArea`，让支付页在 ProfileLayout 的受限高度壳内自行滚动，而非撑破父容器。`min-h-0` 是 flex 子项允许收缩的关键。
2. **垂直居中**：ScrollArea 内层用 `flex min-h-full flex-1 flex-col justify-center`，使套餐卡在视口较高时居中、较高时顶部贴齐并向下滚动。
3. **去除 header**：删除 `motion.header` 及其 `ShieldCheck` 徽章、`pay.title` 标题，减少与 ProfileLayout 标题栏的重复；保留装饰层 `pointer-events-none absolute inset-0 opacity-[0.45]`。
4. **容器宽度收敛**：原 `mx-auto max-w-2xl` 外层结构调整为先 `px-6 pt-6 pb-10` 留白，再内嵌 `mx-auto w-full max-w-2xl` 限宽，保证滚动条出现时宽度仍稳定。
5. **测试账号拦截**：在 `onOpenEmbeddedCheckout` 入口处读取 `getLoggedInUserInfoFromStorage()` 与 `userStore.userInfo?.username`，命中 `isProtectedAccountUsername` 则 Toast 警告并 `return`，不进入 Stripe `initEmbeddedCheckout`。
6. **文案精简**：嵌入式开关按钮统一为「开启支付 / 关闭支付（Open payment / Close payment）」，移除不再使用的 `pay.badge.stripeEmbedded`、`pay.footer.stripeProvided`。

## 4. 关键代码对比与注释

### 4.1 `return` 整体结构（`apps/frontend/src/views/pay/index.tsx`）

**对比范围**：组件 `return` 语句的最外层结构（从 `return (` 到闭合 `);`），摘录外层容器与布局骨架，省略内部套餐/收银台 JSX。

**改动前** · `apps/frontend/src/views/pay/index.tsx`（基线，约 `return` 外层结构）

```tsx
// 返回整个组件的 JSX，最外层是相对定位、铺满最小高度的渐变背景容器
return (
    // 旧版外层：相对定位 + 最小高度铺满 + 主题渐变背景，无滚动能力
    <div className="relative min-h-full bg-theme-gradient">
        // 装饰层：绝对定位铺满、不拦截指针事件、45% 透明度
        <div className="pointer-events-none absolute inset-0 opacity-[0.45]" />
        // 内容容器：水平居中、最大宽度 2xl、纵向 flex、间距 8、内边距 6/10
        <div className="relative mx-auto flex max-w-2xl flex-col gap-8 px-6 py-10">
            // 旧版 header（含盾牌徽章与标题），详见 4.2 节
            <motion.header ...>
                // header 内部 JSX 省略
            </motion.header>
            // 套餐选择 + 收银台主体，省略内部实现
            <motion.div ...>
                // 套餐/收银台 JSX 省略
            </motion.div>
        </div>
    </div>
);
```

**改动后** · `apps/frontend/src/views/pay/index.tsx`（当前，约 `return` 外层结构）

```tsx
// 返回整个组件的 JSX，最外层改为 flex 列布局并隐藏溢出
return (
    // 新版最外层：flex 列、铺满高宽、min-h-0 允许 flex 收缩、隐藏溢出、无外边距
    <div className="flex h-full w-full min-h-0 flex-col overflow-hidden m-0">
        // ScrollArea 包裹整页，接管纵向滚动；铺满高宽、min-h-0 收缩、无圆角、渐变背景
        <ScrollArea className="h-full w-full min-h-0 rounded-none bg-theme-gradient">
            // 内层 flex 容器：相对定位、最小高度铺满、纵向 flex、垂直居中、渐变背景
            <div className="relative flex h-full min-h-full w-full flex-1 flex-col justify-center bg-theme-gradient">
                // 装饰层保留：绝对定位铺满、不拦截指针事件、45% 透明度
                <div className="pointer-events-none absolute inset-0 opacity-[0.45]" />
                // 留白层：水平内边距 6、上 6 下 10
                <div className="relative px-6 pt-6 pb-10">
                    // 限宽容器：水平居中、铺满可用宽度、最大宽度 2xl
                    <div className="mx-auto w-full max-w-2xl">
                        // 套餐选择 + 收银台主体（原 motion.div，header 已删除）
                        <motion.div ...>
                            // 套餐/收银台 JSX 省略
                        </motion.div>
                    </div>
                </div>
            </div>
        </ScrollArea>
    </div>
);
```

**变更摘要**：最外层从 `min-h-full` 铺满改为 `flex + overflow-hidden` 壳 + `ScrollArea` 滚动；内层新增 `justify-center` 垂直居中与 `px-6 pt-6 pb-10` 留白；`max-w-2xl` 下沉到内层。

### 4.3 测试账号拦截（`onOpenEmbeddedCheckout`，纯新增）

**对比范围**：`onOpenEmbeddedCheckout` 函数开头新增的测试账号校验（纯新增，仅贴改动后）。

**改动后** · `apps/frontend/src/views/pay/index.tsx`（当前，约 `onOpenEmbeddedCheckout` 入口）

```tsx
// 从本地存储读取已登录用户信息（可能在 userStore 尚未 hydrate 时兜底）
const stored = getLoggedInUserInfoFromStorage();
// 取用户名：优先 userStore 中的 userInfo.username，否则回退到本地存储的 username
const username = userStore.userInfo?.username ?? (typeof stored?.username === 'string' ? stored.username : undefined);
// 命中测试账号用户名则拦截，Toast 警告并直接返回，不进入 Stripe 收银台
if (isProtectedAccountUsername(username)) {
    // 弹出警告 Toast：测试账号禁止支付（i18n key account.toast.testAccountForbidden）
    Toast({ type: 'warning', title: t('account.toast.testAccountForbidden') });
    // 中断函数，不执行后续 initEmbeddedCheckout
    return;
}
```

**变更摘要**：在打开 Stripe 嵌入式收银台前新增测试账号校验，命中 `isProtectedAccountUsername` 则 Toast 警告并 `return`，防止测试账号误扣款。

## 5. 兼容性与影响

- **向后兼容**：支付页内部套餐选择、Stripe 嵌入式收银台调用逻辑未变，仅外层布局容器与拦截逻辑调整。
- **ProfileLayout 适配**：重构后支付页作为 ProfileLayout 子路由，高度由父壳分配，`ScrollArea` 负责自身滚动，不再撑破父容器。
- **测试账号影响**：测试账号用户点击「开启支付」将收到警告 Toast 且无法打开收银台，属预期行为。
- **i18n 键移除**：`pay.badge.stripeEmbedded`、`pay.footer.stripeProvided` 被删除，若有外部引用需同步清理（仓库内仅支付页引用）。

## 6. 风险与回归

| 风险点 | 说明 | 建议回归 |
|--------|------|----------|
| ScrollArea 滚动 | 内容超长时需确认滚动条出现且底部套餐卡可见 | 低高度视口下切换套餐、展开收银台 |
| 垂直居中 | 高视口下内容应居中而非贴顶 | 桌面端高分辨率窗口访问支付页 |
| 测试账号拦截 | 正常账号不受影响，测试账号被拦截 | 分别用正常账号与测试账号点击「开启支付」 |
| 文案变更 | 按钮文案变短，需确认中英文均更新 | 切换中 / 英语言查看按钮文案 |
| header 删除 | 确认无其它组件依赖 `pay.title`、`pay.badge.stripeEmbedded` | 全局搜索这两个 i18n key |
