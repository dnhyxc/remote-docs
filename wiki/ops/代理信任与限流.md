# 生产环境 trust proxy 与 rate-limit

> **文档角色**：Nginx 反向代理后 Express **信任 X-Forwarded-For**，修复 `express-rate-limit` 抛错并正确按客户端 IP 限流。  
> **延伸阅读**：[ops/Nginx配置.md](./Nginx配置.md)（部署与反代）、[app/路由认证.md](../auth/路由认证.md)（路由与 HTTPS）。

若与仓库最新源码不一致，**以源码为准**。

---

## 1. 背景与目标

**现象**：生产环境 Nest 启动或请求时日志出现 `ERR_ERL_UNEXPECTED_X_FORWARDED_FOR`（express-rate-limit 检测到 `X-Forwarded-For` 但未设置 `trust proxy`）。

**目标**：仅在 `NODE_ENV === 'production'` 启用 `trust proxy`；rate-limit 使用标准 `RateLimit-*` 响应头。

## 3. 关键代码与注释

**来源**：`apps/backend/src/main.ts`（bootstrap 内 rate-limit 之前，约 L55–L68）

```typescript
// nginx 反向代理时需信任 X-Forwarded-*，否则 rate-limit 会抛 ERR_ERL_UNEXPECTED_X_FORWARDED_FOR
if (process.env.NODE_ENV === 'production') {
	app.set('trust proxy', 1); // 说明：信任第一层代理（Nginx），req.ip 取真实客户端 IP
}

app.use(
	rateLimit({
		windowMs: 1 * 60 * 1000,
		max: 300,
		standardHeaders: true,  // 说明：返回 RateLimit-Limit / Remaining 等 RFC 头
		legacyHeaders: false,   // 说明：关闭 X-RateLimit-* 旧头
	}),
);
```

---

## 4. 兼容性与回归

| 维度 | 说明 |
|------|------|
| 本地开发 | 不设 trust proxy，直连 IP 限流 |
| 生产 | 需 Nginx 正确传递 `X-Forwarded-For` |
| 回归 | 生产启动无 ERL 错误；超限返回 429 |
