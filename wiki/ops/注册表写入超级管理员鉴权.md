## 0. 延伸阅读

## 1. 背景与目标

此前「写入插件 registry 等 remotes JSON」接口（PUT `/api/upload/remotes/:filename`）仅通过 `JwtGuard` 做「已登录」校验：任何注册用户拿到有效 Token 后，都可直接覆盖 `plugins-registry.json` 等文件，等价于掌握全部已上架/待上架功能模块的来源清单（含 `iframeUrl`、`routePath`、信任级别等）。与此同时，插件中心页面右上角的「编辑配置」按钮对所有登录用户可见，进一步放大了误触与越权的风险面。

本轮通过以下两项收口把 registry 写入通道限定为「超级管理员」：

1. **后端接口硬鉴权**：写接口在 `JwtGuard` 之上追加 `UserService.userHasSuperAdminRole(userId)` 判定；未登录抛 `401 Unauthorized`，非超级管理员抛 `403 Forbidden`。
2. **前端入口隐藏**：插件中心「编辑配置」按钮通过 `useIsSuperAdmin()` 取当前登录角色，只有超级管理员会看到；后端仍是最终信任边界。

## 3. 实现思路

### 3.1 角色判定逻辑前后端对齐

后端 `UserService.userHasSuperAdminRole(userId)` 以 `roles` 关联表为准：任一 role `id === 1` **或** `name === '超级管理员'` 即视为超级管理员。

前端 `checkIsSuperAdmin(userInfo)` 严格沿用同一条判定键：
- 角色 `id === 1`（数据库主键，最稳）
- 或角色 `name === '超级管理员'` / `'Super Admin'`（中英双语兜底）

前后端共享同一套真值表，避免「A 端算出来是管理员、B 端不算」导致按钮闪烁或 403 驳回。

### 3.2 后端接口分层防御（3 层）

| 层 | 机制 | 异常 |
| --- | --- | --- |
| L1 | `JwtGuard`（NestJS Guard）：未带 Token / Token 无效在进入 Controller 前被拦截 | 401（由 Guard 标准返回） |
| L2 | Controller 内部取 `req.user?.userId`：JWT 解析成功但对象缺 `userId` 时主动抛 | `UnauthorizedException('未授权')` → 401 |
| L3 | `userHasSuperAdminRole(userId)` 落库查 roles：不是管理员时明确抛 | `ForbiddenException('需要超级管理员权限')` → 403 |

L2 不是冗余：JWT payload 结构如被改写 / 版本错位可能出现空对象，需要兜底。

### 3.3 前端「看不见 ≠ 安全」

按钮隐藏只用于**降低误触**，不承担安全角色。后端 L1–L3 始终独立判定。即使用户手动拼 URL 进入 `/plugins/registry`，保存时仍会被 `PUT /api/upload/remotes/plugins-registry.json` 的 `ForbiddenException` 拦回。

### 3.4 依赖注入选择构造器

本轮把 `UserService` 通过 Controller 构造器注入（标准 NestJS 依赖注入），避免在方法体内直接查 TypeORM 让测试耦合度升高。因该类此前无自定义构造器，等价于首次引入依赖；无循环依赖风险（upload 模块 → user 模块单向）。

### 3.5 `@Req()` 而非 `@Request()` 别名

`@Req()` + Express `Request` 类型扩展 `{ user?: { userId?: number } }` 为 `AuthedRequest`，语义清晰；不引入 `@nestjs/common` 的 `Request` 对象包装层。

```typescript
// 以 Node 同步写入 API 落盘 JSON 文本
import { writeFileSync } from 'node:fs';
// 拼接绝对路径用
import { join } from 'node:path';
// NestJS 路由与 HTTP 层装饰器
import {
        // 接收 JSON 请求体
        Body,
        // 控制器装饰器：路由前缀
        Controller,
        // HTTP 通用异常（本类 BAD_REQUEST / INTERNAL_SERVER_ERROR）
        HttpException,
        // HTTP 状态码常量
        HttpStatus,
        // 读取 URL 路径参数 filename
        Param,
        // 路由动词：全量替换写文件
        Put,
        // 认证守卫：需要 JWT
        UseGuards,
        // 统一响应格式（{code, data, message} 包装）
        UseInterceptors,
} from '@nestjs/common';
// JwtGuard：从 Authorization: Bearer <token> 解析并挂载 req.user
import { JwtGuard } from '../../guards/jwt.guard';
// ResponseInterceptor：把返回值包裹到统一数据结构
import { ResponseInterceptor } from '../../interceptors/response.interceptor';
// uploads 目录保障 + remotes 根路径解析工具
import { ensureUploadDir, getUploadRemotesDir } from '../../utils/upload-paths';

// 写接口请求体：只有 content 一个可选字符串字段（JSON 文本）
type PutRemoteBody = {
        /** 完整 JSON 文本（将写入 uploads/remotes/:filename） */
        content?: string;
};

/**
 * 写入插件 registry 等 remotes JSON（需登录）。
 * 与公开 GET /api/upload/remotes/:filename、静态 /remotes/ 对应。
 */
// 控制器统一前缀 /upload
@Controller('upload')
// 统一响应包裹
@UseInterceptors(ResponseInterceptor)
// 所有路由需要 JWT；本轮仅验证「登录」，不区分角色
@UseGuards(JwtGuard)
export class UploadRemotesWriteController {
        // PUT /upload/remotes/:filename 方法签名
        @Put('remotes/:filename')
        // 无显式构造器 → 使用默认空构造；方法参数：路径文件名 + JSON body
        putRemote(@Param('filename') filename: string, @Body() body: PutRemoteBody) {
                // 文件名判空 + 路径穿越 / 子目录 3 连黑名单（.. / / \）
                if (
                        !filename ||
                        filename.includes('..') ||
                        filename.includes('/') ||
                        filename.includes('\\')
                ) {
                        // 命中任一即 400 拒绝
                        throw new HttpException('非法文件名', HttpStatus.BAD_REQUEST);
                }
                // 仅放行 .json 后缀，防止 remotes 目录被当成任意写桶
                if (!filename.toLowerCase().endsWith('.json')) {
                        // 非 json 后缀一律 400
                        throw new HttpException('仅支持 .json', HttpStatus.BAD_REQUEST);
                }

                // 把请求体 content 归一化为字符串（空对象视为空串）
                const content = typeof body?.content === 'string' ? body.content : '';
                // 空串或全空白内容不允许写入
                if (!content.trim()) {
                        // 400：缺少 JSON 正文
                        throw new HttpException('content 不能为空', HttpStatus.BAD_REQUEST);
                }

                // 解析 JSON 到中间变量，失败即报错
                let parsed: unknown;
                try {
                        // 使用全局 JSON.parse
                        parsed = JSON.parse(content);
                } catch {
                        // catch 中直接抛 400
                        throw new HttpException('JSON 解析失败', HttpStatus.BAD_REQUEST);
                }

                // 如果目标文件名是 plugins-registry.json，再做一次结构最低要求校验
                if (
                        filename === 'plugins-registry.json' &&
                        (!parsed ||
                                typeof parsed !== 'object' ||
                                // plugins 数组必须存在
                                !Array.isArray((parsed as { plugins?: unknown }).plugins))
                ) {
                        // 结构不合时 400
                        throw new HttpException(
                                'plugins-registry.json 须含 plugins 数组',
                                HttpStatus.BAD_REQUEST,
                        );
                }

                // 获取 uploads/remotes 绝对根目录
                const remotesDir = getUploadRemotesDir();
                // 若目录不存在则递归创建
                ensureUploadDir(remotesDir);
                // 拼出目标 JSON 文件绝对路径
                const absolutePath = join(remotesDir, filename);
                // 用 4 空格制表缩进重写 JSON，末尾强制换行对齐 POSIX 文本文件
                const pretty = `${JSON.stringify(parsed, null, '\t')}\n`;
                try {
                        // 同步写入（简单、写入量小，无性能压力）
                        writeFileSync(absolutePath, pretty, 'utf8');
                } catch (e) {
                        // 如权限/磁盘满等错误包装为 500 返回
                        throw new HttpException(
                                e instanceof Error ? e.message : '写入失败',
                                HttpStatus.INTERNAL_SERVER_ERROR,
                        );
                }

                // 返回文件名与静态路由路径，前端可直接重新拉取 /remotes/:filename
                return { filename, path: `/remotes/${filename}` };
        }
}
```

### 4.2 `userHasSuperAdminRole`（`apps/backend/src/services/user/user.service.ts`）

**说明**：本方法定义在本轮并未改动；仅作上下文展示，与 `UploadRemotesWriteController` 的新调用点及前端 `checkIsSuperAdmin` 形成三方对照。

`apps/backend/src/services/user/user.service.ts`（当前源码，约 L133–L140）

```typescript
// 异步判定某 userId 是否拥有超级管理员角色；供 Controller、Config、English 等服务复用
async userHasSuperAdminRole(userId: number): Promise<boolean> {
        // UserRepository.findOne 带 roles 关联，一次查询拉回主表 + 角色表
        const user = await this.userRepository.findOne({
                // 主键过滤：按 userId 精确匹配
                where: { id: userId },
                // 必须声明 relations: ['roles'] 才能拿到关联数组，否则 roles 为 undefined
                relations: ['roles'],
        });
        // 无用户或 roles 为空，直接视为非管理员
        if (!user?.roles?.length) return false;
        // 任一角色命中 id=1（预置主键）或 name='超级管理员' 即通过
        return user.roles.some((r) => r.id === 1 || r.name === '超级管理员');
}
```

`apps/frontend/src/hooks/useIsSuperAdmin.ts`（当前源码，约 L1–L46）

```typescript
// React Hooks：useEffect 挂载/清理事件，useState 保存 userInfo 快照
import { useEffect, useState } from 'react';
// localStorage 中 userInfo 读写键名（与登录模块一致）
import { USER_INFO_STORAGE_KEY } from '@/store/loggedInUserId';

// 前端轻量角色结构：与后端 roles 表字段子集对齐
type UserRoleLike = { id?: number; name?: string };

// 前端 userInfo 对象结构：登录成功后写入 localStorage 的那份 JSON
type UserInfoLike = {
        // 用户主键 ID（数字）
        id?: number;
        // 角色数组；可为 null 或缺失
        roles?: UserRoleLike[] | null;
};

// 封装 localStorage JSON 读取；SSR 不存在 window 时返回 {} 避免抛
const readUserInfoJson = () => {
        // 浏览器环境判空（Tauri/桌面端也走此分支；SSR/Node 则安全）
        if (typeof window === 'undefined') return '{}';
        // 键不存在则兜底空对象字符串，保证 JSON.parse 总能成功
        return localStorage.getItem(USER_INFO_STORAGE_KEY) || '{}';
};

/** 根据 userInfo 判断是否超级管理员（与后端 userHasSuperAdminRole 对齐） */
// 独立导出纯函数，便于非组件场景（路由守卫、拦截器、unit test）直接调用
export function checkIsSuperAdmin(
        // 可空 userInfo 入参：组件/存储/接口拿到即可
        userInfo: UserInfoLike | null | undefined,
): boolean {
        // ID 必须是正数；避免对象转 Number 成 NaN 或 0 等边角
        const id = Number(userInfo?.id);
        // 非有限正数直接否
        if (!Number.isFinite(id) || id <= 0) return false;
        // 安全读取 roles 数组引用
        const roles = userInfo?.roles;
        // 非数组/空数组视为无角色
        if (!Array.isArray(roles) || roles.length === 0) return false;
        // 同后端真值表：id=1 或 中文名「超级管理员」或英文「Super Admin」均通过
        return roles.some(
                (r) => r?.id === 1 || r?.name === '超级管理员' || r?.name === 'Super Admin',
        );
}

/** 当前登录用户是否为超级管理员（随 userInfo 变更自动更新） */
// React Hook 形式：返回布尔；组件挂载即读本地，登出/换号后自动重算
export function useIsSuperAdmin(): boolean {
        // 本地 JSON 解析为 userInfo 快照；首次渲染立即有值（无闪烁）
        const [userInfo, setUserInfo] = useState(() =>
                JSON.parse(readUserInfoJson()),
        );

        // 挂载时监听跨标签页/登录事件
        useEffect(() => {
                // 事件回调：重读取 JSON 并刷新 state
                const sync = () => setUserInfo(JSON.parse(readUserInfoJson()));
                // 原生 storage 事件：多 Tab 场景其他页改变 userInfo
                window.addEventListener('storage', sync);
                // 业务自定义 userInfoChanged：登录流程、换号、登出结束主动 dispatch
                window.addEventListener('userInfoChanged', sync);
                // 卸载清理：移除两个监听，避免内存泄漏
                return () => {
                        window.removeEventListener('storage', sync);
                        window.removeEventListener('userInfoChanged', sync);
                };
                // 空依赖数组：只挂载一次
        }, []);

        // 基于最新 userInfo 跑纯判定
        return checkIsSuperAdmin(userInfo);
}
```

## 5. 行为变化与兼容性

| 场景 | 旧行为 | 新行为 |
| ---- | ---- | ---- |
| 任意登录用户发 `PUT /api/upload/remotes/plugins-registry.json` | 通过 JwtGuard 后写入成功 | 非超级管理员返回 **403** `需要超级管理员权限` |
| Token 合法但 `user` 为空 / 缺 `userId` | 直接进入写入逻辑（旧版不用 userId，无报错） | 返回 **401** `未授权` |
| 插件中心页面「编辑配置」按钮 | 所有登录用户可见 | 仅超级管理员可见 |
| 手动拼 URL 访问 `/plugins/registry` | 可进入并保存（JWT 即可） | 可进入，但保存时后端 403 拒绝 |

**向下兼容**：超级管理员（role id=1 / name=超级管理员）体验不变。普通用户看不到按钮且后端 403，属于预期安全加固，非破坏性变更。

**权限前提**：部署时须保证 `upload` 模块能解析 `UserService` 注入（NestJS Module Import 链须包含 `UserModule`；若项目使用 `forwardRef` 则保持已有配置即可，不新增环形依赖）。

## 6. 测试与回归建议

- **403 主路径**：用非管理员账号登录，调 `PUT /api/upload/remotes/plugins-registry.json`，期望返回体含 `需要超级管理员权限`、磁盘文件无改动。
- **401 主路径**：篡改 JWT payload 去掉 `userId`，调 PUT，期望返回 `未授权`。
- **200 正路径**：管理员保存 plugins-registry.json，期望 `/remotes/plugins-registry.json` 内容更新、返回 `{filename, path}` 结构。
- **前端 UI**：非管理员登录插件中心，右上角无「编辑配置」按钮；管理员登录能看到并可跳转 registry 编辑页。
- **登录/登出重算**：管理员登出 → 按钮消失；普通用户切号为管理员 → 按钮自动出现（通过 `userInfoChanged` 事件确认）。
- **回归面**：`UserService.userHasSuperAdminRole` 其它调用方（英语学习、LLM 配置等）行为保持一致；本轮未改方法体，不应影响其它权限入口。
