# 知识库列表与回收站：按文档标题搜索

> 本文说明「在知识库列表抽屉与回收站抽屉中，用户可按文档名称输入关键字，回车后过滤云端 / 本地 / 回收站结果，并对大小写不敏感」这一功能的完整实现，含改动前 / 改动后成对源码与逐行中文注释。
>
> 若与仓库最新源码不一致，以源码为准。

---

## 1. 功能与数据流总览

用户在**知识库列表抽屉**（`KnowledgeList`）顶部的搜索框中输入标题关键字，按 **Enter** 后：

- **云端模式**：把已提交的关键字（`appliedQuery`）通过 `knowledgeStore.refreshList(title)` 传到后端，后端 `KnowledgeService.findPage` 对 `title` 列做 `LOWER(k.title) LIKE :title`，大小写不敏感模糊匹配。
- **本地文件夹模式**：不请求后端，而是在前端对 `localList` 的 `title` 做 `includes(titleQueryNorm)`（同样 `toLowerCase()` 归一化），重新构建本地树；对匹配结果调用 `collectLocalMdDirPaths` 把匹配到的所有目录路径一次性加入 `expandedDirs`，让用户直接看到命中的文件，不必手动一层层展开。

用户在**回收站抽屉**（`KnowledgeTrashList`）顶部输入关键字，按 Enter 后：

- 走同一套「输入态 `titleQuery` → 回车后写 `appliedQuery` → 调 Store → 后端 `KnowledgeService.findTrashPage` 使用同样的 `LOWER()` + `Raw()` 大小写不敏感规则」。

输入框与空态文案均通过中英双语 i18n key 驱动。

const localTree = useMemo(() => {
  // 根目录：用户自定义根为空时回退默认知识库目录
  const root = localFolderPath.trim() || TAURI_KNOWLEDGE_DIR;
  // 从 Store 本地列表中，筛出确实有本地绝对路径的条目（排除已解关联的脏数据）
  const entries = localList
    .filter((i) => !!i.localAbsolutePath)
    // 把 KnowledgeListItem 转成 buildLocalMdTree 需要的 entry 形状
    .map((i) => ({
      // 本地绝对路径；已知非空，非空断言消除 TS 严格模式报错
      path: i.localAbsolutePath!,
      // 展示标题：优先条目自身标题；否则取文件名末段；再不然空串
      title:
        i.title?.trim() || i.localAbsolutePath!.split(/[/\\]/).pop() || '',
      // 更新时间：ISO 字符串；没给就空串防止 formatDate 崩
      updatedAt: i.updatedAt?.toString() ?? '',
    }))
    // 搜索态下只保留标题命中的文件：先把两侧都 toLowerCase，做到大小写不敏感
    .filter((e) =>
      searching ? e.title.toLowerCase().includes(titleQueryNorm) : true,
    );
  // 调用树构造函数：入口扁平化 entries → 目录/文件树
  return buildLocalMdTree(root, entries);
  // 依赖多了 searching 与 titleQueryNorm：只要已提交的查询有变化，立即重算本地树
}, [localFolderPath, localList, searching, titleQueryNorm]);

// 回车提交搜索：写 appliedQuery；本地模式下顺带一次性展开所有命中目录
const submitTitleSearch = useCallback(() => {
  // 第一步：把输入框中的内容同步到「已提交」状态，其它派生值据此重算
  setAppliedQuery(titleQuery);
  // 本地模式下不走后端：纯前端过滤 + 自动展开
  if (useLocalFolder) {
    // 归一化查询串：trim + toLowerCase，与 localTree 里的规则保持一致
    const q = titleQuery.trim().toLowerCase();
    // 空查询不需要额外处理（直接 return 让上面的 setAppliedQuery 清空搜索态即可）
    if (!q) return;
    // 回车搜索时先展开匹配树，之后折叠由 expandedDirs 控制
    // 重新取根目录（与 localTree 同源）
    const root = localFolderPath.trim() || TAURI_KNOWLEDGE_DIR;
    // 用完全相同的 map + filter 规则，得到一个「仅含命中文件」的临时 entries
    const entries = localList
      .filter((i) => !!i.localAbsolutePath)
      .map((i) => ({
        path: i.localAbsolutePath!,
        title:
          i.title?.trim() ||
          i.localAbsolutePath!.split(/[/\\]/).pop() ||
          '',
        updatedAt: i.updatedAt?.toString() ?? '',
      }))
      // 仅保留标题（小写后）包含查询串（小写后）的条目
      .filter((e) => e.title.toLowerCase().includes(q));
    // 关键：构建出「命中文件的树」，再把该树上所有目录的 path 收集出来
    // 并一次性塞进 expandedDirs，使得用户立刻可见所有命中行，无需手动逐层展开
    setExpandedDirs(
      new Set(collectLocalMdDirPaths(buildLocalMdTree(root, entries))),
    );
    // 本地分支结束；return 避免走到下面的云端逻辑
    return;
  }
  // 云端分支：仅在 allowCloudList 为真时请求后端拉当前已提交关键词的分页
  if (allowCloudList) {
    // 注意传的是 titleQuery（未规范化的用户原始串），规范化在后端完成
    void knowledgeStore.refreshList(titleQuery);
  }
  // useCallback 依赖：所有外部读取的变量都显式列出，保证闭包新鲜
}, [
  // 用户键入中的查询文本
  titleQuery,
  // 当前是否处于本地文件夹模式；决定走本地还是云分支
  useLocalFolder,
  // 本地根目录（仅本地模式下使用）
  localFolderPath,
  // 本地扁平文件列表（仅本地模式下使用）
  localList,
  // 是否允许云端列表；未登录时为 false，避免 401
  allowCloudList,
  // 知识库 MobX store：云端刷新列表靠它
  knowledgeStore,
]);
```

变更摘要：`localTree` 多一层搜索态 `.filter()`；新增 `submitTitleSearch`，其本地分支会基于命中结果重建 `expandedDirs`，云分支调用 `knowledgeStore.refreshList(titleQuery)`。

/** 收集树上所有目录 path（含根）；搜索时用来一次性展开匹配结果的祖先 */
// 导出函数：入参是某棵本地树的根；返回目录 path 数组（string[]）
export function collectLocalMdDirPaths(root: LocalMdTreeDir): string[] {
  // 结果累加器：最终按前序把所有目录 path 塞进这里
  const out: string[] = [];
  // 内部 DFS 递归函数：参数类型显式标为 LocalMdTreeDir，避免传 file
  const walk = (dir: LocalMdTreeDir) => {
    // 先序：把当前目录自己的 path 加入结果（根也会被包含进来，expandedDirs 包含根不影响渲染）
    out.push(dir.path);
    // 遍历当前目录的所有子节点
    for (const c of dir.children) {
      // 只对类型为 dir 的子节点继续递归；file 没有子节点，忽略
      if (c.type === 'dir') walk(c);
    }
  };
  // 从根节点开始启动 DFS
  walk(root);
  // 返回收集到的目录 path 数组；调用方一般会直接包一层 new Set(...) 作为 expandedDirs
  return out;
}
```

变更摘要：新增一个纯函数工具，用于在本地模式「回车搜索命中若干文件」时，把命中树的所有目录 path 取出，一次性放到 `expandedDirs`，让用户直接看到所有命中的文件行。

  const pageNo = query.pageNo ?? 1;
  const pageSize = query.pageSize ?? 10;

**改动后**（`LOWER(k.title) LIKE LOWER(...)` 实现大小写不敏感）：

```ts
// 分页列表：本人条目 + 他人公开条目；默认按更新时间倒序
async findPage(
  userId: number,
  query: QueryKnowledgeDto,
): Promise<{ list: KnowledgeListItem[]; total: number }> {
  // 分页参数：pageNo 缺省为 1（第一页）
  const pageNo = query.pageNo ?? 1;
  // 分页参数：pageSize 缺省为 10（与前端默认一致）
  const pageSize = query.pageSize ?? 10;
  // TypeORM take：实际 LIMIT
  const take = pageSize;
  // TypeORM skip：实际 OFFSET
  const skip = (pageNo - 1) * take;
  // DTO 里的 title 两端空白不算有效搜索
  const title = query.title?.trim();

  const qb = this.knowledgeRepository
    .createQueryBuilder('k')
    .select([
      'k.id',
      'k.title',
      'k.author',
      'k.authorId',
      'k.isPublic',
      'k.createdAt',
      'k.updatedAt',
    ])
    // 可见性：自己的 + 别人公开的 都能查
    .where('(k.authorId = :userId OR k.isPublic = true)', { userId })
    // 最近更新在前
    .orderBy('k.updatedAt', 'DESC')
    .take(take)
    .skip(skip);

  // title 有值时用 LOWER 做大小写不敏感匹配：两端都 toLowerCase 保证语义一致
  if (title) {
    // 列侧 LOWER(k.title)：把数据库列值转成小写再比
    qb.andWhere('LOWER(k.title) LIKE :title', {
      // 参数侧也 toLowerCase：用户输入的 ABC 会变成 %abc%，与列侧小写匹配
      title: `%${title.toLowerCase()}%`,
    });
  }

  const [rows, total] = await qb.getManyAndCount();
  return {
    list: rows.map((row) => this.toListItem(row, userId)),
    total,
  };
}
```

```ts
// 回收站分页列表；默认按删除时间倒序
async findTrashPage(
  query: QueryKnowledgeTrashDto,
): Promise<{ list: KnowledgeTrashListItem[]; total: number }> {
  // 页码：没传默认第一页
  const pageNo = query.pageNo ?? 1;
  // 每页条数：没传默认 10
  const pageSize = query.pageSize ?? 10;
  // take / skip 与 findPage 对齐
  const take = pageSize;
  const skip = (pageNo - 1) * take;
  // 两端 trim：空白字符串不算搜索
  const title = query.title?.trim();
  // 回收站按作者隔离：必须是本人的条目才进入列表
  const authorId = query.authorId;

  const where: Record<string, unknown> = {};
  // 有 title 时改用 Raw 写原生 SQL，保证不依赖数据库 collation 的大小写规则
  if (title) {
    // Raw 接收 (alias) => `LOWER(${alias}) LIKE :title`：alias 会被 TypeORM 替换成正确的列别名
    // 同时第二个参数对象中传入绑定值，避免 SQL 注入
    where.title = Raw(
      (alias) => `LOWER(${alias}) LIKE :title`,
      // 参数值与 findPage 一样做 toLowerCase，% 包裹保证模糊匹配
      { title: `%${title.toLowerCase()}%` },
    );
  }
  // authorId 精确过滤（与改前一致）
  if (authorId != null) where.authorId = authorId;

  const [list, total] = await this.knowledgeTrashRepository.findAndCount({
    // 只取前端需要的字段：减少不必要的数据传输
    select: {
      id: true,
      originalId: true,
      title: true,
      author: true,
      authorId: true,
      deletedAt: true,
    },
    // 组装好的 where（title 可能是 Raw，authorId 可能是 number）
    where,
    // 最近删除的排前面
    order: { deletedAt: 'DESC' },
    take,
    skip,
  });
  return { list, total };
}
```

变更摘要：去掉对 TypeORM `Like` 的使用；知识库主列表用 QueryBuilder 手动拼 `LOWER(k.title) LIKE :title`，回收站查询对象用 `Raw` 写等价原生 SQL 片段；两者都在参数侧也 `toLowerCase()` 包裹 `%%`，保证前后端大小写归一一致。
