## 1. 背景与目标

### 1.1 问题

桌面端（Tauri）知识库的**本地文件夹模式**下，列表行 hover 时已有「在 Cursor / Trae 中打开」按钮，但用户经常需要**在系统文件管理器中定位该文件**（macOS 访达 / Windows 资源管理器），以便：

1. 快速确认文件在磁盘上的物理位置。
2. 用其它工具（如 IDE、终端）打开同一目录。
3. 拖拽文件到其它应用。

此前用户必须先记住本地文件夹根路径，再手动在访达中层层点入——体验割裂。

### 1.2 目标

1. **新增 `revealItemInDir` 工具函数**：封装 Tauri `plugin:opener|reveal_item_in_dir` 命令，在系统文件管理器中选中并显示指定文件。
2. **知识列表行新增「在访达中显示」按钮**：位于「在编辑器中打开」按钮左侧，仅桌面端 + 本地文件可见。
3. **重构 `actionCount` 与 `hoverPr` 逻辑**：原 if-else 链硬编码 4 种按钮；新增第 5 种按钮后改用数组 + 查表，避免嵌套三元式失控。
4. **国际化**：中英文新增 `revealInFolder` / `revealInFolderFailed` 两条翻译。

## 3. 实现思路与架构方案

### 3.1 整体架构

```
用户 hover 本地 .md 列表行
  │
  ├─ KnowledgeListRow 组件
  │   ├─ showReveal = showRevealInFolder && item.localAbsolutePath && onRevealInFolderClick
  │   ├─ actionCount = [showReveal, showOpenEditor, showVisibility, showCategory, showTrash].filter(Boolean).length
  │   ├─ hoverPr = ROW_HOVER_PR[min(actionCount, 4)]   ← 查表，最多 5 档
  │   └─ JSX: {showReveal ? <Tooltip><button onClick={onRevealInFolderClick}><FolderSearch/></button></Tooltip> : null}
  │
  └─ onRevealInFolderClick callback (KnowledgeList 主组件)
      └─ revealItemInDir(item.localAbsolutePath)
          └─ Tauri invoke('plugin:opener|reveal_item_in_dir', { paths: [path] })
              └─ macOS: 访达打开并选中文件
              └─ Windows: 资源管理器打开并选中文件
              └─ 非 Tauri: 短路返回（no-op）
```

### 3.2 关键决策

1. **`revealItemInDir` 放在 `open-external.ts` 而非独立文件**：与 `openExternalUrl` 同属「打开外部应用」语义，共用 `isTauriRuntime` 判断与 dynamic import 模式，内聚性高。
2. **Tauri `plugin:opener|reveal_item_in_dir` 而非 Rust 自定义命令**：Tauri 官方 `opener` 插件已封装了跨平台（macOS `NSWorkspace` / Windows `Explorer.exe`）的文件选中逻辑，无需自写 Rust。
3. **`ROW_HOVER_PR` 查表替代 if-else 链**：原 4 档按钮的嵌套三元式已达 4 层，再加第 5 档可读性崩溃。改为数组索引 `ROW_HOVER_PR[Math.min(actionCount, ROW_HOVER_PR.length - 1)]`，新增按钮只需在数组加一项。
4. **按钮位于「编辑器打开」左侧**：reveal 属于「定位文件」语义，editor 属于「编辑文件」语义，定位先于编辑，符合从左到右的操作流。
5. **`showRevealInFolder={isTauriRuntime()}`**：与 `showOpenInExternalEditor` 一样仅桌面端可见，Web 端无系统文件管理器。

```typescript
/**
 * 在系统文件管理器中选中并显示文件（macOS 访达 / Windows 资源管理器）。仅 Tauri 可用。
 */
// 导出异步函数：参数为文件绝对路径，返回 Promise<void>
export async function revealItemInDir(path: string): Promise<void> {
	// 空路径或非 Tauri 环境直接短路返回（Web 端无系统文件管理器）
	if (!path || !isTauriRuntime()) return;
	// 动态 import Tauri core 模块的 invoke 函数（与 openExternalUrl 一致，避免 HMR 504）
	const { invoke } = await import('@tauri-apps/api/core');
	// 调用 Tauri opener 插件的 reveal_item_in_dir 命令，传入单元素路径数组
	await invoke('plugin:opener|reveal_item_in_dir', { paths: [path] });
}
```

## 5. 兼容性与影响

### 5.1 行为变化

| 场景 | 改动前 | 改动后 |
| --- | --- | --- |
| 桌面端本地列表行 hover | 最多 4 个操作按钮 | 最多 5 个操作按钮（新增访达显示） |
| 桌面端点击「在访达中显示」 | 不存在 | 调 Tauri opener，访达/资源管理器打开并选中文件 |
| Web 端本地列表行 hover | 无本地文件（Web 端无本地文件夹模式） | 无变化（`showRevealInFolder={isTauriRuntime()}` 短路 false） |
| 标题 hover 右侧 padding | 4 档（0/8/14/22/30） | 5 档不变（数组长度 5，`Math.min` 防越界） |
| `actionCount` 计算方式 | 三元式逐项累加 | 数组 `.filter(Boolean).length`（行为等价） |

### 5.2 风险与回归

- **Tauri opener 插件权限**：`reveal_item_in_dir` 需 capabilities 中含 `core:opener:allow-reveal-item-in-dir` 权限；若缺失则 invoke 抛错，由 catch 弹 Toast。
- **macOS 访达已打开**：若访达已打开但未选中目标文件，`reveal_item_in_dir` 会新开一个访达窗口选中该文件；属 Tauri opener 插件行为，非本代码可控。
- **路径含空格/中文**：Tauri opener 插件内部处理路径转义，前端无需额外编码。
- **`ROW_HOVER_PR` 数组长度**：当前 5 档（0~4+），若未来新增第 6 种按钮需同步追加 `group-hover:pr-38` 等更大档位。
- **回归测试**：桌面端本地文件夹模式下，hover 列表行确认 5 按钮均可见且 padding 正确；点击访达按钮确认访达打开并选中文件；Web 端确认无访达按钮。
