# 公开优先排序

## 1. 背景与目标

知识库与电子书架均支持「本人条目 + 他人公开条目」混排展示。改造前列表只按更新时间倒序排列，公开与私有混排，公开条目无法被快速识别。

本轮改动统一了两个域的列表排序行为：**公开条目排在前面，组内保持原有相对顺序（稳定排序）**。同时为电子书补一条守卫：**非本人书架/他人公开书不可改分类**，避免公开条目被错误调用分类 API 后破坏排序与归属一致性。

- 知识库：后端 SQL 与前端内存排序双层对齐「公开优先」。
- 电子书：后端 SQL、前端内存排序、UI 入口守卫三层对齐。
- 兼容旧数据：仅改变显示顺序，不写库、不改 ID。

## 2. 改动范围

- `apps/backend/src/services/knowledge/knowledge.service.ts` — `findPage` 排序键。
- `apps/backend/src/services/ebook/ebook.service.ts` — `getShelf` 排序键。
- `apps/frontend/src/store/knowledge.ts` — 新增 `sortKnowledgeByPublic`；`setItemVisibility` 调用排序。
- `apps/frontend/src/store/ebook.ts` — `sortBooksByLastRead` 增公开优先；`setBookPublic` 调用排序；`assignBookCategory` 增 owner 守卫。
- `apps/frontend/src/views/ebook/components/shelf/EbookShelfBookCard.tsx` — `showMoveCategory` 收紧可见条件。

## 3. 实现思路

1. **排序键前置 `isPublic`**：SQL 层把 `isPublic DESC` 作为第一排序键，`updatedAt DESC`/`shelf_sort DESC` 作为第二排序键。`isPublic` 为布尔列，`DESC` 让 `true` 排前，无需额外表达式。
2. **稳定排序**：组内第二排序键沿用旧键（更新时间 / 最近阅读），且 SQL 默认稳定，保证组内相对顺序不变。
3. **前端内存层复算**：本地更新单条 `isPublic` 后，仅 map 替换该条不够，必须再整体 `sort` 一次，否则该条位置不会随公开态变化而移动。
4. **电子书组内键复用 `shelf_sort`**：`shelf_sort` 是「阅读进度时间 → 否则创建时间」的派生列，保持与旧实现一致的最近阅读语义。
5. **`owner` 作为公开书标识**：他人公开书在 `toBookDtoWithOwner` 注入 `owner`，前端排序与守卫统一用 `!!book.owner` 判定是否他人公开书。
6. **UI 守卫前置**：`showMoveCategory` 收紧到 `canManage && !book.owner`，让分类移动按钮在公开书架/他人公开书上根本不渲染，避免误触；Store 层 `assignBookCategory` 再加 `owner` 早返回兜底。
7. **不引入新字段**：复用既有 `isPublic`/`owner`/`categoryId`，不动表结构、不动 DTO 必填项。

```typescript
// 公开文档优先，组内保持原相对顺序（稳定排序）
function sortKnowledgeByPublic(
	// 待排序列表
	list: KnowledgeListItem[],
): KnowledgeListItem[] {
	// 复制新数组再排序，避免原地变更 MobX observable
	return [...list].sort((a, b) => {
		// a 公开时得 1，否则 0
		const aPublic = a.isPublic ? 1 : 0;
		// b 公开时得 1，否则 0
		const bPublic = b.isPublic ? 1 : 0;
		// DESC：bPublic - aPublic，正值表示 b 应在前，即公开优先
		return bPublic - aPublic;
	});
}
```

**变更摘要**：新增稳定排序辅助函数，按 `isPublic` 倒序、组内保持原顺序（`Array.prototype.sort` 在各引擎中稳定）。

```typescript
// 公开书（含他人公开）优先，组内再按最近阅读倒序
function sortBooksByLastRead(
	// 待排序书籍
	books: Book[],
	// 阅读进度映射
	progMap: Record<string, Prog>,
): Book[] {
	// 复制新数组再排序，避免原地变更 MobX observable
	return [...books].sort((a, b) => {
		// a 公开或为他人公开书（有 owner）时得 1，否则 0
		const aPublic = a.isPublic || a.owner ? 1 : 0;
		// b 公开或为他人公开书（有 owner）时得 1，否则 0
		const bPublic = b.isPublic || b.owner ? 1 : 0;
		// 公开态不同时：DESC，公开在前
		if (aPublic !== bPublic) return bPublic - aPublic;
		// 公开态相同时：组内按最近阅读时间倒序
		return bookLastReadMs(b, progMap) - bookLastReadMs(a, progMap);
	});
}
```

**变更摘要**：比较器由单键改为双键：先比 `isPublic || owner`（本人公开或他人公开均算公开），再比 `bookLastReadMs`。

**改动前** · `apps/frontend/src/store/ebook.ts`（`assignBookCategory`，基线）

```typescript
// 修改书籍分类
async assignBookCategory(
	// 目标书 id
	bookId: string,
	// 目标分类 id，null 表示移入未分类
	categoryId: string | null,
): Promise<void> {
	// 直接调后端分类 API（无 owner 守卫，他人公开书也会发请求）
	const updated = await assignEbookBookCategory(bookId, categoryId);
	// MobX 批量更新
	runInAction(() => {
		// 命中条目分类是否仍属当前 Tab
		const stays = this.bookMatchesActiveCategory(updated.categoryId);
		// 命中且仍属当前 Tab：原地替换
		if (stays) {
			this.books = this.books.map((b) => (b.id === bookId ? updated : b));
		} else {
			// 否则从列表移除并扣减总数
			const had = this.books.some((b) => b.id === bookId);
			this.books = this.books.filter((b) => b.id !== bookId);
			// 有命中才扣减，避免负数
			if (had) {
				this.total = Math.max(0, this.safeTotal() - 1);
			}
		}
		// 更新单条缓存
		this.bookCache[bookId] = updated;
		// 若当前 Tab 空了则切回全部
		this.resetActiveCategoryIfEmpty();
	});
	// 刷新分类摘要
	void this.fetchCategories();
}
```

## 5. 兼容性与影响

- **排序改动仅影响显示顺序**：不写库、不改 ID、不改 DTO 必填项；存量数据无需迁移。
- **后端 SQL 与前端内存排序一致**：两端都以 `isPublic DESC` 为第一键，组内键沿用旧键，避免服务端分页与前端重排出现「跳位/抖动」。
- **稳定排序**：`isPublic` 相同的组内，SQL 默认稳定、`Array.prototype.sort` 在现代引擎稳定，相对顺序不变。
- **电子书 `owner` 标识**：他人公开书由后端 `toBookDtoWithOwner` 注入 `owner`；本人书/自己公开书无 `owner`，前端 `a.isPublic || a.owner` 把两类「公开书」都置顶。
- **电子书非本人不可改分类**：
  - UI 层（4.6）：公开书架 Tab 与他人公开书上分类移动按钮不渲染。
  - Store 层（4.5）：即使绕过 UI 直接调 `assignBookCategory`，`owner` 守卫也会早返回，不发请求。
  - 防止他人公开书被错误调用分类 API 后，本地列表因 `stays` 误判而移除条目、扣减总数，破坏公开优先排序的稳定性。
- **回归建议**：
  - 知识库：切换公开/私有后，该条应实时移动到公开/私有组顶；分页加载下一页后顺序仍稳定。
  - 电子书：本人公开书置顶、他人公开书置顶、私有书按最近阅读跟在后面；公开书架 Tab 上无分类移动按钮。
  - 电子书分类：在他人公开书上不应能改分类；在自己公开书上可改分类。
