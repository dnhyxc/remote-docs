# 知识库分类管理

> 本文说明「知识库列表自定义分类」功能的端到端实现：用户可创建 / 重命名 / 删除 / 排序自定义分类、把文档归入分类、按分类标签筛选列表；首次使用时自动播种 5 个默认分类（中英文不同）。文档含改动前 / 改动后成对源码与逐行中文注释。
>
> 若与仓库最新源码不一致，以源码为准。

---

## 1. 背景与目标

知识库列表原先只有「标题模糊 + 分页」一个维度，文档多了之后查找不便。本功能在不破坏既有列表逻辑的前提下，给每用户增加一套**自定义分类**：

- 列表抽屉顶部出现分类标签栏（全部 / 各分类 / 未分类），点击切换筛选维度。
- 行内可把当前文档「移动到」某个分类或移回未分类。
- 弹窗内可新建 / 重命名 / 删除 / 上移下移分类，操作即时生效。
- 首次进入时若该用户还没有任何分类，后端自动播种 5 个默认分类。
- 删除分类时该分类下文档的 `categoryId` 由服务端置空（即归入未分类）。
- 分类对本人文档生效；他人公开文档不可被改分类。
- 本地文件夹模式不显示分类标签栏，避免误导用户对只读本地文件做归档。

## 3. 实现思路（要点）

1. **数据模型**：新增 `knowledge_category` 表，按 `userId + sortOrder` 复合索引；`knowledge` 表新增可空 `category_id` 列。可空保证旧数据自动落入「未分类」，无需数据迁移。
2. **首次播种**：`getCategoriesSummary` 内调用 `ensureDefaultCategories`，若该用户分类计数为 0，则按 `locale`（`zh-CN` / `en-US`）一次性插入 5 条默认分类。前端调用时携带 `locale` 参数。
3. **互斥筛选**：列表查询 DTO 同时存在 `categoryId` 与 `uncategorizedOnly`，但二者**互斥**——服务端在构造 where 时只在两者任一存在时按本人文档过滤；两者都不传时退回原行为（本人 + 公开）。这样公开文档不会被分类筛选误伤。
4. **名称唯一性**：使用 `LOWER(name)` 大小写不敏感比对，避免「Notes」与「notes」并存；空名直接拒绝。
5. **数量上限**：每用户最多 50 个分类，超出直接抛 `BadRequestException`。
6. **删除级联**：删除分类前先把所有 `authorId = userId` 且 `categoryId = 该分类` 的文档 `categoryId` 置空，再做分类删除，避免出现悬挂引用。
7. **排序重排**：`reorderCategories` 接受 `orderedIds` 全量数组；服务端校验「无无效 id」+「长度等于当前用户分类总数」，再以 `index` 写回 `sortOrder`，保证排序幂等。
8. **公开文档保护**：`assignItemCategory` 走 `requireOwned(userId, id)`，非本人文档直接 403/404，无法被改分类。
9. **前端排序**：服务端 `findPage` 改为「`isPublic DESC` 优先 + `updatedAt DESC`」，前端 `setVisibility` 同步增加 `sortKnowledgeByPublic` 稳定排序，保证用户切公开态时本组相对顺序不变。
10. **搜索输入下沉**：把搜索框的草稿态收进独立组件 `KnowledgeSearchInput`，避免每次按键触发父级（含整个列表）重渲导致输入卡顿。
11. **组件复用**：把电子书专用的分类管理弹窗逻辑抽取为通用 `CategoryManageDialog`（只关心 `items` + 4 个回调 + 一组 label），电子书与知识库各自只做薄壳注入。

```typescript
// 从 typeorm 引入实体装饰器、列装饰器、主键、索引、创建/更新时间列
import {
	Column,
	CreateDateColumn,
	Entity,
	Index,
	PrimaryGeneratedColumn,
	UpdateDateColumn,
} from 'typeorm';

// 声明该类映射到 knowledge_category 表
@Entity('knowledge_category')
// 复合索引：按 userId + sortOrder 排序时走索引，避免列表查询扫表
@Index('idx_knowledge_category_user_sort', ['userId', 'sortOrder'])
export class KnowledgeCategory {
	// 主键：UUID 自动生成，对外暴露为 string
	@PrimaryGeneratedColumn('uuid')
	id: string;

	// 所属用户 id，用于隔离不同用户的分类
	@Column({ type: 'int', name: 'user_id' })
	userId: number;

	// 分类名称，长度上限 64
	@Column({ type: 'varchar', length: 64 })
	name: string;

	// 排序序号，默认 0；新建时按 max + 1 写入
	@Column({ type: 'int', name: 'sort_order', default: 0 })
	sortOrder: number;

	// 创建时间戳，由数据库生成
	@CreateDateColumn({ name: 'created_at', type: 'timestamp' })
	createdAt: Date;

	// 更新时间戳，每次 save 自动刷新
	@UpdateDateColumn({ name: 'updated_at', type: 'timestamp' })
	updatedAt: Date;
}
```

**变更摘要**：新增用户级分类实体，作为整条分类链路的存储载体。

```typescript
	// 此时只查本人文档（公开文档不属于任何用户的分类视图）
	qb.where('k.authorId = :userId', { userId });
	if (query.categoryId) {
		// 校验该分类确实属于当前用户，否则抛 BadRequestException
		await this.resolveUserCategoryId(userId, query.categoryId);
		// 按列名 k.category_id 精确匹配
		qb.andWhere('k.category_id = :categoryId', {
			categoryId: query.categoryId,
		});
	} else {
		// 未分类分支：categoryId IS NULL
		qb.andWhere('k.category_id IS NULL');
	}
} else {
	// 默认分支：维持旧版「本人 + 公开」语义
	qb.where('(k.authorId = :userId OR k.isPublic = true)', { userId });
}
```

```typescript
// 归一化分类名：去首尾空白
private normalizeCategoryName(name: string): string {
	// trim 后返回，调用方再做长度判断
	return name.trim();
}

// 校验 categoryId 属于当前用户，并返回该 id；找不到抛 BadRequestException
private async resolveUserCategoryId(
	userId: number,
	categoryId?: string | null,
): Promise<string | null> {
	// 空值直接返回 null，不查库
	if (!categoryId) return null;
	// 按 id + userId 双重确认归属
	const cat = await this.categoryRepo.findOne({
		where: { id: categoryId, userId },
	});
	// 不存在则抛错（可能是越权或被删）
	if (!cat) {
		throw new BadRequestException('分类不存在');
	}
	// 返回校验通过的 id
	return cat.id;
}

// 校验分类名在当前用户下唯一（大小写不敏感）
private async assertCategoryNameUnique(
	userId: number,
	name: string,
	// 重命名场景下排除自身 id
	excludeId?: string,
): Promise<void> {
	// 归一化后再判空
	const normalized = this.normalizeCategoryName(name);
	if (!normalized) {
		// 空名直接拒绝
		throw new BadRequestException('分类名称不能为空');
	}
	// 查询同用户下 LOWER(name) 相同的所有候选
	const rows = await this.categoryRepo
		.createQueryBuilder('c')
		.where('c.user_id = :userId', { userId })
		.andWhere('LOWER(c.name) = LOWER(:name)', { name: normalized })
		.getMany();
	// 排除正在编辑的自身，看是否还有重复
	const dup = rows.find((r) => r.id !== excludeId);
	if (dup) {
		// 重复抛冲突错误
		throw new ConflictException('分类名称已存在');
	}
}

private async ensureDefaultCategories(

	locale?: 'zh-CN' | 'en-US',
): Promise<void> {

	const count = await this.categoryRepo.count({ where: { userId } });
	if (count > 0) return;
	// locale 缺省值视为中文
	const lang = locale === 'en-US' ? 'en-US' : 'zh-CN';

	);
	// 批量写入

}
```

```typescript
	userId: number,
	dto: ReorderKnowledgeCategoriesDto,
): Promise<void> {
	// 拉取当前用户全部分类
	const rows = await this.categoryRepo.find({ where: { userId } });
	// 用 Set 加速校验
	const idSet = new Set(rows.map((r) => r.id));
	// orderedIds 中若包含不属于当前用户的 id，直接拒绝
	if (dto.orderedIds.some((id) => !idSet.has(id))) {
		throw new BadRequestException('orderedIds 包含无效分类');
	}
	// 长度必须等于当前用户分类总数，避免漏排
	if (dto.orderedIds.length !== rows.length) {
		throw new BadRequestException('orderedIds 须包含全部分类');
	}
	// 构造 id -> index 的顺序映射
	const orderMap = new Map(dto.orderedIds.map((id, index) => [id, index]));
	// 给每行写回新的 sortOrder
	for (const row of rows) {
		row.sortOrder = orderMap.get(row.id) ?? row.sortOrder;
	}
	// 批量保存
	await this.categoryRepo.save(rows);
}
```

```typescript
// 上移 / 下移分类
async moveCategory(id: string, direction: 'up' | 'down'): Promise<void> {
	// 找到当前分类在数组中的下标
	const idx = this.categories.findIndex((c) => c.id === id);
	// 找不到直接返回
	if (idx < 0) return;
	// 计算交换目标
	const swapWith = direction === 'up' ? idx - 1 : idx + 1;
	// 越界直接返回
	if (swapWith < 0 || swapWith >= this.categories.length) return;
	// 拷贝数组用于交换
	const ordered = [...this.categories];
	// 经典双变量交换
	const tmp = ordered[idx]!;
	ordered[idx] = ordered[swapWith]!;
	ordered[swapWith] = tmp;
	// 把新顺序的 id 数组传给后端
	await reorderKnowledgeCategories(ordered.map((c) => c.id));
	// 重拉 summary 以拿到准确的 sortOrder
	await this.fetchCategories();
}

// 把某条文档归入 / 移出分类
async assignItemCategory(
	id: string,
	categoryId: string | null,
): Promise<void> {
	// 先在本地列表里找到该文档
	const current = this.list.find((item) => item.id === id);
	// 非本人文档直接返回，不允许改
	if (current && current.isOwned === false) return;
	// 调用 service 拿到最新行
	const updated = await assignKnowledgeItemCategory(id, categoryId);
	// 在 action 内更新视图
	runInAction(() => {
		// 判断该文档在新分类下是否仍应出现在当前 Tab
		const stays = this.itemMatchesActiveCategory(updated.categoryId);
		if (stays) {
			// 留在列表：合并更新对应行
			this.list = this.list.map((item) =>
				item.id === id ? { ...item, ...updated } : item,
			);
		} else {
			// 不在当前 Tab：从列表移除
			const had = this.list.some((item) => item.id === id);
			this.list = this.list.filter((item) => item.id !== id);
			// 同步减总数
			if (had) this.total = Math.max(0, this.total - 1);
		}
		// 列表若空则回退 Tab
		this.resetActiveCategoryIfEmpty();
	});
	// 异步刷新分类计数
	void this.fetchCategories();
}
```

```typescript
	onCommit,
	placeholder,
	className,
```

## 5. 兼容性与影响

- **数据库兼容**：`knowledge.category_id` 列 `nullable=true`，旧数据自动为 `null`（未分类），无需数据迁移脚本。
- **首次播种**：`getCategoriesSummary` 在该用户分类计数为 0 时自动播种 5 个默认分类，前端列表抽屉打开时即触发；既有用户首次访问会看到 5 个默认分类出现。
- **删除级联**：删除分类时该分类下文档 `categoryId` 由服务端置 `null`，自动归入未分类；前端 store 同步把当前列表内对应文档的 `categoryId` 改为 `null`，并刷新 summary 与列表分页。
- **公开文档**：分类仅对本人文档生效，他人公开文档不可被改分类；`assignItemCategory` 走 `requireOwned`，非本人文档直接抛错。`findPage` 在分类 / 未分类过滤时只查本人文档，避免公开文档被误纳入他人分类视图。
- **本地文件夹模式**：不显示分类标签栏与行内赋值 UI，避免对只读本地文件做归档产生混淆。
- **列表排序变化**：`findPage` 与前端 `setVisibility` 均改为「公开优先 + 更新时间倒序」（原仅更新时间倒序）。视觉上：用户切公开态时公开文档仍排前；切本人态时无公开文档影响；切未分类 / 某分类时全是本人文档，组内相对顺序稳定。
- **接口幂等**：`reorderCategories` 要求 `orderedIds` 与当前用户分类总数严格相等，避免部分排序导致数据不一致；多次重排同一顺序不会产生副作用。
- **回归范围**：建议测试——首次播种（中英文 locale 各一次）、新建 / 重命名 / 删除 / 上下移、行内移动到分类与移出未分类、Tab 切换列表过滤、删除分类后列表与计数同步、本地文件夹模式不显示分类、回收站搜索框仍可用。
