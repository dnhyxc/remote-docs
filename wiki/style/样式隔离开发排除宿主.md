## 1. 背景与目标

### 1.1 问题

`styleIsolation.ts` 的 `looksLikeRemoteStyle` 在 Vite 开发模式下靠 `data-vite-dev-id` 属性识别一个 `<style>` 是否来自 Remote（子应用）。旧实现用**白名单正则**匹配 remote 目录名：

```typescript
return /(?:^|[\\/])micro(?:[\\/]|$)|remote-plugins|remote-demo|remote-host/i.test(viteId);
```

这带来两个问题：

1. **每新增 / 重命名一个 `apps/<remote>` 子项目，都要回来改这行正则**。例如 `apps/remote-plugins` 改名为 `apps/micro` 后，必须同步把 `micro` 加进白名单，否则 dev 模式下该子应用的样式不会被 `@scope` 包裹，样式污染主站。
2. **白名单永远滞后于目录结构**。忘记加正则 → dev 模式样式隔离失效 → 开发者排查很久才发现是这里漏了。

### 1.2 目标

把「**白名单 remote 目录名**」改为「**排除 Host 自身**」：

- Host 的 Vite dev 样式（`apps/frontend` 注入的）→ 排除，不认领。
- 其余所有 `apps/<name>` 的 Vite dev 样式 → 在 capture 窗口内一律可认领。
- **新增 / 重命名 `apps/<remote>` 不必再改 `styleIsolation.ts`**。

### 1.3 为什么不直接删掉 viteId 判断

生产构建（MF 打包后）注入的 `<style>` 通常**没有** `data-vite-dev-id`，走的是 `active?.pluginId === ctx.pluginId` 的 capture 窗口认领——这条路径不变。viteId 判断**只影响本地 dev / HMR**，此时 Vite 会给 `<style>` 打上 `data-vite-dev-id`，Host 与 Remote 的样式都带这个属性。如果直接删掉 viteId 判断、全部走 capture 窗口，那么 Host 自身的样式也会在窗口期内被 `@scope` 包裹，导致主站 UI 被错误隔离。因此需要「排除 Host」而非「全部认领」。

## 3. 实现思路

- **由本模块 URL 反推 Host 源码根**：`import.meta.url` 在 dev 模式下指向 `…/apps/frontend/src/plugins/host/styleIsolation.ts`，取路径中最后一次出现 `/apps/frontend` 的位置，截取到该段末尾即得 Host 源码根（如 `/Users/xx/code/dnhyxc-ai/apps/frontend`）。缓存到 `hostViteRootCache` 避免重复计算。
- **三重判断排除 Host**：一个 `data-vite-dev-id` 满足以下任一条件即视为 Host 自身样式，`looksLikeRemoteStyle` 返回 `false`：
  1. id 包含 `hostViteRoot()` 推出的完整路径（最精确，命中 `/Users/xx/…/apps/frontend`）。
  2. id 匹配 `/\/apps\/frontend(?:\/|$)/i`（兜底：路径被截断或符号链接时仍能命中）。
  3. id **不含** `/apps/` 且以 `/src/` 或 `/@id/` 开头——这是 Host Vite 的相对 id 形态；Remote 一般是 `@fs` 绝对路径且含 `apps/<name>`。
- **capture 窗口兜底**：viteId 不为空但不是 Host 样式时，**不再正则匹配 remote 目录名**，而是交给 `active?.pluginId === ctx.pluginId` 的 capture 窗口判断。这与生产构建的行为完全一致，只是 dev 模式下多了一层「排除 Host」的保护。
- **生产不变**：生产构建的 `<style>` 无 `data-vite-dev-id`，`viteId` 为空字符串，直接走 capture 窗口认领，行为与旧版完全相同。
- **回退安全**：`hostViteRoot()` 推导失败（`import.meta.url` 解析异常）时回退到字面量 `/apps/frontend`，仍能靠第 2 条正则兜底。

## 4. 关键代码对比与注释

### 4.1 `hostViteRoot` — 推导 Host 源码根（新增）

**对比范围**：`hostViteRoot` 函数全文（含缓存变量 `hostViteRootCache`）。基线中不存在，属纯新增。

**改动后** · `apps/frontend/src/plugins/host/styleIsolation.ts`（新增，约 L46–L65）

```typescript
// 文档注释：说明本函数用途——由本模块 URL 推导 Host 源码根，避免白名单 remote 目录名
/** Host 源码根（…/apps/frontend），由本模块 URL 推导，避免白名单 remote 目录名 */
// 缓存变量：首次推导后缓存，避免每次调用都解析 URL；null 表示尚未推导
let hostViteRootCache: string | null = null;
// 函数签名：无参数，返回 Host 源码根字符串
function hostViteRoot(): string {
	// 已缓存则直接返回，避免重复解析 import.meta.url
	if (hostViteRootCache != null) return hostViteRootCache;
	// try 块：URL 解析可能抛错（SSR / 非浏览器环境）
	try {
		// 取本模块的完整 URL 路径，decodeURIComponent 处理中文/空格等编码，反斜杠统一为正斜杠
		const path = decodeURIComponent(
			// import.meta.url 在 Vite dev 下指向当前 .ts 文件的 http 路径
			new URL(import.meta.url).pathname.replace(/\\/g, '/'),
		);
		// Host 源码根的固定标记段
		const marker = '/apps/frontend';
		// 在完整路径中最后一次出现标记段的位置（lastIndexOf 避免路径中恰好含 apps/frontend 字样的子串误匹配）
		const idx = path.lastIndexOf(marker);
		// 命中则截取到标记段末尾
		if (idx >= 0) {
			// 截取从路径开头到标记段末尾，得到 Host 源码根（如 /Users/xx/code/dnhyxc-ai/apps/frontend）
			hostViteRootCache = path.slice(0, idx + marker.length);
			// 返回缓存值
			return hostViteRootCache;
		}
	// catch 块：解析异常时忽略，走下方回退
	} catch {
		// 忽略异常
	}
	// 回退：推导失败时用字面量，仍能靠 isHostViteDevStyle 的正则兜底
	hostViteRootCache = '/apps/frontend';
	// 返回回退值
	return hostViteRootCache;
}
```

**变更摘要**：新增 `hostViteRoot` 与缓存变量，通过 `import.meta.url` 反推 `…/apps/frontend`，为 `isHostViteDevStyle` 提供精确的 Host 路径判断依据。

### 4.2 `isHostViteDevStyle` — 判断是否 Host 自身 Vite 样式（新增）

**对比范围**：`isHostViteDevStyle` 函数全文。基线中不存在，属纯新增。

**改动后** · `apps/frontend/src/plugins/host/styleIsolation.ts`（新增，约 L67–L81）

```typescript
// 文档注释：说明本函数用途——只排除 Host，其余 app 在 capture 窗口内均可认领
/**
 * 是否为 Host 自身 Vite 注入的 style（dev）。
 * 只排除 Host；其余 app（micro / remote-demo / 未来新目录）在 capture 窗口内一律可认领。
 */
// 函数签名：接收 viteId（data-vite-dev-id 属性值），返回是否为 Host 样式
function isHostViteDevStyle(viteId: string): boolean {
	// 统一反斜杠为正斜杠，兼容 Windows 路径
	const id = viteId.replace(/\\/g, '/');
	// 取 Host 源码根
	const root = hostViteRoot();
	// 第 1 条：id 包含 Host 源码根完整路径（最精确）
	if (root && id.includes(root)) return true;
	// 第 2 条：兜底正则——id 含 /apps/frontend/ 或以 /apps/frontend 结尾
	if (/\/apps\/frontend(?:\/|$)/i.test(id)) return true;
	// 第 3 条：id 不含 /apps/ 段且以 /src/ 或 /@id/ 开头——Host Vite 相对 id 形态
	// Remote 一般是 @fs 绝对路径且含 apps/<name>，不会命中此条
	if (!/\/apps\//i.test(id) && (/^\/src\//.test(id) || /^\/@id\//.test(id))) {
		// 命中 Host 相对 id，返回 true
		return true;
	}
	// 其余情况不是 Host 样式
	return false;
}
```

**变更摘要**：新增 `isHostViteDevStyle`，通过三重判断（完整路径 / 兜底正则 / 相对 id 形态）识别 Host 自身的 Vite dev 样式，替代旧版白名单 remote 目录正则。

### 4.3 `looksLikeRemoteStyle` — viteId 分支改写

**对比范围**：`looksLikeRemoteStyle` 函数全文（含声明与闭合）。改动集中在 viteId 分支，前两段（`mfStyleOwner` / `HTMLLinkElement`）未变，为保持完整符号边界一并贴出。

**改动前** · `apps/frontend/src/plugins/host/styleIsolation.ts`（基线，约 L46–L66）

```typescript
// 函数签名：判断一个 style/link 元素是否属于当前插件的 Remote 样式
function looksLikeRemoteStyle(
	// 待判断的元素，可能是 style 或 link
	el: HTMLStyleElement | HTMLLinkElement,
	// 当前捕获上下文（插件 id + 入口 origin）
	ctx: CaptureCtx,
// 返回值：是否属于当前插件
): boolean {
	// 1. 已标记元素：检查 data-mf-style-owner 属性（最快路径）
	if (el.dataset.mfStyleOwner) {
		// 直接比对已标记的插件 ID 与当前上下文
		return el.dataset.mfStyleOwner === ctx.pluginId;
	}
	// 2. link 标签：比对 href origin 与插件入口 origin
	if (el instanceof HTMLLinkElement) {
		// 只处理 stylesheet 类型且有 href 的 link
		if (el.rel !== 'stylesheet' || !el.href) return false;
		// try 块：URL 解析可能抛错
		try {
			// 同 origin 则归属于该插件
			return new URL(el.href).origin === ctx.entryOrigin;
		// catch 块：解析失败不认为是远程样式
		} catch {
			// 返回 false
			return false;
		}
	}
	// 3. style 标签：检查 Vite dev 的 data-vite-dev-id 属性
	const viteId = el.getAttribute('data-vite-dev-id') || '';
	// 有 viteId 时用白名单正则匹配 remote 目录名
	if (viteId) {
		// 旧版白名单：匹配 micro / remote-plugins / remote-demo / remote-host
		return /(?:^|[\\/])micro(?:[\\/]|$)|remote-plugins|remote-demo|remote-host/i.test(
			// 传入 viteId 进行匹配
			viteId,
		);
	}
	// 4. 生产无 vite id：仅在主动 capture 窗口内认领
	return active?.pluginId === ctx.pluginId;
}
```

**改动后** · `apps/frontend/src/plugins/host/styleIsolation.ts`（当前，约 L83–L102）

```typescript
// 文档注释：说明判断顺序——已标记 → link origin →（dev）排除 Host vite-dev-id → 捕获窗口认领
/**
 * 判断节点是否属于当前插件的 Remote 样式。
 * 顺序：已标记 → link origin →（dev）排除 Host vite-dev-id → 捕获窗口认领。
 */
// 函数签名：判断一个 style/link 元素是否属于当前插件的 Remote 样式
function looksLikeRemoteStyle(

	el: HTMLStyleElement | HTMLLinkElement,
	// 当前捕获上下文（插件 id + 入口 origin）
	ctx: CaptureCtx,
// 返回值：是否属于当前插件
): boolean {
	// 1. 已标记元素：检查 data-mf-style-owner 属性（最快路径）
	if (el.dataset.mfStyleOwner) {
		// 直接比对已标记的插件 ID 与当前上下文
		return el.dataset.mfStyleOwner === ctx.pluginId;
	}
	// 2. link 标签：比对 href origin 与插件入口 origin
	if (el instanceof HTMLLinkElement) {
		// 只处理 stylesheet 类型且有 href 的 link
		if (el.rel !== 'stylesheet' || !el.href) return false;
		// try 块：URL 解析可能抛错
		try {
			// 同 origin 则归属于该插件
			return new URL(el.href).origin === ctx.entryOrigin;
		// catch 块：解析失败不认为是远程样式
		} catch {
			// 返回 false
			return false;
		}
	}
	// 3. style 标签：取 Vite dev 的 data-vite-dev-id 属性
	const viteId = el.getAttribute('data-vite-dev-id') || '';
	// 有 viteId 且为 Host 自身样式时排除，不认领
	// Dev：有 vite id 时排除 Host，其余交给当前 capture；生产无 id 同样仅认领 active
	if (viteId && isHostViteDevStyle(viteId)) return false;
	// 4. 其余情况（viteId 为空 / 非 Host 样式）：仅在 capture 窗口内认领
	return active?.pluginId === ctx.pluginId;
}
```

**变更摘要**：
- 删除旧版白名单正则 `(?:^|[\\/])micro(?:[\\/]|$)|remote-plugins|remote-demo|remote-host`。
- viteId 分支改为：有 viteId 且 `isHostViteDevStyle(viteId)` 返回 `true` 时排除（`return false`）；否则不再正则匹配 remote 目录，直接落入 capture 窗口判断 `active?.pluginId === ctx.pluginId`。
- 生产构建（viteId 为空）行为完全不变。

## 5. 兼容性与影响

### 5.1 行为变化

| 场景 | 旧版 | 新版 |
| ---- | ---- | ---- |
| dev：Host 自身 `<style data-vite-dev-id>` | 不匹配白名单 → 走 capture 窗口（若恰在窗口期会被误认领） | `isHostViteDevStyle` 返回 true → 排除，不认领 |
| dev：`apps/micro` 的 `<style>` | 需白名单含 `micro` 才认领 | 非 Host → 走 capture 窗口认领 |
| dev：新增 `apps/<新目录>` 的 `<style>` | **白名单未加则不认领**（bug） | 非 Host → 走 capture 窗口认领（**自动支持**） |
| 生产：`<style>` 无 viteId | 走 capture 窗口 | 走 capture 窗口（**不变**） |
| `<link rel="stylesheet">` | 走 origin 比对 | 走 origin 比对（**不变**） |

### 5.2 兼容性

- **生产构建**：无 `data-vite-dev-id`，行为与旧版完全一致。
- **dev 模式**：Host 自身样式被更精确地排除，减少误认领风险；Remote 样式不再依赖白名单。
- **新增子项目**：无需改 `styleIsolation.ts`，直接被 capture 窗口认领。

### 5.3 风险与回归点

- 验证 dev 模式下 Host 自身样式（如主站 Tailwind）不被 `@scope` 包裹。
- 验证 dev 模式下 `apps/micro`（原 `apps/remote-plugins`）样式正常被 `@scope` 包裹。
- 验证 dev 模式下新增一个 `apps/<新目录>` 子项目后样式自动隔离。
- 验证生产构建插件样式隔离行为不变。
- 验证 `hostViteRoot()` 在符号链接 / monorepo 别名路径下仍能正确推导。
