## 1. 分析目的

评估 **英语学习资源库接入 Redis 列表/词条缓存 + 写后世代失效 + 前端进库双请求修复**，是否改变或破坏已有功能：

- 资源库左侧库列表（自有 + 公开，分页）
- 资源库右侧词条 / 语句分页浏览与续读预取
- 导入整库、删除整库、改标题、超管改公开/私有
- 续读 offset 记忆与侧栏「记忆」模块开关
- 收藏星标（`favoriteId` 内嵌）
- 练习抽题、主题包生成扫库、收藏/错题/每日记词列表

**改动范围（当前 diff）**：

| 文件 | 变更 |
|------|------|
| `apps/backend/src/services/english-learning/english-learning-library.cache.ts` | **新建**：key/TTL/世代 bump、安全 get/set |
| `apps/backend/src/services/english-learning/english-learning.service.ts` | 列表/词条旁路缓存；写路径 bump；Winston logger；mapper 复用 |
| `apps/frontend/src/views/englishLearning/hooks/useEnglishLearningList.ts` | 吸收 settingsRev、列表就绪后再 reload、同页请求单飞 |

**结论摘要**：

| 维度 | 是否影响原有功能 | 说明 |
|------|------------------|------|
| 库列表 API 语义（筛选/排序/分页） | **否** | 仍 `userId=me OR isPublic` + `createdAt DESC`；仅增加 Redis 旁路 |
| 词条/语句 API 字段与鉴权 | **否** | 仍先 `assert*Readable`；响应仍含 library + items + favoriteId + 续读 |
| 导入 / 删除 / 改标题 / 改可见性 | **有条件变化** | 业务结果不变；成功后 bump 世代使旧缓存 miss（用户可见数据应更新更快） |
| 续读「记忆」开关 / offset 持久化 | **否** | 续读不进 Redis 正文缓存；开关不关闭 Redis |
| 收藏 / 错题 / 每日记词 / 主题包 | **否** | 未接入本套 `el-lib-*` 缓存 |
| 性能体感 | **低（增强）** | 热路径重复读可 HIT；冷路径与改前接近 |
| 前端进库双请求 | **低（修复）** | 减少重复 `items` HTTP，不改产品语义 |

### 1.1 Redis 缓存的实际作用

本改动**不是**新功能入口，而是给已有「资源库列表 / 词条分页」读路径加一层 **Cache-Aside（旁路缓存）**。对调用方仍是同一套 HTTP API；Redis 只挡重复的、可共享的非用户态查询。

| 作用点 | 改前 | 改后实际效果 |
|--------|------|--------------|
| **降 DB 压力** | 每次打开列表、进库、翻页、续读预取都打 TypeORM | 同一分页 key 在 TTL 内二次及以后可读 Redis（HIT），少做大段列表/词条 SQL |
| **多实例共享** | 各 Nest 进程各自打 DB | 热数据在 Redis，多副本部署时命中可跨实例复用 |
| **削峰** | 公开库被多人反复浏览 = 同查询放大 | 公开列表 `publicVer` + 词条页 key 可被多用户共享正文缓存 |
| **写后可见性** | 写库即下次读 DB 新数据 | 写成功后 **bump 世代** 换 key，旧页自然 miss，无需 SCAN 删 key |
| **故障降级** | 无 Redis 依赖 | `getSafe` / `setSafe` 吞错，Redis 宕机时退回纯 DB，功能可用、只是变慢 |
| **观测** | 无命中可观测 | HIT 时 Winston 打 `[lib-cache-*]` 日志，便于确认热路径是否生效 |

**明确不做 / 不带来的效果**：

- **不改变**权限、筛选、排序、分页契约；鉴权仍走 DB（`assert*Readable`）。
- **不缓存**用户态：`favoriteId`、`itemsResumeOffset`、`isOwned` 仍按请求用户现算，避免串用户。
- **不加速**冷启动第一次打开（MISS 仍查库再 `set`）。
- **不覆盖**收藏 / 错题 / 每日记词 / 主题包 / 练习抽题等其它读路径。
- **不替代**前端会话内 `libraryWordsListCache`；浏览器层与 Redis 分层，各管各的。

**价值一句话**：读多写少的整库分页，用 Redis 挡重复 SQL；写用世代号廉价失效，产品语义尽量与改前一致。

### 1.2 增加 Redis 后对功能的影响

下表按**产品能力**说明：加 Redis 后用户侧 / 一致性 / 性能分别怎样变。等级与 §3 矩阵一致（无 / 低 / 中 / 高）。

| 功能 | 影响等级 | 对功能的影响（用户 / 数据 / 性能） |
|------|----------|-----------------------------------|
| **左侧库列表（自有 + 公开）** | 低 | 筛选与排序不变；短时间重复打开同一页更快；写库后靠 bump 换代，列表应立刻反映新建/删除/改标题/改可见性 |
| **右侧词条 / 语句分页** | 低 | 字段与鉴权不变；同 `limit/offset` 复访可 HIT；删库后 `itemsVer` bump，旧词条页不可再当合法数据用 |
| **续读 offset +「记忆」预取** | 无～低 | 续读表读写语义不变；开记忆只多预取几页，**每页仍可走 Redis**；进度仍按用户挂在 HIT 结果上 |
| **收藏星标** | 无 | 不进 Redis value；两用户同库收藏互不影响；收藏变更不 bump 正文缓存 |
| **导入整库** | 低 | 导入成功结果不变；事务提交后 `onLibraryCreated` bump `mineVer`，所有者列表不再命中缺新库的旧页 |
| **删除整库** | 低 | 删除结果不变；列表 +（曾公开）公开列表 + 该库词条逻辑失效 |
| **改库标题** | 低 | 标题以 DB 为准展示；列表换代；词条正文缓存可保留，`library.title` 来自鉴权查库 |
| **超管改公开 / 私有** | 中 | 可见性语义不变；`publicVer` 抬升会使**所有用户**公开列表缓存短暂全 miss（冷启动一阵），属预期代价 |
| **练习抽题 / 主题包扫库** | 无 | 未包本缓存，行为与改前一致 |
| **收藏 / 错题 / 每日记词页** | 无 | 未使用 `EnglishLearningLibraryCache` |
| **进库首屏加载** | 低（修复） | 前端吸收 `settingsRev` + 请求单飞，减少重复 `items` HTTP；产品语义不变，Network/HIT 更干净 |
| **运维：Redis 不可用** | 低 | 接口仍应 200，全部 MISS 走 DB；无「必须 Redis 才能学」的硬依赖 |

**对既有需求的总判**：产品功能需求（能列库、能翻词条、能续读、能收藏、能改库）**均保留**；可感知变化主要是**热路径更快**、写后靠 bump 保证读到新世代，以及超管改可见性时公开列表命中率短暂下降。详情见 §3～§6。

## 2. 改动要点（相对改前行为）

### 2.1 后端：库列表 / 词条 Cache-Aside

**改前**：

```text
HTTP list*Libraries / list*LibraryItems
  → 每次直接 TypeORM 查库
  → 组装 DTO（含 isOwned / resume / favoriteId）返回
```

**改后**：

```text
HTTP list*Libraries
  → 读 publicVer + mineVer → 拼 key → Redis get
       HIT  → revive 行 → 再查续读 map → map DTO
       MISS → DB → set Redis(10min) → 续读 → DTO

HTTP list*LibraryItems
  → assertReadable(DB)
  → 读 itemsVer → 拼 key → Redis get
       HIT  → map 行 → 挂 favoriteId + resume
       MISS → DB → set Redis(1h) → 挂收藏/续读
```

**动机**：资源库读多写少；写粒度为整库，适合用世代号失效，避免 SCAN 删 key。

### 2.2 后端：写路径世代失效（逻辑清除）

**改前**：无共享缓存，写库后读路径自然读到新数据。

**改后**：事务/写库成功后 bump：

| 写操作 | bump |
|--------|------|
| 新建库 | `mineVer(owner)` |
| 删库 | `mineVer` +（曾公开）`publicVer` + `itemsVer(lib)` |
| 改标题 | `mineVer` +（公开）`publicVer` |
| 改可见性 | `mineVer` + `publicVer` |

旧业务 key 不主动 DEL，靠 key 内嵌 ver 换代 + TTL。

### 2.3 前端：进库双请求修复

**改前（历史风险）**：`libraryId` 首屏加载与 `settingsRev`（hydrate）reload 叠加 → 同一 `items?limit&offset` 可能打两次 → 后端双 HIT 日志。

**改后**：换库时吸收当前 `settingsRev`；仅列表就绪后才因设置变更 reload；同 `id:limit:offset` 进行中请求单飞合并。

**动机**：Network 与 HIT 日志一致；避免无意义重复打 Redis/DB。

| 模块 / 场景 | 影响等级 | 分析 |
|-------------|----------|------|

## 4. 潜在风险与缓解

| 风险 | 等级 | 说明 | 建议验证 |
|------|------|------|----------|
| 用户态字段误入 Redis | 高（已防） | 若缓存含 favoriteId/resume，会串用户 | 查 Redis value 无 favoriteId；两用户同库收藏不同 |
| 公开库改私有后仍被读 | 高（已防） | 依赖 assertReadable，非仅缓存 | 取消公开后他人 items 应 404/无权 |
| 事务未提交就写缓存 | 中（已防） | `onLibraryCreated` 在 transaction.then | 导入失败时列表不应出现新库 |
| bump 竞态丢一次 +1 | 低 | get-set 非原子 INCR | 仍至少失效一次；可接受 |
| hydrate 后列表已就绪再 bump | 低 | 可能多一次 reload | 单飞可合并并发；模块设置真变更应 reload |
| Redis 宕机 | 低 | getSafe/setSafe 降级 DB | 停 Redis 后列表/词条仍可用 |

## 8. 需求与缓存生命周期（会话问答整理）

### 8.1 需求摘要

1. 单词库 / 语句库列表与词条分页走 Redis，**不改变**既有 API 与权限逻辑。  
2. DB 变更后自动失效（世代 bump），非定时全量刷。  
3. 不缓存用户态：`favoriteId`、`itemsResumeOffset`、`isOwned`。  
4. 命中可打日志；logger 用 Winston `WINSTON_MODULE_NEST_PROVIDER`。  
5. 前端避免进库双打相同 items 请求。

### 8.2 什么时候**设置（写）**缓存

| 场景 | 条件 | TTL |
|------|------|-----|
| 拉库列表 miss | `load*LibrariesPageCached` DB 查完后 `setSafe` | 10 min |
| 拉词条/语句页 miss | `load*ItemsPageCached` DB 查完后 `setSafe` | 1 h |
| bump 世代 | 任一 `bumpVer` | ver 7 天 |

### 8.3 什么时候**读**缓存

| 场景 | 路径 |
|------|------|
| 资源库左侧列表 | `list*Libraries` → HIT libs |
| 点进库 / 翻页 / 续读预取 | `list*LibraryItems` → HIT items（每页独立） |

读命中后仍 DB：`assert*Readable`、续读、收藏。

### 8.4 什么时候**清除 / 失效**

逻辑清除 = **bump ver**（换 key），不是 DEL 扫库。

| 操作 | 失效范围 |
|------|----------|
| 新建库 | 所有者列表 |
| 删库 | 所有者列表 +（曾公开）全站列表 + 该库词条 |
| 改标题 | 所有者列表 +（公开）全站列表 |
| 改可见性 | 所有者 + 全站列表 |
| 续读/收藏/记忆开关 | **不**失效正文缓存 |
| TTL | 列表 10min / 词条 1h 自然过期 |

### 8.5 开「记忆」会不会不走 Redis？

**会走。** 续读只影响预取多少页与 offset 从哪恢复；每页仍可 HIT。收藏/错题/每日记词**未**接本套缓存。

### 8.6 性能预期（与 §1.1 呼应）

| 场景 | 预期 |
|------|------|
| 热路径重复读同一列表/词条页 | 中等收益：降 DB，可出现 HIT 日志 |
| 冷路径 / 首次打开 | 提升有限：仍 MISS → DB → set |
| 多实例 + 公开库热读 | 主要价值：削峰与跨实例共享正文缓存 |
| Redis 宕机 | 功能可用，性能回退到改前水平 |

更完整的「实际作用 / 对功能影响」见 **§1.1、§1.2**。

### 8.7 双 HIT 日志说明

`if (hit) logger.log` **每调用一次打一行**。历史双 HIT = 服务端方法被调两次（前端 settingsRev reload 叠加）。已在 `useEnglishLearningList` 修复；Network 一条 200 与单次 HIT 应对齐。

## 9. 完整实现源码（逐行中文注释）

### 9.1 `english-learning-library.cache.ts`（全文）

源码路径：`apps/backend/src/services/english-learning/english-learning-library.cache.ts`

```typescript
// 引入 Nest Cache 类型（底层已接 Redis store）
import type { Cache } from '@nestjs/cache-manager';
// 引入 Nest LoggerService，与 Winston 注入兼容
import type { LoggerService } from '@nestjs/common';

/** vocab = 单词库；classic = 经典语句库 */
// 资源库种类：单词库或经典语句库
export type ElLibraryKind = 'vocab' | 'classic';

/** 库列表缓存行：不含 isOwned / itemsResumeOffset（按请求用户现算） */
// 库列表缓存行结构（不含用户态字段）
export type CachedLibraryRow = {
// 库主键 UUID
	id: string;
// 库所有者用户 ID
	userId: number;
// 库标题
	title: string;
	/** vocab→wordCount；classic→quoteCount */
// 条目数量字段
	count: number;
// 是否公开库
	isPublic: boolean;
	/** ISO 字符串，避免 Redis JSON 后 Date 方法丢失 */
// 创建时间 ISO
	createdAt: string;
// 结束类型/对象定义
};

/** 词条缓存：禁止带 favoriteId（用户相关） */
// 单词词条缓存行：禁止含 favoriteId
export type CachedVocabItemRow = {
// 库主键 UUID
	id: string;
// 库内排序序号
	sortOrder: number;
// 英文单词
	word: string;
// 音标
	ipa: string;
// 词性
	pos: string;
// 音节划分
	segmentation: string;
// 中文释义
	translationZh: string;
// 例句
	example: string;
// 结束类型/对象定义
};

// 经典语句缓存行：禁止含 favoriteId
export type CachedClassicItemRow = {
// 库主键 UUID
	id: string;
// 库内排序序号
	sortOrder: number;
// 英文原句
	english: string;
// 中文释义
	translationZh: string;
// 出处
	source: string;
// 中文赏析/备注
	noteZh: string;
// 结束类型/对象定义
};

// 库列表页 TTL：10 分钟
export const EL_LIB_LIST_TTL_MS = 10 * 60 * 1000;
// 词条/语句分页 TTL：1 小时
export const EL_LIB_ITEMS_TTL_MS = 60 * 60 * 1000;
/** version key 长 TTL；实际靠 bump 失效 */
// 世代号 TTL：7 天（靠 bump 续期）
export const EL_LIB_VER_TTL_MS = 7 * 24 * 60 * 60 * 1000;

// 公开列表全局世代 key
export function elPublicVerKey(kind: ElLibraryKind): string {
// 返回 publicVer Redis key
	return `el:lib:${kind}:publicVer`;
// 结束当前块
}

// 某用户「我的库」列表世代 key
export function elMineVerKey(kind: ElLibraryKind, userId: number): string {
// 返回按用户隔离的 mineVer key
	return `el:lib:${kind}:mineVer:${userId}`;
// 结束当前块
}

// 把 Redis 读出的 ver 规范成非负整数
export function parseCacheVer(value: unknown): number {
// number / 数字字符串 → 数值，其它 → 0
	const n =
// 已是数字则直接用
		typeof value === 'number'
// 见左侧源码语义
			? value
// 字符串则 Number 转换
			: typeof value === 'string'
// 见左侧源码语义
				? Number(value)
// 其它类型视为 0
				: 0;
// 非法/负数一律归 0，再向下取整
	return Number.isFinite(n) && n >= 0 ? Math.floor(n) : 0;
// 结束当前块
}

/**
 * 英语学习资源库 Redis 旁路缓存。
 * 只缓存与「当前用户」无关的数据；收藏 / 续读 / isOwned 必须在命中后再挂。
 */
// 资源库 Redis 旁路缓存封装类
export class EnglishLearningLibraryCache {
// 构造：注入 Cache 与 Logger
	constructor(
// Nest CACHE_MANAGER（Redis）
		private readonly cache: Cache,
// Winston Nest Logger
		private readonly logger: LoggerService,
// 空构造体结束
	) {}

// 安全 get：失败只 warn，返回 undefined
	async getSafe<T>(key: string): Promise<T | undefined> {
// 捕获 Redis 异常以免拖垮接口
		try {
// 从 Redis 取值
			const v = await this.cache.get<T>(key);
// 空值统一当未命中
			return v === null || v === undefined ? undefined : v;
// 异常分支
		} catch (e) {
// 见左侧源码语义
			this.logger.warn?.(
// 见左侧源码语义
				`[el-lib-cache] get failed key=${key}: ${e instanceof Error ? e.message : e}`,
// 见左侧源码语义
			);
// 降级为 miss
			return undefined;
// 结束当前块
		}
// 结束当前块
	}

// 安全 set：失败只 warn
	async setSafe(key: string, value: unknown, ttlMs: number): Promise<void> {
// 捕获 Redis 异常以免拖垮接口
		try {
// 写入 Redis 并带 TTL
			await this.cache.set(key, value, ttlMs);
// 异常分支
		} catch (e) {
// 见左侧源码语义
			this.logger.warn?.(
// 见左侧源码语义
				`[el-lib-cache] set failed key=${key}: ${e instanceof Error ? e.message : e}`,
// 见左侧源码语义
			);
// 结束当前块
		}
// 结束当前块
	}

// 读世代号（缺省 0）
	async getVer(key: string): Promise<number> {
// get + 规范化
		return parseCacheVer(await this.getSafe(key));
// 结束当前块
	}

// 世代 +1 并写回（逻辑失效）
	async bumpVer(key: string): Promise<number> {
// 当前 ver+1
		const next = (await this.getVer(key)) + 1;
// 用长 TTL 保存新世代
		await this.setSafe(key, next, EL_LIB_VER_TTL_MS);
// 返回新世代值
		return next;
// 结束当前块
	}

// 并行读取 publicVer 与用户 mineVer
	async getListVers(
// 库种类参数
		kind: ElLibraryKind,
// 用户 ID 参数
		userId: number,
// 见左侧源码语义
	): Promise<{ publicVer: number; mineVer: number }> {
// 并行以减少 RTT
		const [publicVer, mineVer] = await Promise.all([
// 读公开列表世代
			this.getVer(elPublicVerKey(kind)),
// 读该用户 mine 世代
			this.getVer(elMineVerKey(kind, userId)),
// 见左侧源码语义
		]);
// 供拼列表 key
		return { publicVer, mineVer };
// 结束当前块
	}

	/** 新建私有库：只影响所有者「我的库」世代 */
// 新建库后：只 bump 所有者 mineVer
	async onLibraryCreated(kind: ElLibraryKind, ownerUserId: number): Promise<void> {
// 所有者列表页全部换代
		await this.bumpVer(elMineVerKey(kind, ownerUserId));
// 结束当前块
	}

	/**
	 * 删除库：所有者列表必变；若曾公开则公开列表也变；词条页世代升高丢弃旧分页。
	 */
// 删库：mine +（曾公开则 public）+ itemsVer
	async onLibraryDeleted(
// 库种类参数
		kind: ElLibraryKind,
// 库所有者用户 ID
		ownerUserId: number,
// 库 ID 参数
		libraryId: string,
// 曾公开才 bump 全局 publicVer
		wasPublic: boolean,
// 见左侧源码语义
	): Promise<void> {
// 并行以减少 RTT
		await Promise.all([
// 所有者列表页全部换代
			this.bumpVer(elMineVerKey(kind, ownerUserId)),
// 曾公开才 bump 全局 publicVer
			wasPublic
// 读公开列表世代
				? this.bumpVer(elPublicVerKey(kind))
// 未公开则跳过 publicVer
				: Promise.resolve(0),
// 该库词条分页换代
			this.bumpVer(elItemsVerKey(kind, libraryId)),
// 见左侧源码语义
		]);
// 结束当前块
	}

	/** 改标题：所有者列表变；公开库标题出现在公开列表里 */
// 改标题：mine；公开库再 bump public
	async onLibraryTitleChanged(
// 库种类参数
		kind: ElLibraryKind,
// 库所有者用户 ID
		ownerUserId: number,
// 当前是否公开
		isPublic: boolean,
// 见左侧源码语义
	): Promise<void> {
// 所有者列表页全部换代
		await this.bumpVer(elMineVerKey(kind, ownerUserId));
// 公开库标题出现在他人列表
		if (isPublic) {
// 读公开列表世代
			await this.bumpVer(elPublicVerKey(kind));
// 结束当前块
		}
// 结束当前块
	}

	/** 改可见性：公开列表 + 所有者列表都变；词条内容本身不变 */
// 改可见性：mine + public 都 bump
	async onLibraryVisibilityChanged(
// 库种类参数
		kind: ElLibraryKind,
// 库所有者用户 ID
		ownerUserId: number,
// 见左侧源码语义
	): Promise<void> {
// 并行以减少 RTT
		await Promise.all([
// 所有者列表页全部换代
			this.bumpVer(elMineVerKey(kind, ownerUserId)),
// 读公开列表世代
			this.bumpVer(elPublicVerKey(kind)),
// 见左侧源码语义
		]);
// 结束当前块
	}
// 结束当前块
}
```

```typescript
private async loadVocabLibrariesPageCached(
	userId: number,
	limit: number,
	offset: number,
): Promise<EnglishVocabularyLibrary[]> {
	// 读取公开世代 + 该用户 mine 世代
	const { publicVer, mineVer } = await this.libraryCache.getListVers(
		'vocab',
		userId,
	);
	// 拼本页完整 key
	const key = elLibsPageKey(
		'vocab',
		userId,
		publicVer,
		mineVer,
		limit,
		offset,
	);
	// 尝试 Redis
	const hit = await this.libraryCache.getSafe<CachedLibraryRow[]>(key);
	if (hit) {
		// 命中：打 Winston 日志
		this.logger.log(
			`[lib-cache-vocab-list] HIT vocab libs userId=${userId} limit=${limit} offset=${offset} count=${hit.length}`,
		);
		// ISO 行 revive 成实体形态供 map
		return hit.map((r) => this.reviveVocabLibraryRow(r));
	}
	// miss：原 SQL 语义查库
	const rows = await this.vocabLibraryRepo
		.createQueryBuilder('lib')
		.where('(lib.userId = :userId OR lib.isPublic = true)', { userId })
		.orderBy('lib.createdAt', 'DESC')
		.take(limit)
		.skip(offset)
		.getMany();
	// 写入 Redis，TTL 10 分钟
	await this.libraryCache.setSafe(
		key,
		rows.map((r) => this.serializeVocabLibraryRow(r)),
		EL_LIB_LIST_TTL_MS,
	);
	// 返回 DB 行
	return rows;
}

// 加载一页单词词条（Cache-Aside；调用方须已鉴权）
private async loadVocabItemsPageCached(
	libraryId: string,
	limit: number,
	offset: number,
): Promise<CachedVocabItemRow[]> {
	// 读该库词条世代
	const itemsVer = await this.libraryCache.getVer(
		elItemsVerKey('vocab', libraryId),
	);
	// 拼分页 key
	const key = elItemsPageKey('vocab', libraryId, itemsVer, limit, offset);
	// 尝试 Redis
	const hit = await this.libraryCache.getSafe<CachedVocabItemRow[]>(key);
	if (hit) {
		// 命中日志
		this.logger.log(
			`[lib-cache-vocab-items] HIT vocab items libraryId=${libraryId} limit=${limit} offset=${offset} count=${hit.length}`,
		);
		// 直接返回缓存行（无 favoriteId）
		return hit;
	}
	// miss：按 sort_order 分页查词条
	const rows = await this.vocabLibraryItemRepo.find({
		where: { libraryId },
		order: { sortOrder: 'ASC' },
		take: limit,
		skip: offset,
	});
	// 经 mapper 后剥离 favoriteId 再缓存
	const cached: CachedVocabItemRow[] = rows.map((r) => {
		const { favoriteId: _f, ...rest } = this.mapLibraryItemRow(r);
		return rest;
	});
	// 写入 Redis，TTL 1 小时
	await this.libraryCache.setSafe(key, cached, EL_LIB_ITEMS_TTL_MS);
	return cached;
}

async listVocabularyLibraryItems(
	userId: number,
	libraryId: string,
```
