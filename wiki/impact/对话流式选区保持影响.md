## 1. 分析目的

评估 **流式输出期间保留气泡内文本选区（便于复制）** 相关改动，是否改变或破坏已有功能，以及对 **性能 / 功能逻辑** 的波及：

- 助手消息流式 Markdown 渲染（`StreamingMarkdownBody`）
- 流式代码围栏横滚与闭合冻结（`StreamingCodeFenceBlock`）
- 流式贴底滚动、联网引用后处理、Mermaid 岛、选区右键菜单
- 非流式（已完成）消息渲染路径

**改动范围（当前 diff）**：

| 文件 | 变更 |
|------|------|
| `apps/frontend/src/utils/domTextSelection.ts` | **新增**：按 root 内纯文本偏移 snapshot / restore 选区 |
| `apps/frontend/src/components/design/ChatAssistantMessage/StreamingMarkdownBody.tsx` | 流式 `StableMarkdownChunk` 改为命令式写 `innerHTML`；写前快照、写后恢复选区；流式 markdown 段用 `md-stream-${i}` 稳定 key |
| `apps/frontend/src/components/design/ChatAssistantMessage/StreamingCodeFenceBlock.tsx` | 更新 `pre>code` / 整根 `innerHTML` 前后同样 snapshot / restore |

**结论摘要**：

| 维度 | 是否影响原有功能 | 说明 |
|------|------------------|------|
| 流式正文持续输出 / SSE 拆段 | **否** | 仍按 chunk 更新 `markdown` → `splitStreamingBodyParts`；未冻结画面、无全局 `selectionchange` |
| 流式代码块横滚 / 闭合冻结 | **否** | `scrollLeft`/`scrollTop` 保留与 `frozenRef` 逻辑不变；仅在改 DOM 时多一步选区恢复 |
| 非流式（`isStreaming=false`）渲染 | **否** | 仍走 `dangerouslySetInnerHTML` + content-hash `partKey`，不经过命令式选区路径 |
| 贴底滚动 / 生成中 Spinner | **否** | 未改 `useStickToBottomScroll`、未改 `ChatAssistantMessage` 贴底与「正在生成中…」 |
| 联网引用 HTML 后处理 | **否** | `renderedMarkdownHtmlPostProcess` 仍在 `useMemo` 算 html 时调用 |
| Mermaid 流式岛 | **否** | Mermaid 分支未改；选区工具不触达岛内命令式更新 |
| 流式时拖选复制 | **低（增强）** | 主目标：选区尽量不被每帧 `innerHTML` 清掉；结构剧变时仍可能丢选（降级） |
| 性能（无选区主路径） | **低（微增）** | 每段 html 变化时多一次廉价 `getSelection` + 折叠/域外早退；有选区时多 TreeWalker 恢复 |
| 选区右键朗读/复制菜单 | **有条件变化** | 流式时选区更稳 → 菜单更易触发；工厂与 hook API 未改 |

## 2. 改动要点（相对改前行为）

### 2.1 流式正文段 `StableMarkdownChunk`

**改前**：

```text
text 变化 → useMemo 出 html → <div dangerouslySetInnerHTML>
React commit 替换整段 DOM → 浏览器选区被清掉 → 无法稳定拖选/复制
流式 markdown 的 key/partKey = md-${hashText(text)} → 每字 hash 变 → 频繁 remount
```

**改后**：

```text
text 变化 → useMemo 出 html → useLayoutEffect：
  若 root.innerHTML === html → return
  snapshotTextOffsetsInRoot(root)（无选区/不在 root → null）
  root.innerHTML = html
  若有 snap → restoreTextOffsetsInRoot
key/partKey = md-stream-${i}（流式下按下标稳定，避免无谓 remount）
```

**动机**：React 的 `dangerouslySetInnerHTML` 在 commit 时已毁掉选区，无法在之后「事后恢复」；必须在写入前快照。稳定 key 避免 remount 直接丢掉旧节点上的选区。

### 2.2 流式代码围栏 `StreamingCodeFenceBlock`

**改前**：

```text
更新 code.innerHTML / 整根 innerHTML 时只保留 pre 的 scrollLeft/scrollTop
选区在代码块内时同样被清掉
```

**改后**：

```text
在写 DOM 前 snapshot，写后 restore（与 scroll 保留并列）
闭合冻结、lang 切换、开放围栏补丁路径均覆盖
```

**动机**：与正文同一问题；用户可能在未闭合/刚闭合的代码块内选字复制。

### 2.3 刻意未采用的方案（历史风险）

| 方案 | 为何不用 |
|------|----------|
| 有选区时冻结整段 `paintMarkdown` + `document.selectionchange` | 停更画面、全局监听，易影响「边输出边看」与性能 |
| 仅 defer 更新 | 功能逻辑上像卡顿，贴底与生成观感变差 |

## 3. 影响点矩阵

| 模块 / 场景 | 影响等级 | 分析 |
|-------------|----------|------|
| **智能对话 `ChatBot` → `ChatAssistantMessage`** | 低 | 唯一消费 `StreamingMarkdownBody` 的主路径之一；流式时选区可保留，内容仍每 chunk 更新 |
| **知识库 / 英语 / 电子书问书等复用 `ChatAssistantMessage` 的助手** | 低 | 同上组件树；无新 props、无 Store API 变更 |
| **分享页等只读展示助手消息** | 无 | 非流式走旧 `dangerouslySetInnerHTML`；本改动不触达 |
| **流式代码块横滚** | 无 | scroll 保留逻辑仍在；选区 restore 在 scroll 恢复之后，不改 scroll 语义 |
| **流式贴底** | 无 | 未改 stick hook；内容高度仍随 html 更新变化 |
| **联网检索引用胶囊** | 无 | postProcess 仍作用于 html 字符串；DOM 写入方式变了但不改 postProcess 契约 |
| **Mermaid 岛 / 工具栏** | 无 | 仍 `MermaidFenceIsland`；不走 `domTextSelection` |
| **选区右键 `useSelectionContextMenu`** | 低 | 依赖气泡内稳定 Selection；流式时更易读到有效选区；菜单项工厂未改 |
| **性能：无选区流式** | 低 | 每更新段：`getSelection` + `isCollapsed` 早退；无 TreeWalker、无 setState 额外路径 |
| **性能：有选区流式** | 低～中 | 每更新段：两次 `Range#toString` 算偏移 + TreeWalker 定位；仅用户正在拖选/按住选区时触发 |
| **跨多个 markdown 段的选区** | 中 | snapshot 以**单个 chunk root** 为界；选区跨两个 `md-stream-*` 时，一端更新可能截断/错位（见 §4） |
| **Markdown 结构剧变**（列表未闭合→闭合、标题等级跳变） | 中 | 纯文本偏移与新 DOM 文本流可能错位，restore catch 后放弃 → 选区丢失（降级到改前） |

## 4. 潜在风险与缓解

| 风险 | 等级 | 说明 | 建议验证 |
|------|------|------|----------|
| 跨段选区在流式拆段变化时丢失 | 中 | `StableMarkdownChunk` 只恢复本 root；中间插入 codeFence 导致下标 `i` 变化时 key 移位可能 remount | 流式长文跨两段拖选，观察是否偶发清空 |
| 结构剧变导致偏移错位 | 低 | restore try/catch 放弃；不抛错、不打断流式 | 流式输出未闭合列表/加粗时拖选复制 |
| 有选区时每 chunk 的 TreeWalker 成本 | 低 | 仅选区落在该 root 时走满路径；松开选区后回到廉价早退 | Performance 面板：拖选期间 vs 不选期间主线程 |
| 首帧空 div 闪白 | 低 | `useLayoutEffect` 在 paint 前写入；与 `StreamingCodeFenceBlock` 同模式 | 流式首包到达时肉眼看是否闪一下 |
| `md-stream-${i}` 在「前插围栏」时 key 错位 | 低 | 正常 SSE 多为尾部增长；围栏从尾部打开时下标稳定 | 流式先出正文再出 ``` 代码块 |

### 性能与功能逻辑（直接回答）

| 问题 | 结论 |
|------|------|
| **会不会影响性能？** | **主路径（无选区）影响可忽略**：多一次 `getSelection` 早退。有选区时每 chunk 多偏移计算 + TreeWalker，属用户主动拖选时的短暂成本，无全局监听、无冻结导致的积压重绘。 |
| **会不会影响现有功能逻辑？** | **拆段、冻结代码块、贴底、引用后处理、非流式路径均保持原语义。** 可感知变化仅为流式时选区更不易被清（增强）。极端结构剧变/跨段选区仍可能丢选，属降级而非新破坏。 |
