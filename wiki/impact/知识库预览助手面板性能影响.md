## 1. 分析目的

评估 **左侧 Markdown 预览与右侧知识库助手同时开启时的主线程争用缓解与输入区重渲染优化**，是否改变或破坏已有功能：

- 左栏 Monaco：纯编辑 / 纯预览 / 分屏 / Diff 各 `viewMode` 与底栏切换
- 右栏助手：AI/RAG 发送、流式输出、停止生成、快捷卡片、会话切换
- 助手输入：Enter 发送、Shift/Ctrl+Enter 换行、IME 组合输入、空正文禁用规则
- 编辑器选区「复制到助手」、`KnowledgeAssistantHandle.appendInput` / `focusInputAtEnd`
- 保存 / 自动保存 / `getMarkdownFromEditorRef` 读正文
- 分享模式（`AssistantShareBar`）、滚动 FAB、AI/RAG 草稿分存
- 非知识页 `MarkdownEditor` 与其它 `ParserMarkdownPreviewPane` 消费方

**改动范围（当前 diff + 未跟踪新文件）**：

| 文件 | 变更 |
|------|------|
| `apps/frontend/src/components/design/Monaco/index.tsx` | 新增 `assistantPaneBusy`；预览+助手同开时卸载隐藏 Monaco、`useDeferredValue` + latch 冻结左栏预览；Editor 卸载时 TextModel / `getMarkdownFromEditorRef` 回退 |
| `apps/frontend/src/components/design/Markdown/index.tsx` | 新增 `enableCodeFloatingToolbar`（可关闭代码块浮动工具条 layout） |
| `apps/frontend/src/views/knowledge/index.tsx` | 抽出 `KnowledgeMarkdownPane` observer，计算并传入 `assistantPaneBusy` |
| `apps/frontend/src/views/knowledge/KnowledgeAssistant.tsx` | 底部输入迁至 `KnowledgeAssistantChatFooter`；`KnowledgeAssistantHandle` 委托 footer ref；分享态用 `EMPTY_AI_MESSAGES` 稳定 memo |
| `apps/frontend/src/views/knowledge/KnowledgeAssistantChatFooter.tsx` | **新建**：轻量 footer、`KnowledgeAssistantEntry`、AI/RAG 草稿 ref、受控 props 可选保留 |
| `apps/frontend/src/views/knowledge/KnowledgeAssistantEntry.tsx` | **新建**：非受控 textarea，按键不触发 React 重渲染 |
| `apps/frontend/src/views/knowledge/constants.ts` | 导出 `KnowledgeAssistantPanelMode`；`KnowledgeAssistantMode` 类型别名对齐 |
| `apps/frontend/tsconfig.tsbuildinfo` | 构建缓存，无运行时语义 |

**说明**：Monaco 左栏预览处 `enableCodeFloatingToolbar={!assistantRightPaneActive}` **当前为注释**，`Markdown` 新 prop 在知识页路径**尚未接线**，行为与改前一致。

**结论摘要**：

| 维度 | 是否影响原有功能 | 说明 |
|------|------------------|------|
| 纯 edit + 助手（主修复场景之一） | **低（增强）** | 沿用第一轮「edit 不喂隐藏预览」；本轮未改 edit 路径 |
| 纯 preview + 助手同开 | **有条件变化** | 隐藏 Monaco **卸载**（改前 co-mount 仅 `invisible`）；预览期用户本不可见编辑，但 `getMarkdownFromEditorRef` 改走 TextModel |
| 助手流式/发送中左栏预览更新 | **有条件变化** | `assistantPaneBusy` 时左栏预览 **冻结** 为 latch 快照；流式结束后 `useDeferredValue` 追平 |
| 分屏 preview + 助手 | **否** | `unmountEditorInPreviewWithAssistant` 仅 `viewMode === 'preview'`；split 仍 co-mount 编辑器与即时 `splitPaneMarkdown` |
| 助手输入与发送 | **否** | `KnowledgeAssistantEntry` 保留 Enter/组合键/停止钮；发送仍走 `assistantStore.sendMessage` / `knowledgeRagQaStore.sendMessage` |
| 无正文时 AI 输入禁用 | **否** | `disableTextInput` + `hasText` 逃逸与改前 `!editorHasBody && !activeInput.trim()` 等价 |
| AI/RAG 草稿切换 | **否** | 改前双 state；改后 `aiDraftRef` / `ragDraftRef` + 模式切换 `useLayoutEffect` 互换 textarea |
| 选区复制到助手 / ref API | **否** | `KnowledgeAssistantHandle` 方法签名不变，实现委托 `KnowledgeAssistantChatFooter` |
| 分享 / 会话工具条 | **否** | `AssistantShareBar`、`AssistantSessionEntryToolbar` 仍使用；工具条 memo 与输入分离 |
| 保存 / 自动保存 / Diff | **否** | `value`/`onChange`/`getMarkdownFromEditorRef` 契约保留；预览+助手时 ref 读 TextModel |
| 外部受控 `input`/`ragInput` props | **否** | footer 仍支持；`useLayoutEffect` 同步进 textarea |
| 其它页面 MarkdownEditor | **否** | `assistantPaneBusy` 默认 `false`；`unmountEditorInPreviewWithAssistant` 需助手右栏激活 |
| 预览侧代码浮动工具条 | **否** | 新 prop 未接线，默认 `enableCodeFloatingToolbar=true` |

## 2. 改动要点（相对改前行为）

### 2.1 Monaco：预览 + 助手时卸载隐藏 Editor、忙时冻结预览

**改前**：

```text
assistantRightPaneActive && viewMode === 'preview'
→ 左栏 co-mount 预览 + 隐藏 Monaco（invisible + pointer-events-none）
→ 预览每键/流式仍可能与助手侧 Markdown 解析争用主线程
```

**改后**：

```text
unmountEditorInPreviewWithAssistant = assistantRightPaneActive && viewMode === 'preview'
→ 满足时完全不渲染 Monaco Editor DOM
→ TextModel（keepCurrentModel）仍通过 useEffect setValue 同步外部 value
→ getMarkdownFromEditorRef 在 Editor 缺失时读 TextModel

assistantPaneBusy（发送/流式）&& 纯预览+助手
→ latchedLeftPreviewRef 冻结 leftPreviewMarkdown，暂停左栏 ParserMarkdownPreviewPane 重解析
→ 非 busy 时用 useDeferredValue 低优先级追平
```

**动机**：仅开预览或仅开助手时不卡；同开时 Monaco layout + 双侧 Markdown 解析 + ChatEntry 受控重渲染叠加导致主线程饱和。

### 2.2 知识页：`KnowledgeMarkdownPane` 与 `assistantPaneBusy`

**改前**：

```text
Knowledge observer 直接渲染 MarkdownEditor
→ markdown 每键 + assistantStore 流式状态变化均可牵动较大子树
```

**改后**：

```text
KnowledgeMarkdownPane 单独 observer，订阅 knowledgeStore.markdown 等
assistantPaneBusy = 助手打开 && (AI/RAG isSending || isStreaming)
→ 传入 MarkdownEditor，驱动预览冻结策略
```

**动机**：将「正文编辑区」与页面其它 MobX 订阅隔离；busy 信号集中计算。

### 2.3 助手输入：`ChatEntry` → `KnowledgeAssistantEntry`

**改前**：

```text
ChatEntry 受控 input/setInput
→ 每键 setState → KnowledgeAssistantInner（observer）重渲染
→ messages.map、scroll、share 等子树随按键 reconcile
```

**改后**：

```text
KnowledgeAssistantEntry：textarea defaultValue + ref
→ onChange 仅在 trim 后「空↔非空」切换时 setHasText
KnowledgeAssistantChatFooter：AI/RAG 草稿存 ref，模式切换 layout 互换
KnowledgeAssistantFooterControls：仅 observer isSending/isStreaming
```

**动机**：ChatEntry 1100+ 行通用组件对知识助手过重；按键不应触发消息列表重渲染。

### 2.4 Markdown：`enableCodeFloatingToolbar`（预留）

**改前**：预览 ScrollArea 始终挂载 `ChatCodeFloatingToolbar`，`layoutDeps: [markdown]`。

**改后**：prop 为 `false` 时不渲染工具条、跳过 scroll relayout；**知识页 Monaco 调用处尚未传入**（注释状态）。

**动机**：助手同开时避免预览侧与助手消息区共用浮动代码条 layout 争用；待产品确认后再接线。

## 3. 影响点矩阵

| 模块 / 场景 | 影响等级 | 分析 |
|-------------|----------|------|
| **纯 preview + 助手** | 中 | Editor DOM 卸载：预览模式本以 `ParserMarkdownPreviewPane` 为主；保存/`getMarkdownFromEditorRef` 改读 TextModel，须回归保存与自动保存 |
| **preview + 助手 + 流式** | 中 | 左栏预览 busy 期不随 `value` 重解析；外部 `setMarkdown`（如「写入当前文档」）可能延迟至流式结束才反映到预览 |
| **preview + 助手 + 流式结束** | 低 | `assistantPaneBusy` 变 false 后 latch 更新 + deferred 追平；须确认无长时间陈旧预览 |
| **纯 edit + 助手** | 低 | 不触发 `unmountEditorInPreviewWithAssistant`；仍享受第一轮 edit 不喂隐藏预览 |
| **split + 助手** | 无 | `viewMode === 'split'` 时 Editor 仍 mount；`splitPaneMarkdown` 仍为即时 `value` |
| **splitDiff / Diff** | 无 | 未改 Diff 模型与 `splitDiffModifiedText` 路径 |
| **edit ↔ preview 切换（助手开）** | 低 | 切到 preview 卸载 Editor；切回 edit  remount，依赖既有 `documentIdentity` / bootstrap 链路 |
| **助手输入键入** | 低 | 非受控 DOM 更新，React 树不重渲染；发送钮 disabled 依赖 `hasText` |
| **IME 中文输入** | 低 | `compositionStart/End` + Enter 组合键判断保留 |
| **AI 模式无正文** | 无 | `disableTextInput && !hasText` 时禁用；已有草稿仍可编辑发送（与改前一致） |
| **RAG 发送** | 无 | 仍 `knowledgeRagQaStore.sendMessage`；不依赖 `editorHasBody` |
| **AI/RAG 模式切换** | 无 | layout effect 在 ref 间迁移草稿；localStorage 模式键不变 |
| **documentKey 切换清空输入** | 无 | footer `useEffect([documentKey])` 清 ref + textarea |
| **正文清空 debounce 清 AI 输入** | 无 | 仍 200ms + `markdownNonempty` 判定 |
| **选区 → appendInput** | 无 | 拼接 `\n\n` 规则不变；`focusInputAtEnd` 经 entry imperative API |
| **分享模式** | 无 | 分享时仍渲染 `AssistantShareBar`；非分享传 `EMPTY_AI_MESSAGES` 避免 footer memo 被 messages 引用击穿 |
| **英语学习等其它 MarkdownEditor** | 无 | 不传 `assistantPaneBusy` 时行为与改前相同 |
| **ParserMarkdownPreviewPane 其它调用方** | 无 | 默认 `enableCodeFloatingToolbar=true` |

## 4. 潜在风险与缓解

| 风险 | 等级 | 说明 | 建议验证 |
|------|------|------|----------|
| 预览+助手时保存读到陈旧正文 | 中 | Editor 卸载，`getMarkdownFromEditorRef` 依赖 TextModel sync effect | 纯预览+助手开，编辑标题区不改正文，点保存，确认内容与预览一致 |
| 流式中「追加到当前文档」左栏预览不更新 | 中 | busy 期 latch 冻结预览 Markdown | 流式进行中点消息「写入当前文档」，流式结束后预览应追平 |
| 预览+助手切回 edit Monaco 重挂载闪动 | 低 | `unmountEditorInPreviewWithAssistant` 切换时 mount/unmount | 助手开着 edit→preview→edit，光标与滚动可接受 |
| 非受控 textarea 与受控 props 双写 | 低 | 仅测试页或 Story 传入 `input`/`setInput` 时走受控同步 | 若存在外部受控接入，切换模式与 appendInput 后 textarea 与 props 一致 |
| `KnowledgeAssistantEntry` 缺少 ChatEntry 附属能力 | 低 | 知识助手原 ChatEntry 未传附件/模型选择等 props；若未来复用需逐项对照 | 对比改前 ChatEntry props 列表，确认无遗漏 |
| `enableCodeFloatingToolbar` 未接线 | 无 | 性能收益未完全兑现 | 若仍卡，取消 Monaco 注释并回归预览代码块选中浮动条 |
| footer 仍在 observer 内创建 JSX | 低 | `chatFooter` 每轮 render 新建元素，靠 `memo` 子组件挡渲染 | 长文+助手+流式同时开，输入仍卡则继续拆 `chatFooter` 到 stable slot |
