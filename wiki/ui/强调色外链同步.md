# 强调色外链同步

> 延伸阅读：
> - [Sheet 描边与主题墨色修正](./Sheet描边与主题墨色修正.md)
> - [独立预览打磨](./独立预览打磨.md)

## 1. 背景与目标

主应用内通过 `localStorage` 持久化的强调色（accent color，如 `teal`、`violet` 等）只对**当前浏览器、当前站点**生效。一旦内容被分享到**独立预览页 / 外部嵌入页 / 不同浏览器标签**，这些页面无法读取到主应用写入的 `localStorage`，导致强调色回退到默认 `teal`，与原页面观感不一致。

本次改动新增 **URL 查询参数同步** 能力：

- 主应用在生成分享 / 外链时，把当前强调色以 `?accent=<id>`（或 `?accentColor=<id>`）拼到目标 URL 上。
- 目标页（含独立预览页）在**首屏内联脚本**阶段优先读取 URL 参数，先于 `localStorage`，避免主题闪烁（FOUC）。
- 提供 `appendShareAccentQuery` 工具函数，统一外链拼接逻辑，避免各调用点自行拼参数。

目标：让强调色在主应用 → 外链 / 独立预览页之间**一致传递**，且首屏不闪烁。

## 2. 改动范围

- `apps/frontend/index.html` — 首屏内联脚本新增 `accentFromSearch()`，并调整强调色解析优先级为「URL 参数 → localStorage → 默认 `teal`」。
- `apps/frontend/src/hooks/theme.ts` — 新增 `parseAccentFromSearch`、`appendShareAccentQuery`；导出原私有的 `readAccentBootstrapSync` 并使其优先读取 URL 参数；`useTheme` 异步初始化同样先读 URL。
- `apps/frontend/src/utils/public-doc-url.ts` — `getSitePageAbsoluteUrl` 新增可选 `accentId` 入参，并在生成绝对地址时调用 `appendShareAccentQuery` 拼上强调色参数。

## 3. 实现思路

1. **URL 参数优先级高于 `localStorage`**：凡能从 `location.search` 解析到合法 `accent` / `accentColor` 的，一律以 URL 为准；解析失败再回退 `localStorage`，最后回退默认 `teal`。这样外链携带的强调色可**覆盖**目标浏览器里残留的旧偏好，保证分享所见即所得。
2. **首屏内联脚本防闪烁**：`index.html` 里的内联脚本在 React 挂载前同步执行，先于任何异步 hook 把强调色写到 `<html>` 的 inline style / class，避免页面先渲染默认色再跳变。
3. **分享 URL 生成集中化**：新增 `appendShareAccentQuery(url, accentId)` 统一处理「是否已有 query、相对/绝对 URL、`URL` 构造异常回退」等边界，调用方只需传入目标地址与当前强调色。
4. **同名解析函数复用**：`parseAccentFromSearch` 内部复用既有的 `resolveAccentId`，保证「合法 accent id」判定与首屏脚本、hook、存储三处一致，不引入新的白名单。
5. **向后兼容**：URL 参数为可选，未携带时行为与改动前完全一致；`getSitePageAbsoluteUrl` 的 `accentId` 同为可选入参，旧调用点无需改动。

### 4.1 `accentFromSearch`（`apps/frontend/index.html`）

**对比范围**：内联脚本中新增的 `accentFromSearch` 全函数（纯新增）。

**改动前** · `apps/frontend/index.html`（基线，内联脚本首屏段）

```javascript
// 旧版首屏内联脚本不存在该函数，强调色仅从 localStorage 读取
// 旧版解析行：var accentId = accentFromStorage() || "teal";
```

**改动后** · `apps/frontend/index.html`（当前，内联脚本首屏段，约 `accentFromSearch` 定义处）

```javascript
// 声明首屏同步读取 URL 强调色的函数，供内联脚本在 React 挂载前调用
function accentFromSearch() {
    // try 块包裹，任何解析异常都安全回退到 null，不阻塞首屏
    try {
        // 取当前页查询串，可能为空字符串
        var s = location.search || "";
        // 构造 URLSearchParams；若 s 没有 leading "?" 则补一个，保证解析合法
        var p = new URLSearchParams(s.startsWith("?") ? s : ("?" + s));
        // 依次尝试 accent 与 accentColor 两个参数名，取先命中者
        var raw = p.get("accent") || p.get("accentColor");
        // 仅当 raw 命中预置 ACCENT_HEX 表时才返回，否则返回 null
        return raw && ACCENT_HEX[raw] ? raw : null;
    } catch (_e) {
        // 解析异常时回退 null，交由后续 localStorage / 默认值兜底
        return null;
    }
}
```

**变更摘要**：新增纯函数，首屏即可从 URL 解析强调色；不改动既有 `accentFromStorage`。

### 4.3 `parseAccentFromSearch`（`apps/frontend/src/hooks/theme.ts`）

**对比范围**：新增的 `parseAccentFromSearch` 全函数（纯新增）。

**改动后** · `apps/frontend/src/hooks/theme.ts`（当前，约 `parseAccentFromSearch` 定义处）

```typescript
// 导出函数：从任意查询串中解析合法强调色 id，供 hook 与首屏逻辑复用
export function parseAccentFromSearch(search: string): AccentId | null {
    // 构造 URLSearchParams，自动处理 leading "?" 缺失的情况
    const params = new URLSearchParams(
        // 若 search 已带 "?" 直接传入，否则补 "?" 前缀以保证解析合法
        search.startsWith('?') ? search : `?${search}`,
    );
    // 依次尝试 accent 与 accentColor 两个参数名，命中后交由 resolveAccentId 校验合法性
    return resolveAccentId(params.get('accent') || params.get('accentColor'));
}
```

**变更摘要**：新增导出函数，统一 URL 强调色解析入口，复用既有 `resolveAccentId` 做合法性校验。

### 4.4 `appendShareAccentQuery`（`apps/frontend/src/hooks/theme.ts`）

**对比范围**：新增的 `appendShareAccentQuery` 全函数（纯新增）。

**改动后** · `apps/frontend/src/hooks/theme.ts`（当前，约 `appendShareAccentQuery` 定义处）

```typescript
// 导出函数：把强调色参数拼到目标 URL 上，供分享 / 外链生成调用
export function appendShareAccentQuery(
    // 待拼接的目标地址，可为绝对或相对 URL
    url: string,
    // 当前强调色 id
    accentId: AccentId,
): string {
    // try 块包裹 URL 构造，异常时走兜底拼接
    try {
        // 确定 base：浏览器环境下取 origin，SSR / 测试环境回退 localhost
        const base = typeof window !== 'undefined' ? window.location.origin : 'http://localhost';
        // 若 url 已是 http 开头的绝对地址则不传 base，否则用 base 解析相对地址
        const u = new URL(url, url.startsWith('http') ? undefined : base);
        // 统一写入选定参数名 accent
        u.searchParams.set('accent', accentId);
        // 返回完整字符串形式
        return u.toString();
    } catch {
        // URL 构造失败时的字符串兜底：根据是否已有 query 选择分隔符
        const sep = url.includes('?') ? '&' : '?';
        // 手动拼接并 encode 参数值，保证特殊字符安全
        return `${url}${sep}accent=${encodeURIComponent(accentId)}`;
    }
}
```

**变更摘要**：新增导出函数，集中处理绝对/相对 URL 与异常兜底，供外链生成复用。

### 4.5 `readAccentBootstrapSync`（`apps/frontend/src/hooks/theme.ts`）

**对比范围**：`readAccentBootstrapSync` 全函数（改动前为私有且只读 localStorage；改动后导出并先读 URL）。

**改动前** · `apps/frontend/src/hooks/theme.ts`（基线，约 `readAccentBootstrapSync` 定义处）

```typescript
// 旧版：私有函数，仅从 localStorage 读取强调色
function readAccentBootstrapSync(): AccentId {
    // try 块包裹，localStorage 不可用时回退默认值
    try {
        // 读取 localStorage 中持久化的强调色
        const stored = localStorage.getItem(ACCENT_STORAGE_KEY);
        // 校验合法性，非法时回退 teal
        return resolveAccentId(stored) ?? 'teal';
    } catch {
        // localStorage 抛错时回退默认 teal
        return 'teal';
    }
}
```

**改动后** · `apps/frontend/src/hooks/theme.ts`（当前，约 `readAccentBootstrapSync` 定义处）

```typescript
// 新版：改为 export，并在 localStorage 之前优先读取 URL 参数
export function readAccentBootstrapSync(): AccentId {
    // try 块包裹，任何读取异常都安全回退默认值
    try {
        // 先从当前页查询串解析强调色，外链优先级最高
        const fromSearch = parseAccentFromSearch(window.location.search);
        // URL 命中合法值则直接返回，不再查 localStorage
        if (fromSearch) return fromSearch;
        // URL 未携带时回退到 localStorage 持久化值
        const stored = localStorage.getItem(ACCENT_STORAGE_KEY);
        // 校验 localStorage 值合法性，非法时回退 teal
        return resolveAccentId(stored) ?? 'teal';
    } catch {
        // 读取异常时回退默认 teal
        return 'teal';
    }
}
```

**变更摘要**：由私有改为导出；解析顺序变为「URL → localStorage → 默认」，使外链可覆盖本地偏好。

## 5. 兼容性与影响

- **URL 参数可选**：未携带 `accent` / `accentColor` 时，行为与改动前完全一致（回退 `localStorage` → 默认 `teal`）。
- **参数名双兼容**：同时接受 `accent` 与 `accentColor` 两个查询参数名，`accent` 优先。
- **`getSitePageAbsoluteUrl` 向后兼容**：`accentId` 为可选入参，既有调用点无需改动。
- **导出变更**：`readAccentBootstrapSync` 由私有改为 `export`，不影响运行时行为，仅扩大可访问性以供 `public-doc-url.ts` 复用。
- **SSR / 测试环境**：`appendShareAccentQuery` 在 `window` 未定义时回退 `localhost` 作为 base，避免 SSR 报错。

## 6. 风险与回归

- **URL 参数覆盖本地偏好**：用户点击带 `?accent=violet` 的外链后，该次访问会覆盖本地 `localStorage` 偏好显示；但 `localStorage` 本身不被写入，刷新（URL 丢失参数）后回到本地偏好。需确认这是预期行为。
- **参数合法性**：`parseAccentFromSearch` 与 `accentFromSearch` 均通过 `resolveAccentId` / `ACCENT_HEX` 校验，非法值被忽略，不会注入未定义强调色。
- **回归建议**：
  - 主应用切换强调色后生成分享 / 外链，确认 URL 带上 `?accent=<id>`。
  - 独立预览页打开带参 URL，首屏即应用对应强调色，无闪烁。
  - 不带参打开独立预览页，回退 `localStorage` / 默认值，行为与改动前一致。
  - `?accent=invalid` 打开页面，应回退默认值而非报错。
  - 相对 URL 与绝对 URL 两种形态下 `appendShareAccentQuery` 均能正确拼参。
