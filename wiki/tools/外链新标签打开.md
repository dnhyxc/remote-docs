# Markdown 外链默认新标签打开

> 延伸阅读：
> - [使用指南.md](./使用指南.md)（`@dnhyxc-ai/markdown-kit` 包整体使用）
> - [../monaco/Markdown预览目录哈希导航.md](../monaco/Markdown预览目录哈希导航.md)（页内 `#` 锚点滚动逻辑，外链拦截器与本改动互补）
> - 仓外子项目专题：`micro-apps/remote-docs/docs/app/外链系统浏览器打开.md`（MF 嵌入桌面时的点击拦截；与本篇 §5 对照）

## 1. 背景与目标

助手回复、知识库预览等场景渲染 Markdown 时，正文中的外部链接（`http://` / `https://`）默认在**当前标签页**打开。在 SPA（单页应用）和 Tauri WebView 环境中，同页导航会**顶掉整个应用**——用户点击链接后应用被替换为目标网页，需手动后退才能回来。

改动前，外链拦截靠宿主侧 `attachExternalLinkClickInterceptor` 在 `click` 事件中拦截 `href` 非页内锚点的 `<a>`，调系统浏览器打开。但这只在**已挂载拦截器的宿主**生效；若某处 Markdown 渲染未接拦截器，外链仍走浏览器默认行为。

本次改动在 **markdown-it 渲染层**直接给外链 `<a>` 补 `target="_blank"` + `rel="noopener noreferrer"`，使无论宿主是否挂了点击拦截器，外链在**普通浏览器**里都默认新标签打开。页内 `#` 锚点除外，保持 SPA 内片段导航能力。

**重要**：本补丁**不能**替代桌面壳的点击拦截。`target="_blank"` 在 Tauri WebView 里通常仍是应用内窗口，要进**系统默认浏览器**必须走宿主 `openExternalUrl`（详见 §5）。

## 3. 实现思路

1. **在渲染层而非宿主层处理**：markdown-it 的 `renderer.rules.link_open` 是所有 `<a>` 标签渲染的必经之路。在此注入逻辑，比在每个宿主挂拦截器更可靠——一次修改覆盖所有使用该 parser 的场景。

2. **保留已有 `link_open` 逻辑**：用「保存 `prev` → 覆写 → 末尾调 `prev`」模式（monkey-patch），不破坏 markdown-it 内置或其它插件对 `link_open` 的处理。

3. **只补不覆盖**：用 `attrIndex('target') < 0` 判断已有 `target` 属性时不重复添加，尊重 Markdown 源码中手动写了 `target` 的场景。

4. **`#` 锚点除外**：`href.startsWith('#')` 的链接是页内片段导航，不补 `target="_blank"`，保持与 `useMarkdownHashLinkViewportScroll` / `attachMarkdownHashLinkNavigation` 的锚点滚动逻辑兼容。

5. **`rel="noopener noreferrer"`**：`_blank` 打开时浏览器默认 `opener` 非空，新页面可通过 `window.opener` 操作原页面（钓鱼攻击向量）。`noopener` 切断引用，`noreferrer` 兼容旧浏览器且不泄露 `Referer`。

### 4.2 `patchExternalLinksOpenBlank` 方法（纯新增）

> 本方法为**纯新增**，无「改动前」版本。按 `code-before-after.md` §4，纯新增符号只需贴改动后代码块。

**改动后** · `packages/markdown-kit/src/markdown/parser.ts`（当前源码，约 L428–L450）

```typescript
/**
 * 渲染层：给外链 `<a>` 补 `target="_blank"` + `rel="noopener noreferrer"`（页内 `#` 除外）。
 *
 * - **只改 HTML 属性**，不处理 click、不调 opener；避免 SPA 同页导航顶掉应用（Web 兜底）。
 * - **不能替代**宿主点击拦截：Tauri / MF 嵌桌面时 `_blank` 仍常是应用内窗口，须
 *   `attachExternalLinkClickInterceptor` → `openExternalUrl`（系统浏览器）。
 * - 主/子项目何时还要拦：见 `docs/tools/外链新标签打开.md` §5。
 */
private patchExternalLinksOpenBlank(): void {
	const md = this.md;
	const prev =
		md.renderer.rules.link_open ||
		((tokens, idx, options, _env, self) =>
			self.renderToken(tokens, idx, options));
	md.renderer.rules.link_open = (tokens, idx, options, env, self) => {
		const href = tokens[idx].attrGet('href')?.trim() ?? '';
		if (href && !href.startsWith('#')) {
			if (tokens[idx].attrIndex('target') < 0) {
				tokens[idx].attrPush(['target', '_blank']);
			}
			if (tokens[idx].attrIndex('rel') < 0) {
				tokens[idx].attrPush(['rel', 'noopener noreferrer']);
			}
		}
		return prev(tokens, idx, options, env, self);
	};
}
```

**变更摘要**：在 `link_open` 上 monkey-patch；外链补 `_blank`，`#` 锚点跳过。与 Host / remote-docs 点击拦截互补，见文档 §5。
### 4.3 测试用例（纯新增）

**改动后** · `packages/markdown-kit/test/markdown/parser.test.ts`（当前源码，约 L53–L64）

```typescript
// 测试标题：外链带 target=_blank，页内锚点不带
it('外链带 target=_blank，页内锚点不带', () => {
	// 用基础选项创建 parser 实例
	const parser = new MarkdownParser(baseParserOptions);
	// 渲染包含外链和锚点的 Markdown 源码
	const html = parser.render(
		'[外](http://127.0.0.1:9012/) 与 [锚](#sec)',
	);
	// 匹配外链 <a> 标签
	const external = html.match(/<a\b[^>]*href="http:\/\/127\.0\.0\.1:9012\/"[^>]*>/);
	// 断言外链带 target="_blank"
	expect(external?.[0]).toContain('target="_blank"');
	// 断言外链带 rel="noopener noreferrer"
	expect(external?.[0]).toContain('rel="noopener noreferrer');
	// 匹配页内锚点 <a> 标签
	const hash = html.match(/<a\b[^>]*href="#sec"[^>]*>/);
	// 锚点标签存在
	expect(hash?.[0]).toBeTruthy();
	// 锚点不带 target 属性
	expect(hash?.[0]).not.toContain('target=');
});
```

## 5. 兼容性与影响：kit 补属性 vs 使用方拦截

`patchExternalLinksOpenBlank` **只改渲染结果上的 HTML 属性**，不处理点击、不调 Tauri opener。与宿主点击拦截是**两层互补**，不是互相替代。

### 5.1 本方法具体做什么 / 不做什么

| 项 | 说明 |
| -- | ---- |
| **做** | 外链 `<a>`（`href` 非空且不以 `#` 开头）补 `target="_blank"` + `rel="noopener noreferrer"`（已有属性不覆盖） |
| **做** | 页内 `#` 锚点保持原样，交给 SPA 片段导航 / 预览 TOC 滚动 |
| **不做** | `preventDefault`、点击委托、`openExternalUrl`、Tauri `plugin:opener` |
| **效果** | 浏览器默认尽量**新开标签**，降低「同页 `location` 跳走顶掉 SPA」概率 |

### 5.2 使用方还要不要拦截？（主项目 / 子项目）

| 场景 | 仅靠 `target="_blank"` | 是否还需拦截 + `openExternalUrl` |
| ---- | ---------------------- | -------------------------------- |
| **主项目 Web**（浏览器跑 Host） | 一般够用（新标签） | 可不拦；已有拦截无害（统一 `window.open`） |
| **主项目 Tauri**（桌面 WebView） | **不够**（`_blank` 常仍是应用内新窗/同 WebView） | **必须拦** → `plugin:opener\|open_url` 进系统浏览器 |
| **remote-docs 独立站**（真浏览器打开） | 够用 | 可不拦 |
| **remote-docs 嵌进 Host（MF）** | 与 Host 同 WebView | **桌面必须拦**；纯 Web 可选 |

一句话：

- **markdown-kit** = Web 兜底 / 防同页导航。
- **使用方拦截** = Tauri / 嵌入桌面时「系统默认浏览器」的正道；kit 做不到。

### 5.3 当前落点（勿随意删拦截）

**主项目**（应保留）：

- Monaco / Markdown 预览、聊天气泡、文档分析页 → `useMarkdownHashLinkViewportScroll` → `attachExternalLinkClickInterceptor`（`apps/frontend/src/utils/external-link-click.ts`）→ `openExternalUrl`
- 实录：`docs/monaco/Markdown预览目录哈希导航.md`（`#` 与外链分工）

- `Markdown` 挂载 `attachExternalLinkClickInterceptor`（`micro-apps/remote-docs/src/utils/open-external.ts`）

- 仅永远独立浏览器打开、且确认不嵌桌面 Host 时，才可只靠 kit 的 `_blank`
