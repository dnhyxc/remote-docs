# 主题热更新机制

## 1. 背景与目标

`remote-docs` 是一个基于 Module Federation 的远程微应用，它有两种运行形态：

- **嵌入态**：被 Host 主站通过 federation-kit 加载为插件，需要实时跟随 Host 当前主题（亮 / 暗）。
- **独立态**：通过外链直接打开（例如 Host 分享时 append 的 `?theme=black`），需要读取 URL `?theme=` 参数决定首屏主题。

用户关心的两个核心问题是：

> **怎么实现的主题热更新？为什么要这么实现热更新？**

这里的"热更新"指 **主题在不刷新页面的情况下实时切换**，而非模块热替换（HMR）。本文围绕这两点展开。

### 核心挑战

1. Host 主站用 `body.theme-black` 标识暗色，而 remote 自身会写 `html.dark`。如果探测暗色时只读 `html.dark`，会读到 **自己刚写上去的类**，形成回环。
2. 嵌入态下，Host 的 federation-kit 会把 `html.dark` 翻译成 `[data-mf-style-realm][data-plugin-root].dark`，因此暗色类必须同时钉到 **插件根元素** 上，否则作用域内的暗色 CSS 变量不生效。
3. `github-markdown` CSS 的 dark/light token 写在 `prefers-color-scheme` 媒体查询里。当用户 OS 是浅色但应用要走暗色（外链 `?theme=black`）时，媒体查询不命中，会出现"暗底配浅色 token"导致代码块不可读。

## 3. 实现思路

主题热更新采用 **三级探测 + 独立态首屏同步 + CSS token 兜底** 的组合方案。以下逐条解释 **为什么这么设计**。

### 3.1 三级主题探测（嵌入态）

`useHostTheme` 内部并行三套机制：

| 级别 | 机制 | 触发时机 | 为什么需要 |
| --- | --- | --- | --- |
| A 主路径 | live `api.theme` prop | Host 重渲染并把新 theme 写进 props 时 | 与 locale 一致的稳定主路径，Host 显式下发 |
| B 主路径 | `event.on('theme')` 事件 | Host 运行时切换主题，无需整页重渲染 | A 只在 Host 重渲染时触发，无法响应"热切换"；事件路径专门解决热更新 |
| C 兜底 | `MutationObserver` 监听 `body` / `html` class | Host 切换 `body.theme-*` 类时 | 旧版 Host 没有 theme 热推事件，只会切 body 类；兜底确保向后兼容 |

**为什么需要三级？** 三者覆盖不同 Host 版本与不同切换路径：A 稳定但低频，B 高频但依赖新 Host，C 兜底老 Host。任一缺失都会在某种场景下出现主题不跟随。

### 3.2 为什么 `isHostChromeDark` 先查 `body.theme-*`

Host 主站 chrome 用 `body.theme-black` 表示暗色。如果探测时只读 `html.dark`，会读到 remote **自己刚写上去** 的 `html.dark`，形成"写 → 读 → 再写"的回环。

因此策略是：**只要 body 上存在任意 `theme-*` 类，就只信任 body 类、忽略 `html.dark`**：

- `body` 有 `theme-black` → 暗色
- `body` 有其他 `theme-*`（非 black）→ 浅色
- `body` 无 `theme-*` → 退回读 `body.dark` / `html.dark`（兼容旧路径）

### 3.3 为什么 `applyDocsDark` 写多处元素

暗色类需同时写到三类锚点，覆盖不同 CSS 选择器命中场景：

1. **`html.dark`** — 独立态 CSS 选择器（如 `html.dark .markdown-body`）与 hljs 暗色主题靠它命中。
2. **`[data-mf-style-realm][data-plugin-root].dark`** — Host federation-kit 的样式作用域包裹元素。嵌入态下 Host 把 `html.dark` 翻译到这个作用域上，直接写它确保作用域内暗色变量生效。
3. **`[data-plugin-root].dark`** — 插件根本身，作为直接锚点兜底。

这样独立态与嵌入态的暗色 CSS 变量都能正确命中。

### 3.4 为什么独立态读 `?theme=`

Host 分享外链时会 append `?theme=black`（或 `dark`），与 Host `appendShareThemeQuery` 行为对齐。独立态 remote 读这个查询参数决定初始主题，保证用户从分享链接打开时主题与分享时一致。

**为什么 `?theme=black` 映射到 dark？** Host 主题体系用 `black` 作为暗色主题名，remote 自身 CSS 约定用 `dark`，因此归一化 `black` → `dark`。

### 3.5 为什么 `applyStandaloneBootFromSearch` 必须在 React 挂载前跑

如果等 React 挂载后再应用主题，首帧会用错 hljs 主题与 github-markdown 浅色 token，产生闪烁。在 `createRoot().render()` 之前 **同步** 设置 `html.dark` + `data-theme` + `colorScheme`，首帧即正确，无闪烁。

### 3.6 为什么 `themePayloadToDark` 接受多形态 payload

不同 Host 版本发送 theme 事件的 payload 形态不一：

- 字符串 `'dark'` / `'black'` → 暗色
- 字符串 `'light'` / `'white'` → 浅色
- 对象 `{ theme: 'dark' | 'light' | ... }`

归一化器统一处理以上变体，无法识别的返回 `null`，调用方据此跳过，不误清当前主题。

### 3.7 为什么 `styles.css` 强制 `html.dark .markdown-body` token

`github-markdown` CSS 把 dark/light token 写在 `prefers-color-scheme` 媒体查询里。当用户 OS 是浅色但应用要走暗色（外链 `?theme=black`）时，媒体查询不命中，`.markdown-body` 会继续用浅色 token → 暗底配浅色 token，代码块发灰发白、不可读。

CSS 覆盖强制：**只要 `html.dark` 存在就用暗色 token，`html:not(.dark)` 就用浅色 token**，与 OS 偏好无关。

### 4.1 useHostTheme（改动前/后对比）

**改动前** · `src/hooks/useHostBridgeSync.ts`（基线，约 L28–L36）

旧实现仅依赖 Host 下发的 `api.theme`，无事件热推、无 body 兜底，且只改 `html`、未考虑嵌入态 federation 样式作用域。

```typescript
// 旧实现：仅依赖 Host bridge 下发的 api.theme，无热推事件、无 body 兜底
export function useHostTheme(api?: HostBridgeProps['api']) {
	// 仅在 Host 重渲染并把新 theme 写进 props 时触发，无法响应运行时热切换
	useEffect(() => {
		// 取 Host 下发的主题字符串（期望 'dark' / 'light'）
		const theme = api?.theme;
		// 缺失则不处理，避免清掉独立模式下的用户偏好
		if (!theme) return;
		// 直接操作 html 元素，未考虑嵌入态下 Host 的样式作用域翻译
		const root = document.documentElement;
		// 暗色时加上 dark 类，供 github-markdown 等选择器命中
		root.classList.toggle('dark', theme === 'dark');
		// 写 data-theme 供部分按属性匹配的组件读取
		root.dataset.theme = theme;
		// 同步 colorScheme，让原生控件（滚动条/表单）也走暗色
		root.style.colorScheme = theme;
	// 依赖 api.theme，只在 Host 重渲染时才重跑
	}, [api?.theme]);
}
```

**改动后** · `src/hooks/useHostBridgeSync.ts`（当前，约 L85–L122）

新增 `pluginRootRef` 参数；三级探测（live prop / 事件热推 / MutationObserver 兜底）；统一走 `applyDocsDark`，覆盖 html + federation 作用域 + 插件根。

```typescript
// 跟随 Host theme（嵌入时）；主路径 live api.theme + 事件热推 + MutationObserver 兜底
export function useHostTheme(
	// Host bridge 能力集，含 theme/event 等
	api?: HostBridgeProps['api'],
	// 插件根元素 ref，用于把 dark 类钉到 federation 样式作用域上
	pluginRootRef?: RefObject<HTMLElement | null>,
) {
	// 取当前插件根；独立态或 ref 未就绪时为 null，applyDocsDark 会自行只改 html
	const root = () => pluginRootRef?.current ?? null;

	// 主路径 A：Host 覆写后的 api.theme；仅在 Host 重渲染时触发
	useEffect(() => {
		// 无 theme 下发则退出，保留独立模式或兜底结果
		if (!api?.theme) return;
		// 统一走 applyDocsDark，确保 html + 插件根 + federation 作用域同步
		applyDocsDark(api.theme === 'dark', root());
	// theme 或插件根变化时重跑
	}, [api?.theme, pluginRootRef]);

	// 主路径 B：事件热推，Host 运行时切换主题无需整页重渲染
	useEffect(() => {
		// 取事件总线
		const event = api?.event;
		// 无事件总线则跳过
		if (!event) return;
		// 主题事件回调：把多形态 payload 归一成暗色布尔
		const onTheme = (data?: unknown) => {
			// 归一化：字符串 'dark'/'black' → true，'light'/'white' → false，对象 {theme:...} 同理
			const dark = themePayloadToDark(data);
			// 无法识别的 payload（如 undefined）忽略，避免误清当前主题
			if (dark === null) return;
			// 识别成功后应用暗色
			applyDocsDark(dark, root());
		};
		// 订阅 theme 事件
		event.on('theme', onTheme);
		// 卸载时取消订阅，防止内存泄漏与重复触发
		return () => event.off('theme', onTheme);
	// 事件总线或插件根变化时重订阅
	}, [api?.event, pluginRootRef]);

	// 兜底路径：仅嵌入时启用；无热推的旧 Host 仍可跟 body.theme-* 切换
	useEffect(() => {
		// 非 embedding 或 SSR 环境退出，避免独立态下误触
		if (!api || typeof document === 'undefined') return;
		// 同步函数：读 Host chrome 暗色状态并应用
		const sync = () => applyDocsDark(isHostChromeDark(), root());
		// 首次挂载立即同步一次，避免错过初始状态
		sync();
		// 监听 body/html class 变化，Host 切换主题时回调
		const mo = new MutationObserver(sync);
		// body.theme-* 是 Host 主站暗色标志，优先监听
		mo.observe(document.body, { attributes: true, attributeFilter: ['class'] });
		// 部分代码路径会改 html.dark，一并监听兜底
		mo.observe(document.documentElement, {
			attributes: true,
			attributeFilter: ['class'],
		});
		// 卸载时断开观察器
		return () => mo.disconnect();
	// api 或插件根变化时重建观察器
	}, [api, pluginRootRef]);
}
```

### 4.2 isHostChromeDark 与 applyDocsDark（纯新增）

**来源** · `src/hooks/useHostBridgeSync.ts`（纯新增，约 L32–L67）

`isHostChromeDark`：兜底探测 Host chrome 暗色，先查 `body.theme-*` 避免回环；`applyDocsDark`：统一写 html + federation 作用域 + 插件根。

```typescript
// Host 暗色探测（兜底）：主站常用 body.theme-black，有 theme-* 时只信 Host chrome 避免回环
export function isHostChromeDark(): boolean {
	// SSR 安全：无 document 时按浅色处理
	if (typeof document === 'undefined') return false;
	// 取 body 元素，Host chrome 暗色类挂在 body 上
	const body = document.body;
	// 标记是否发现任意 theme-* 类，用于决定是否信任 html.dark
	let hasThemeClass = false;
	// 遍历 body 所有类，找 Host chrome 的 theme-* 标志
	for (const c of body.classList) {
		// 命中任意 theme-* 前缀，说明 Host 在管主题
		if (c.startsWith('theme-')) {
			// 标记发现 Host 主题类
			hasThemeClass = true;
			// theme-black 是 Host 的暗色主题名，命中即暗色
			if (c === 'theme-black') return true;
		}
	}
	// Host 在管主题但不是 black，则按浅色；不再读 html.dark，避免读到自身写入造成回环
	if (hasThemeClass) return false;
	// Host 没下发 theme-* 时，退回读 body.dark / html.dark（兼容旧实现）
	return (
		// body 上有 dark 类
		body.classList.contains('dark') ||
		// 或 html 上有 dark 类
		document.documentElement.classList.contains('dark')
	);
}

// 统一应用暗色到 html + federation 作用域 + 插件根，覆盖不同 CSS 选择器命中场景
export function applyDocsDark(
	// 目标暗色状态
	dark: boolean,
	// 插件根元素；独立态为 null
	pluginRoot?: HTMLElement | null,
): void {
	// 始终写 html，供独立态 CSS 选择器（html.dark .markdown-body）与 hljs 主题命中
	const root = document.documentElement;
	// 切换 dark 类
	root.classList.toggle('dark', dark);
	// 写 data-theme 供按属性匹配的组件读取
	root.dataset.theme = dark ? 'dark' : 'light';
	// 同步 colorScheme，让原生控件走对应色板
	root.style.colorScheme = dark ? 'dark' : 'light';

	// 向上找 Host federation-kit 生成的样式作用域包裹元素
	const hostWrap = pluginRoot?.closest(
		'[data-mf-style-realm][data-plugin-root]',
	);
	// 在作用域包裹上同步 dark 类，让 Host 作用域内的暗色变量生效
	hostWrap?.classList.toggle('dark', dark);
	// 插件根本身也加上，作为直接锚点兜底
	pluginRoot?.classList.toggle('dark', dark);
}
```

### 4.3 themePayloadToDark（纯新增）

**来源** · `src/hooks/useHostBridgeSync.ts`（纯新增，约 L69–L78）

主题事件 payload 归一化：把多版本 Host 的不同形态统一成暗色布尔。

```typescript
// 主题事件 payload 归一化：把多版本 Host 的不同形态统一成暗色布尔
function themePayloadToDark(data: unknown): boolean | null {
	// 字符串暗色：'dark'（remote 约定）或 'black'（Host 主题名）
	if (data === 'dark' || data === 'black') return true;
	// 字符串浅色：'light' 或 'white'
	if (data === 'light' || data === 'white') return false;
	// 对象形态：{ theme: 'dark' | 'light' | ... }，新版 Host 可能用对象包裹
	if (data && typeof data === 'object' && 'theme' in data) {
		// 取 theme 字段
		const t = (data as { theme?: unknown }).theme;
		// 对象内 theme 为暗色
		if (t === 'dark' || t === 'black') return true;
		// 对象内 theme 为浅色
		if (t === 'light' || t === 'white') return false;
	}
	// 无法识别的 payload 返回 null，调用方据此跳过，不误清当前主题
	return null;
}
```

### 4.4 useStandaloneThemeFromSearch（纯新增）

**来源** · `src/hooks/useHostBridgeSync.ts`（纯新增，约 L128–L141）

独立态跟随 `?theme=` 查询参数。首屏已在 `main.tsx` 同步过；此处 React 内再跟一次，防止 HMR 或后续 query 变化。

```typescript
// 独立打开时跟随 ?theme= 查询参数（与 Host appendShareThemeQuery 对齐；black → dark）
export function useStandaloneThemeFromSearch(
	// 是否启用独立模式
	enabled: boolean,
	// 插件根 ref
	pluginRootRef?: RefObject<HTMLElement | null>,
) {
	useEffect(() => {
		// 非独立模式或 SSR 退出
		if (!enabled || typeof window === 'undefined') return;
		// 读 ?theme= 查询参数
		const theme = new URLSearchParams(window.location.search).get('theme');
		// 无参数则不处理，避免覆盖 React 内的默认/用户偏好
		if (!theme) return;
		// black 是 Host 暗色主题名，归一成 dark；dark 直接过；其余按浅色
		applyDocsDark(
			theme === 'black' || theme === 'dark',
			pluginRootRef?.current ?? null,
		);
	// enabled 或插件根变化时重跑
	}, [enabled, pluginRootRef]);
}
```

### 4.5 src/utils/standaloneAppearance.ts — 独立站首屏同步（纯新增）

**来源** · `src/utils/standaloneAppearance.ts`（纯新增，约 L1–L18）

在 React 挂载前同步 `?theme=` / `?lang=`，避免首帧用错 hljs 主题与 github-markdown 浅色 token。

```typescript
// 独立打开时在 React 挂载前同步 ?theme= / ?lang=，避免首帧闪烁
export function applyStandaloneBootFromSearch(): void {
	// SSR 安全：无 window 时直接返回
	if (typeof window === 'undefined') return;
	// 解析查询参数
	const params = new URLSearchParams(window.location.search);
	// 取 theme 参数
	const theme = params.get('theme');
	// black/dark 都视为暗色，归一成布尔
	const dark = theme === 'black' || theme === 'dark';
	// 取 html 元素，首屏同步只改 html
	const root = document.documentElement;
	// 切 dark 类，供 hljs 主题与 github-markdown token 选择器命中
	root.classList.toggle('dark', dark);
	// 写 data-theme 供按属性匹配的组件读取
	root.dataset.theme = dark ? 'dark' : 'light';
	// 同步 colorScheme，让原生控件走对应色板
	root.style.colorScheme = dark ? 'dark' : 'light';
	// 取 lang 参数
	const lang = params.get('lang');
	// 合法值才设置，避免脏数据覆盖默认
	if (lang === 'zh-CN' || lang === 'en-US') {
		// en-US 映射成 'en'，其余用 'zh-CN'
		root.lang = lang === 'en-US' ? 'en' : 'zh-CN';
	}
}
```

### 4.7 src/styles.css — github-markdown dark/light token 强制（纯新增）

**来源** · `src/styles.css`（纯新增，约 L172–L223）

`github-markdown` 把 dark/light token 写在 `prefers-color-scheme` 媒体查询里。外链 `?theme=black` 只加 `html.dark`，OS 仍为浅色时 `.markdown-body` 会继续用浅色 token → 代码块发灰/发白。这里强制跟随 `html.dark`。

```css
/* 暗色 token：仅当 html.dark 存在时生效，覆盖 github-markdown 的 prefers-color-scheme 媒体查询 */
```

## 5. 兼容性与影响

### 兼容性

| 场景 | 行为 | 说明 |
| --- | --- | --- |
| 新版 Host 嵌入，运行时切主题 | A + B 路径生效，即时跟随 | 事件 `event.on('theme')` 热推，无需重渲染 |
| 新版 Host 嵌入，Host 重渲染 | A 路径生效 | live `api.theme` prop 覆写 |
| 旧版 Host 嵌入（无 theme 事件/prop） | C 路径兜底 | `MutationObserver` 监听 `body.theme-*` 切换 |
| 独立态外链 `?theme=black` | 首屏同步 + React 内再跟 | `applyStandaloneBootFromSearch` 首帧前同步，`useStandaloneThemeFromSearch` 兜底 HMR |
| 独立态无 `?theme=` | 默认浅色 | 无参数时不动 theme，保留默认 |
| OS 浅色 + 应用暗色 | CSS token 强制暗色 | `html.dark .markdown-body` 覆盖媒体查询 |

### 影响面

- **主题应用**：所有走 `applyDocsDark` 的路径统一行为，不再有"只改 html"的旧路径。
- **首屏渲染**：独立态首帧不再闪烁，hljs 主题与 github-markdown token 首帧即正确。
- **CSS 变量**：`.markdown-body` 的 token 改为由 `html.dark` / `html:not(.dark)` 显式控制，不再依赖 `prefers-color-scheme`。
- **回归风险**：嵌入态下若 Host 既不下发 theme 又无 `body.theme-*`，`isHostChromeDark` 走 `html.dark` 兜底，行为与旧版一致；不会主动清主题。
- **无破坏性改动**：旧 Host 不发送 theme 事件时，B 路径不触发，A/C 路径仍工作；独立态无 `?theme=` 时行为不变。
