# 内存路由与地址栏同步

## 1. 背景与目标

`remote-docs` 是一个基于 Module Federation 的远程微应用，它既会被嵌入到 Host（宿主）中运行，也可以通过外链独立打开。两种使用场景对路由的诉求完全不同：

- **嵌入 Host 时**：浏览器地址栏停在 Host 自己的路由（例如 Host 的 `/update-info` 路径），远程应用无法、也不应该控制地址栏。此时若用 `react-router` 这类基于 URL 的路由，会与 Host 的 router 冲突，造成地址栏被远程抢写、Host 路由状态错乱等问题。
- **独立打开时**：用户希望通过外链直接访问某一篇文档（例如 `/project-guide`），并能使用浏览器的前进/后退按钮、收藏书签。此时地址栏应当反映当前页面。

基于以上差异，本方案的目标是：

1. 在远程应用内部使用一套**纯内存路由**（`useState` + Context），与 Host 的 URL 路由彻底解耦；
2. 通过一个 `syncBrowserUrl` 开关，**仅在独立模式**下开启 `pushState` / `popstate` 与地址栏的双向同步；
3. 对来自 Host 的 `routePath` 属性和来自 URL 的 `pathname` 做**白名单校验**，避免任意路径注入。

## 3. 实现思路

整体链路：`App` 判断 `standalone` → `resolveInitialPath` 计算初始路径 → `NavigationProvider` 持有内存路径状态 → `AppRouter` 按路径分发页面。地址栏同步只在 `standalone` 时开启。

下面解释每个关键决策的**原因（WHY）**：

1. **为什么用内存路由而不是 react-router**：嵌入 Host 时地址栏显示的是 Host 的路由（如 Host 路径下的 `/update-info`），远程无法控制地址栏。`react-router` 会和 Host 的 router 抢地址栏，产生冲突。一个简单的 `useState` + Context 足够撑起三页文档的切换，且不与 Host 耦合。
2. **为什么加 `syncBrowserUrl` 开关**：独立模式下，希望用户在切换页面时地址栏随之更新（这样可以直接收藏 `/project-guide`）；嵌入模式下，绝不能碰 `window.history`，因为地址栏归 Host 所有。
3. **为什么 `browserPathname` 把 `/` 归一成 `/home`**：独立站的根 URL 是 `/`，内部把它映射到首页。归一化后，后续路径处理始终用 `/home` 这个内部表示，逻辑统一。
4. **为什么 `writeBrowserUrl` 用 `pushState` 而非 `replaceState`**：`pushState` 会产生历史记录，浏览器后退按钮才能逐页回退；`replaceState` 不产生记录，后退会跳过中间页面。
5. **为什么监听 `popstate`**：用户点浏览器后退/前进时触发 `popstate`，监听器从 URL 取出新 `pathname` 回写到内存路径状态，保持地址栏与内存路由一致。
6. **为什么 `resolveInitialPath` 要校验 `DOC_PATHS`**：出于安全考虑，拒绝来自 Host 的 `routePath` 属性或 URL `pathname` 的任意路径注入。只接受已知路径（`/home`、`/update-info`、`/project-guide`、`/plugin-dev-guide`），其余一律回退到默认值。
7. **为什么嵌入默认 `/update-info`、独立默认 `/home`**：嵌入用户来自 Host 的「关于 → 更新日志」入口，落地到 `update-info` 符合预期；独立用户打开根 URL，应展示首页，由首页导航链接进入三篇文档。

## 4. 关键代码对比与注释

### 4.1 NavigationContext.tsx — browserPathname 与 writeBrowserUrl（纯新增）

**来源** · `src/router/NavigationContext.tsx`（纯新增，约 L20–L31）

```typescript
// 从浏览器地址栏读取当前 pathname 并归一化为内部路径表示
function browserPathname(): string {
	// SSR / 非浏览器环境下没有 window，直接返回首页路径兜底
	if (typeof window === 'undefined') return '/home';
	// 取地址栏 pathname，去掉末尾斜杠；若结果为空字符串则回填为 '/'
	const p = window.location.pathname.replace(/\/$/, '') || '/';
	// 根 URL '/' 在内部统一映射为首页 '/home'，其余原样返回
	return p === '/' ? '/home' : p;
}

// 把指定路径写回浏览器地址栏（独立模式专用）
function writeBrowserUrl(to: string) {
	// 非浏览器环境直接返回，避免 SSR 报错
	if (typeof window === 'undefined') return;
	// 基于当前 URL 构造新 URL 对象，便于只改 pathname
	const url = new URL(window.location.href);
	// 内部 '/home' 写回地址栏时还原成根路径 '/'
	url.pathname = to === '/home' ? '/' : to;
	// 用 pushState 产生历史记录，使浏览器后退按钮可用
	window.history.pushState(null, '', url.toString());
}
```

### 4.2 NavigationContext.tsx — NavigationProvider（改动前/后对比）

**改动前** · `src/router/NavigationContext.tsx`（基线，约 L16–L33）

```typescript
// 改动前：NavigationProvider 只持有内存路径，完全不碰地址栏
export function NavigationProvider({
	children,
	initialPath = '/home',
}: {
	children: ReactNode;
	initialPath?: string;
}) {
	// 内存路径状态，初始值为传入的 initialPath
	const [path, setPath] = useState(initialPath);

	// navigate 仅更新内存状态，无任何地址栏副作用
	const navigate = useCallback((to: string) => {
		setPath(to);
	}, []);

	// 通过 Context 向下暴露 path 与 navigate
	return (
		<NavigationContext.Provider value={{ path, navigate }}>
			{children}
		</NavigationContext.Provider>
	);
}
```

**改动后** · `src/router/NavigationContext.tsx`（当前，约 L33–L65）

```typescript
// 改动后：新增 syncBrowserUrl 开关，独立模式开启地址栏双向同步
export function NavigationProvider({
	children,
	initialPath = '/home',
	// 默认 false：嵌入 Host 时不同步地址栏；独立预览时由 App 传 true
	syncBrowserUrl = false,
}: {
	children: ReactNode;
	initialPath?: string;
	// 是否将内存路由与浏览器地址栏同步（仅独立模式应传 true）
	syncBrowserUrl?: boolean;
}) {
	// 内存路径状态，初始值为传入的 initialPath
	const [path, setPath] = useState(initialPath);

	// navigate：先更新内存路径；若开启同步，再写地址栏
	const navigate = useCallback(
		(to: string) => {
			// 更新内存路径状态，驱动 AppRouter 重新分发
			setPath(to);
			// 仅在独立模式下把新路径写回浏览器地址栏
			if (syncBrowserUrl) writeBrowserUrl(to);
		},
		// 依赖 syncBrowserUrl：开关变化时重建函数，避免闭包旧值
		[syncBrowserUrl],
	);

	// 副作用：开启同步时，监听浏览器前进/后退事件
	useEffect(() => {
		// 未开启同步则不注册监听
		if (!syncBrowserUrl) return;
		// popstate 回调：从地址栏读 pathname 回写内存路径
		const onPop = () => setPath(browserPathname());
		// 注册 popstate 监听
		window.addEventListener('popstate', onPop);
		// 卸载时移除监听，防止内存泄漏
		return () => window.removeEventListener('popstate', onPop);
		// 依赖 syncBrowserUrl：开关变化时重新注册/取消监听
	}, [syncBrowserUrl]);

	// 通过 Context 向下暴露 path 与 navigate
	return (
		<NavigationContext.Provider value={{ path, navigate }}>
			{children}
		</NavigationContext.Provider>
	);
}
```

### 4.3 App.tsx — resolveInitialPath（改动后，纯新增函数）

**来源** · `src/App.tsx`（纯新增，约 L15–L20 与 L38–L46）

```typescript
// 文档路径白名单：只接受这四条路径，其余一律回退默认值
const DOC_PATHS = new Set([
	'/home',            // 首页
	'/update-info',     // 更新日志
	'/project-guide',   // 项目指引
	'/plugin-dev-guide',// 插件开发指引
]);

// 根据是否独立运行，决定初始路径来源（嵌入跟 routePath，独立跟地址栏）
function resolveInitialPath(props: AppProps, standalone: boolean): string {
	// 嵌入 Host 的分支
	if (!standalone) {
		// 取 Host 通过 plugin 属性下发的 routePath
		const routePath = props.plugin?.routePath;
		// 若 routePath 存在且在白名单内，采用它作为初始路径
		if (routePath && DOC_PATHS.has(routePath)) return routePath;
		// 否则回退到 /update-info：嵌入用户来自「关于 → 更新日志」入口
		return '/update-info';
	}
	// 独立运行分支：从地址栏 pathname 读取（根路径会被归一为 /home）
	const fromUrl = browserPathname();
	// 白名单内的路径直接采用，否则回退到 /home 首页
	return DOC_PATHS.has(fromUrl) ? fromUrl : '/home';
}
```

> 在 `App` 中这样调用：`const standalone = !hasBridge;`（无 Host 桥接即独立）；`const initialPath = resolveInitialPath(props, standalone);`，并把 `syncBrowserUrl={standalone}` 传给 `NavigationProvider`。即「嵌入不同步、独立才同步」。

### 4.4 AppRouter.tsx — 内存路由分发（纯已有）

**来源** · `src/router/AppRouter.tsx`（纯已有，全文）

```typescript
// 引入 Host 桥接类型，用于声明 bridge 参数
import type { HostBridgeProps } from '@/types/host';
// 从内存路由 Context 取当前路径
import { useNavigation } from '@/router/NavigationContext';
// 引入四个页面组件
import HomePage from '@/views/home/HomePage';
import UpdateInfoPage from '@/views/updateInfo';
import ProjectGuidePage from '@/views/projectGuide';
import PluginDevGuidePage from '@/views/pluginDevGuide';

// AppRouter：按内存路径 switch 分发对应页面
export function AppRouter({ bridge }: { bridge?: HostBridgeProps }) {
	// 从 Context 读取当前内存路径
	const { path } = useNavigation();
	// 显式标记 bridge 参数当前未使用，避免 lint 报未使用
	void bridge;

	// 按路径分发页面：未命中任何 case 时回落到首页
	switch (path) {
		// 更新日志页
		case '/update-info':
			return <UpdateInfoPage />;
		// 项目指引页
		case '/project-guide':
			return <ProjectGuidePage />;
		// 插件开发指引页
		case '/plugin-dev-guide':
			return <PluginDevGuidePage />;
		// 首页与默认分支
		case '/home':
		default:
			return <HomePage />;
	}
}
```

## 5. 兼容性与影响

- **嵌入 Host 场景**：`syncBrowserUrl` 默认 `false`，`NavigationProvider` 行为与改动前完全一致，不触碰 `window.history`，不会干扰 Host 的地址栏与路由。初始路径默认 `/update-info`，符合「关于 → 更新日志」入口预期。
- **独立预览场景**：`syncBrowserUrl` 为 `true`，`navigate` 会 `pushState` 写地址栏，`popstate` 监听处理浏览器前进/后退。外链打开 `/update-info`、`/project-guide`、`/plugin-dev-guide` 可直达对应页面，根 `/` 落到首页。
- **路径白名单**：`DOC_PATHS` 限制了可接受的路径集合，Host 下发的 `routePath` 或 URL `pathname` 不在白名单内时回退默认值，避免任意路径注入与未知页面渲染。
- **SSR 安全**：`browserPathname` / `writeBrowserUrl` 均先判断 `typeof window === 'undefined'`，SSR 或非浏览器环境下不会报错。
- **历史记录**：`pushState` 会产生历史记录，浏览器后退可逐页回退；若后续希望「不产生历史记录」可改用 `replaceState`，但会丢失逐页后退能力。
- **未改动面**：`AppRouter` 全程未改动，仅消费 `useNavigation().path`；页面组件、i18n、Host 桥接同步等链路不受影响。
