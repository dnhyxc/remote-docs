# 外链系统浏览器打开

> 延伸阅读：主仓 `docs/tools/外链新标签打开.md`（`markdown-kit` 的 `patchExternalLinksOpenBlank`：渲染层补 `target="_blank"`，与本拦截互补）。

## 1. 背景与目标

`remote-docs` 作为 Module Federation 远程子应用嵌入桌面端 Host（Tauri WebView）时，Markdown 正文中的外链（`<a href="https://...">`）若按默认导航，会在当前 WebView 内跳走——离开文档页、丢失应用上下文。用户期望点击外链后在**系统浏览器**中打开，与 Host 行为一致。

本轮在 `Markdown` 组件挂载时拦截 `.markdown-body a` 的点击，经 `openExternalUrl` 重定向：Tauri 走 `plugin:opener|open_url`，否则 `window.open`。

**与 markdown-kit 的关系**（勿删拦截时误以为 kit 已够用）：

| 层 | 能力 | 局限 |
| -- | ---- | ---- |
| **kit `patchExternalLinksOpenBlank`** | 渲染时给外链补 `target="_blank"` + `rel` | 只改 HTML；Tauri 下 `_blank` 常仍是应用内窗口 |
| **本拦截器** | `preventDefault` + opener / `window.open` | 须在 Markdown 宿主挂载 |

结论：独立站纯浏览器可只靠 kit；**MF 嵌桌面 Host 时本拦截必须保留**。场景表见主仓 `dnhyxc-ai/docs/tools/外链新标签打开.md` §5。

## 3. 实现思路

### 3.1 为什么需要在系统浏览器打开

嵌入桌面 Host（Tauri）时，应用运行在 WebView 内。如果外链在 WebView 内导航：
- 用户离开文档页后无法通过浏览器后退返回（WebView 不会像浏览器那样管理历史栈）
- 外部网站可能不具备移动端适配，在窄窗口中体验差
- 无法使用系统浏览器的书签、扩展、密码管理器等能力
- 安全隔离：外部页面不应访问 Host 的 WebView 上下文

### 3.2 为什么用 Tauri `plugin:opener|open_url` 而非只靠 `target="_blank"` / `window.open`

- markdown-kit 已补 `target="_blank"`：在**真浏览器**里通常新开标签，足够。
- 在 **同一 WebView 嵌 Host** 时，`_blank` / `window.open` 可能被拦或弹出应用内窗口，**不是**系统默认浏览器。
- Tauri `plugin:opener` 的 `open_url` 调 OS 默认浏览器，才是桌面端「外链」正道。

### 3.3 为什么需要 `window.open` 回退

- **独立预览模式**：不在 Tauri 环境中运行（纯浏览器），`__TAURI_INTERNALS__` 不存在
- **Tauri opener 插件未安装**：`invoke` 调用失败时不应阻断用户打开链接
- 回退到 `window.open(url, '_blank', 'noopener,noreferrer')` 在浏览器中可靠打开新标签页

### 3.4 为什么用事件委托（capture 阶段）而非给每个 `<a>` 绑定

Markdown 正文由 `dangerouslySetInnerHTML` 渲染，`<a>` 标签是动态生成的。在容器上用**事件委托**（capture 阶段监听 click）可以：
- 覆盖所有现有和未来动态插入的链接
- 只绑定一个监听器，性能优于逐个绑定
- 在 capture 阶段拦截，先于 `<a>` 默认导航行为执行

### 3.5 为什么不拦截 `#` 开头的锚点链接

页内锚点（如 `#section-1`）用于同文档内滚动跳转，应交给浏览器/宿主处理。拦截它们会破坏 Markdown 标题跳转功能。仅拦截外链。

### 3.6 为什么在 `Markdown` 组件的 `useEffect` 中挂载

- `Markdown` 组件是所有文档页正文渲染的统一入口
- 拦截器只作用于该容器内的链接
- cleanup 在卸载时移除监听，避免泄漏
- 与 `bindMarkdownCodeFenceActions` 同生命周期

## 4. 关键代码对比与注释

### 4.1 `open-external.ts` — `openExternalUrl` 函数（纯新增）

**来源** · `src/utils/open-external.ts`（纯新增）

```typescript
/**
 * 在系统浏览器或新标签页打开链接。
 * 嵌入桌面 Host 时与 Host 同 WebView，优先 Tauri opener；否则 window.open。
 * 与 markdown-kit 的 target=_blank 互补：见主仓 docs/tools/外链新标签打开.md §5。
 */
export async function openExternalUrl(url: string): Promise<void> {
	if (!url) return;
	const internals = (
		window as Window & {
			__TAURI_INTERNALS__?: {
				invoke?: (cmd: string, args?: Record<string, unknown>) => Promise<unknown>;
			};
		}
	).__TAURI_INTERNALS__;
	if (typeof internals?.invoke === 'function') {
		try {
			await internals.invoke('plugin:opener|open_url', { url });
			return;
		} catch {
			// opener 不可用时回退
		}
	}
	window.open(url, '_blank', 'noopener,noreferrer');
}
```

### 4.2 `open-external.ts` — `attachExternalLinkClickInterceptor`（纯新增）

```typescript
/**
 * 拦截 Markdown 正文外链点击：preventDefault 后走 openExternalUrl。
 * - 页内 `#` 不拦截。
 * - MF 嵌桌面时勿删：仅靠 kit 的 target=_blank 进不了系统浏览器。
 */
export function attachExternalLinkClickInterceptor(
	container: HTMLElement,
): () => void {
	const onClickCapture = (e: MouseEvent) => {
		const target = e.target as HTMLElement | null;
		if (!target) return;
		const a = target.closest<HTMLAnchorElement>('.markdown-body a');
		if (!a || !container.contains(a)) return;

		const href = a.getAttribute('href')?.trim() ?? '';
		if (!href || href.startsWith('#')) return;

		e.preventDefault();
		e.stopPropagation();
		void openExternalUrl(href);
	};

	container.addEventListener('click', onClickCapture, true);
	return () => container.removeEventListener('click', onClickCapture, true);
}
```

### 4.3 `Markdown/index.tsx` — 挂载拦截

与围栏工具栏同一 `useEffect`：`attachExternalLinkClickInterceptor(el)`，cleanup 中 `detachExternalLinks()`。

## 5. 兼容性与影响

- 外链拦截仅作用于 `.markdown-body a`；`#` 锚点、代码块工具栏不受影响
- 用户可感知：嵌入桌面时外链进系统浏览器，不再顶掉 WebView SPA
- 回归：嵌入 Host + Tauri opener；独立预览 + `window.open`；`#` 不被拦；卸载无泄漏
